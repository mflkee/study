# План курса «Rust + PostgreSQL для СИКН»

> Версия плана: 1.0 (2026-09-24). Источник истины — OpenSpec-артефакты change `rust-pg-course`
> (`openspec/changes/rust-pg-course/`: proposal.md, design.md, tasks.md, specs/). Этот файл —
> производная копия для навигации по курсу. Статус выполнения ведётся в `PROGRESS.md`.

## Цель и портрет ученика

Уверенно строить на Rust приложения поверх PostgreSQL для промышленного сбора данных (СИКН/Modbus/телеметрия): от SQL и проектирования схем до асинхронного доступа, миграций, тестов, производительности и эксплуатации. Ученик — взрослый инженер, Rust на уровне базы (владение/заимствования/трейты/ошибки), PostgreSQL знает чуть-чуть. Формат: самостоятельное обучение, основной упор на практику (30% чтение, 70% выполнение).

## Модули, уроки, упражнения, лабы

### 00-orientation — карта курса и окружение *(4 ч)*
Уроки:
- 01-okruzhenie — установка и проверка Rust toolchain, Docker, psql, sqlx-cli; как диагностировать окружение.
- 02-stend — подъём стенда одной командой, первый запрос к PostgreSQL.
- 03-kak-uchitsya — структура курса, карта компетенций, самооценка, как работать с PROGRESS.md.

Упражнения: «Диагностика окружения» (bash-автопроверка). Лабы: «Стенд поднят и отвечает» (смоук + критерии успеха).

### 01-sql-foundations — язык SQL *(10 ч)*
Уроки:
- 01-select — SELECT, проекции, WHERE, ORDER BY, LIMIT; NULL-семантика.
- 02-dml — INSERT/UPDATE/DELETE, ограничения, каскады, DEFAULT.
- 03-tipy — типы данных: NUMERIC vs float, timestamptz, JSONB, enum, array — выбор под метрологию.
- 04-joins — JOIN (INNER/LEFT), GROUP BY, HAVING.
- 05-prodvinutye — подзапросы, CTE, оконные функции (сменные/суточные агрегаты).

Упражнения: «Каталог оборудования: первые запросы», «Точность: NUMERIC vs float», «Сменный отчёт по линиям» (оконные функции). Лабы: «Сломай и почини: потеря точности и неверный тип времени».

### 02-schema-design — проектирование схемы *(8 ч)*
Уроки:
- 01-normalizaciya — нормальные формы, первичные/внешние ключи, связи, проектирование справочников.
- 02-indeksy — B-tree, BRIN, GIN, partial index; когда какой индекс; EXPLAIN для выбора.
- 03-proektirovanie — схема под временные ряды телеметрии и справочники оборудования.

Упражнения: «Каталог оборудования: схема, ключи, связи» (SQL-автопроверка структуры), «Выбери индекс под запросы». Лабы: «Индекс под запросы телеметрии: BRIN vs B-tree» (замеры EXPLAIN).

### 03-transactions-mvcc — транзакции и MVCC *(8 ч)*
Уроки:
- 01-acid — ACID, BEGIN/COMMIT/ROLLBACK, savepoints.
- 02-izolyaciya — уровни изоляции, MVCC, аномалии (dirty read, lost update, skew).
- 03-blokirovki — блокировки строк/таблиц, deadlock, VACUUM и bloat, advisory locks.
- 04-skip-locked — очереди на `SELECT ... FOR UPDATE SKIP LOCKED`.

Упражнения: «Очередь задач: SKIP LOCKED» (две сессии, без двойной выдачи). Лабы: «Долгая транзакция блокирует VACUUM» и «Deadlock при обновлениях» — воспроизвести и починить.

### 04-rust-sql-first-steps — первый Rust + PostgreSQL *(12 ч, cargo)*
Уроки:
- 01-vybory — крейты доступа: tokio-postgres vs sqlx vs diesel/sea-orm; почему выбран sqlx (см. design D2).
- 02-pervyj-kod — подключение, простые запросы, маппинг типов (int, text, timestamptz).
- 03-decimal-chrono — rust_decimal, chrono, serde; сериализация данных телеметрии.

Упражнения: «Каталог оборудования: CLI на Rust + sqlx» (CRUD, todo!()-заготовки), «Масса нетто на rust_decimal» (методика расчёта по брифу). Лабы: «Считать из PG, посчитать, записать обратно» (сквозной сценарий).

### 05-async-rust-tokio — асинхронность *(8 ч, cargo)*
Уроки:
- 01-async-await — async/await, Future, блокирующие vs async-операции.
- 02-tasks-kanaly — tokio::spawn, mpsc-каналы, select!.
- 03-otmena — отмена задач, backpressure, graceful shutdown.

Упражнения: «Пайплайн опроса датчиков с backpressure и отменой по Ctrl-C». Лабы: «Грациозный останов воркера» (сигналы, доработка очереди).

### 06-sqlx-in-depth — sqlx: пул, транзакции, миграции *(10 ч, cargo)*
Уроки:
- 01-pul — PgPool: конфигурация, размер, таймауты, retry.
- 02-tranzakcii — транзакции из Rust, savepoints, границы транзакций.
- 03-makrosy — query!/query_as! и offline-кэш; когда нужны, когда runtime-запросы (design D2).
- 04-migracii — sqlx migrate, thiserror/anyhow, обработка ошибок БД.

Упражнения: «Эволюция схемы: новый тип датчика» (миграция + обратная совместимость Rust-кода). Лабы: «Забытый индекс» (N+1 и план) и «Долгая транзакция из Rust».

### 07-performance — производительность *(12 ч, cargo)*
Уроки:
- 01-explain — EXPLAIN (ANALYZE, BUFFERS): чтение планов, узкие места.
- 02-statistika — pg_stat_statements, поиск медленных запросов, замеры.
- 03-batch — batch insert, UNNEST, COPY (текстовый/бинарный), prepared statements, pipeline.
- 04-tijuning — тюнинг пула соединений под нагрузку.

Упражнения: «Приём телеметрии Modbus: построчно vs batch vs COPY» (эмулятор токио-modbus, замеры порогов), «Нагрузочный генератор на Rust vs pgbench». Лабы: «Нагрузочный стенд: найти узкое место» (пул, индекс, batch).

### 08-timeseries-partitioning — временные ряды *(8 ч)*
Уроки:
- 01-partitioning — партиционирование по времени, retention, BRIN.
- 02-downsampling — агрегации по интервалам, материализованные представления, отчёты за смену/сутки.
- 03-timescale — TimescaleDB: hypertable, continuous aggregates; честное сравнение с нативным подходом.

Упражнения: «Отчёты за смену по каждой линии» (оконные функции + партиции), «Разверни TimescaleDB и сравни запросы». Лабы: «Партиция без индекса» и «Ретеншн удалил нужное» — воспроизвести и починить.

### 09-plpgsql-triggers-notify — триггеры и события *(10 ч)*
Уроки:
- 01-functions — PL/pgSQL: функции, переменные, циклы, обработка ошибок.
- 02-triggers — триггеры BEFORE/AFTER, аудит изменений.
- 03-notify — LISTEN/NOTIFY: уведомления из триггера, приём в Rust.
- 04-security — RLS, роли и права, минимальные привилегии.

Упражнения: «Журнал аудита с защитой от подмены» (запрет UPDATE/DELETE, цепочка хэшей, проверка из Rust), «Тревоги в реальном времени» (триггер → NOTIFY → Rust-слушатель → таблица событий + квитирование). Лабы: «Обход триггера / отключённый NOTIFY» — как сломать и как чинить.

### 10-app-patterns — паттерны приложений *(10 ч, cargo)*
Уроки:
- 01-repository — repository-паттерн в Rust, границы транзакций.
- 02-outbox — outbox pattern, идемпотентность, ON CONFLICT.
- 03-worker — очередь задач на Postgres: воркеры tokio, ретраи, dead-letter.
- 04-migrations — миграции без даунтайма, обратная совместимость.

Упражнения: «Очередь задач: воркеры и ретраи» (SKIP LOCKED из модуля 03), «Буферизация при потере связи» (шлюз накапливает локально, доставка без дублей). Лабы: «Отказ БД во время записи: без потерь и без дублей».

### 11-web-api-axum — REST API *(8 ч, cargo)*
Уроки:
- 01-axum — базовый REST на axum + sqlx: маршруты, состояния, слои.
- 02-handlers — DTO, валидация, пагинация, ошибки JSON.
- 03-config-tracing — конфигурация env, tracing, метрики.

Упражнения: «Добавь эндпоинт трендов» (заготовка с todo!(), интеграционный тест-чек), «Пагинация значений датчиков». Лабы: «REST API для дашборда: токены и кэш» (отдача под Grafana).

### 12-testing — тестирование *(8 ч, cargo)*
Уроки:
- 01-testcontainers — интеграционные тесты с реальным PostgreSQL в контейнере.
- 02-sqlx-test — sqlx::test (миграции + транзакции на тест), фикстуры.
- 03-property — property-based тесты (proptest) для расчётов.

Упражнения: «Property-тесты массы нетто: накопление ошибки f64 vs decimal», «Тест SQL-функции с фикстурами». Лабы: «Тест миграций: примени на свежую БД и проверь схему».

### 13-ops-reliability — эксплуатация *(10 ч)*
Уроки:
- 01-backup — pg_dump, pg_basebackup, WAL-архив, восстановление на момент времени (PITR), RPO/RTO.
- 02-replication — streaming и logical репликация, промоушен, восстановление после отказа.
- 03-monitoring — pg_stat_*, postgres_exporter, Prometheus, Grafana, alerting.
- 04-ci — Docker-обёртки и базовый CI (GitHub Actions / GitLab CI).

Упражнения: «Стратегия бэкапа скриптами + проверка восстановления», «Подними мониторинг и найди аномалию по метрикам». Лабы: «Инцидент: забился диск WAL», «Долгая транзакция против VACUUM», «Потеря пула соединений», «Восстановление PITR» — сценарии «сломай и почини».

### 14-capstone-historian — итоговый проект *(20 ч, cargo)*
Мини-система сбора и хранения данных СИКН: эмулятор Modbus TCP → Rust-шлюз (опрос, буфер, батчевая запись) → PostgreSQL (партиции, аудит, триггеры) → REST API axum → отчёты и дашборд Grafana.

Уроки:
- 01-arhitektura — архитектура системы, требования, ADR.
- 02-shlyuz — эмулятор устройств + шлюз: опрос, буфер при потере связи, батч.
- 03-hranilishche — схема: партиции, аудит-цепочка, триггеры.
- 04-api-dashboard — REST + Grafana; сквозной поток от Modbus до дашборда.

Упражнения: собрать компоненты по заготовкам. Лабы: полный проект с тестами на testcontainers, docker compose капстоуна, документация и ADR.

### 15-interview-prep — подготовка к собеседованию *(6 ч)*
Уроки:
- 01-sql-questions — вопросы по SQL и проектированию схем с эталонными ответами.
- 02-postgres-questions — вопросы по устройству PostgreSQL (MVCC, WAL, VACUUM, репликация).
- 03-rust-db-questions — вопросы по Rust + БД (пул, транзакции, ошибки, async).
- 04-incidents — разбор типовых инцидентов и задачи на проектирование.

Упражнения: «Собеседование вслух» (вопрос → ответ в `<details>` → самопроверка). Лабы: «Разбери аварию по журналу и метрикам» (кейс-стади).

## Отклонения от предложенной структуры и обоснование

1. **План живёт в OpenSpec** (proposal/design/tasks), `course/PLAN.md` — производный документ для навигации. Причина: единый источник истины, статусы и чеклист сборки в `tasks.md`, `PROGRESS.md` — ученический статус. (design D1)
2. **Порты стенда 15432/15433** вместо широко используемых 5433/5434 — на машине автора они заняты; принцип «нестандартные порты» сохранён. (design D5)
3. **PostgreSQL 18.6 — текущая major-версия**, не LTS-выбор: курс пишется на актуальной версии; отличия от 14–17 отмечаются в тексте, но не тестируются.
4. **SQL-модули (01, 02, 03, 08, 09, 13, 15) — без cargo-проекта**: бриф требует cargo только в Rust-модулях.
5. **Modbus TCP как основной сценарий**, RTU (ESP32) — в теории и как задание «со звёздочкой» в капстоуне: TCP дружелюбен к Docker-стенду. (design D6)
6. **TimescaleDB — только OSS-образ** (`latest-pg18-oss`); Apache-версия требуется для проектов с лицензионными требованиями — в курсе достаточно OSS.
