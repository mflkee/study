# Модуль 14: Капстоун Historian — уроки

Четыре урока-вехи итогового проекта. Каждый заканчивается работающим компонентом;
финальная проверка — `cargo test --test capstone_integration` и сквозной поток (README).

## Урок 01: Архитектура и ADR

**Время:** 3 ч · **Что сделаешь:** архитектуру потоков и ADR-01..04 (docs/ADR.md).

- Поток: эмулятор → шлюз (опрос/буфер/батч) → партиционированное хранилище с аудитом
  → REST API → Grafana.
- ADR фиксируют решения: почему sqlx (D2), почему партиции месяца + UNIQUE(…, ts),
  почему буфер-файл при отказе БД.
- Задание: нарисуй свой вариант потока и сравни с ADR-01 — где бы ты поступил иначе?

## Урок 02: Эмулятор и шлюз

**Время:** 5 ч · **Что сделаешь:** бинари `emulator` и `gateway`.

- Эмулятор: tokio-modbus TCP-сервер, «живые» регистры (модуль 07 — та же механика).
- Шлюз: опрос 500 мс (модуль 05 — таймеры/select!), батч `UNNEST` + `ON CONFLICT`
  (модуль 07), буфер-файл при недоступности PG и flush (модуль 10), Ctrl-C — грациозный
  флаш (модуль 05).
- Задание: останови `docker compose stop postgres_cap` посреди работы шлюза — данные
  копятся в буфере; подними БД — flush без дублей (повтори опыт лаборатории 10).

## Урок 03: Хранилище — партиции и аудит

**Время:** 6 ч · **Что сделаешь:** схему `migrations/0001_capstone.sql`.

- Партиции месяца (модуль 08): `PARTITION BY RANGE (ts)` + авто-мост `ensure_partitions`
  (безопасный DDL с AssertSqlSafe, модуль 11).
- Идемпотентность приёма: `UNIQUE (device_id, seq, ts)` (граница ADR-02 — ключ партиции
  обязан войти в UNIQUE).
- Аудит каталога с цепочкой sha256 и защитой от подмены (модуль 09); проверка из Rust
  (`verify_chain`) — в тестах.
- Задание: добавь в аудит новый тип (например, архивную таблицу) одним триггером —
  и убедись, что `verify_chain` по-прежнему зелёный (обратная совместимость).

## Урок 04: REST API и дашборд

**Время:** 6 ч · **Что сделаешь:** бинарь `api` + provisioning Grafana.

- API: `/devices`, `/devices/{tag}/current`, `/devices/{tag}/trends` (модуль 11;
  тренд — эпоховые бакеты, без гонок date_bin через sqlx: дели на `bucket_seconds`).
- Grafana: datasource PostgreSQL + дашборд «Historian» (панели: последние показания,
  частота выше порога, временной ряд) — provisioning файлами.
- Проверка: сначала эмулятор+шлюз (наполняют БД), затем дашборд показывает «живые» 
  значения; `/trends` совпадает с панелью временного ряда.
- Задание: добавь эндпоинт `POST /devices` с аудитом — и отметь запись в Grafana-таблице
  аудита (провижининг-панель по `audit_log`).
