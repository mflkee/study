# Урок 03: Карта компетенций и как учиться по курсу

**Закрывает цель:** осознанный маршрут по курсу и самооценка стартового уровня
**Время:** 30 мин

## Зачем это нужно

Самостоятельное обучение без преподавателя валится в два места: «прочитал, но не сделал» и «сделал, но не понял». Карта компетенций даёт точку отсчёта (что уже умеешь), а правила прохождения — процедуру, которая заставляет практиковаться, а не скроллить теорию.

## Ключевые идеи (сжато)

- 16 модулей = 16 компетенций, от SQL к эксплуатации и проекту.
- Формула прохождения модуля: **theory → уроки → примеры (запустить) → упражнения (автопроверка) → лаба (сломай и почини)**.
- Соотношение 30% чтения / 70% выполнения — практика первична.
- `PROGRESS.md` в корне курса — твой чеклист; `PLAN.md` — карта; `resources/README.md` — официальная документация.

## Разбор на примере

Карта компетенций курса. Оцени себя 1–5 (1 — не знаком, 5 — уверенно пользуюсь) и запиши в личный файл, например `course/00-orientation/self-assessment.md`:

|---|---|---|---|
| 1 | SQL: выборки, DML, типы, JOIN, оконные функции | 01 | |
| 2 | Проектирование схем, индексы | 02 | |
| 3 | Транзакции, MVCC, блокировки | 03 | |
| 4 | Rust: язык (владение, трейты, ошибки) | 04 (повтор в контексте БД) | |
| 5 | Rust + БД: подключение, маппинг типов | 04 | |
| 6 | Асинхронность: async/await, tokio | 05 | |
| 7 | sqlx: пул, транзакции, миграции | 06 | |
| 8 | Производительность SQL (EXPLAIN, batch, COPY) | 07 | |
| 9 | Временные ряды: партиционирование, downsampling | 08 | |
| 10 | PL/pgSQL, триггеры, LISTEN/NOTIFY, RLS | 09 | |
| 11 | Паттерны приложений: outbox, очередь задач | 10 | |

Как использовать: если по пункту 1–2 — закладывай на модуль полное время и делай все упражнения; если 4–5 — можно проходить быстрее, но лабы «сломай и почини» всё равно обязательны (они добавляют опыт, которого нет у «уверенного пользователя»).

## Как это устроено под капотом

- **Цикл обучения** в каждом модуле устроен так, что знание проверяется действием: упражнение не считается пройденным, пока автопроверка не вернёт код 0 (у заготовки — ненулевой, у решённой — нулевой).
- **Лабы «сломай и почини»** моделируют инциденты, которые реально происходят с БД (забитый диск WAL, долгая транзакция, потеря пула). Цель — отрепетировать диагностику до того, как инцидент случится на работе.
- **PROGRESS.md** — единственное место, где фиксируется «сделано». Это защита от иллюзии прогресса «я про это читал».

## Типичные ошибки и грабли

1. **Чтение вместо выполнения.** Если после урока не запущен ни один пример — модуль не пройден.
2. **Подсматривание решений до попытки.** Решения лежат в `solutions/`, и это не приглашение: сначала автопроверка, потом (если застрял) решение — и переписать самому.
3. **Пропуск лаб.** Лабы — то, что отличает «знаю теорию» от «могу чинить». Не пропускай.
4. **Завышенная самооценка.** Если балл 4–5, а примеры не запускались — пересмотри: самооценка должна опираться на выполненную практику.

## Мини-задание

Заполни таблицу самооценки (файл `self-assessment.md`). Отметь три компетенции с самым низким баллом — на них обратишь внимание в первую очередь.

## Как это спросят на собеседовании

1. «Как ты поддерживаешь актуальность навыков по СУБД?» (структурный подход: теория → практика → инциденты)
2. «Расскажи про последний инцидент с базой, который ты разбирал, и что вынес» — отвечай сценарием из лаб 13.
3. «Как ты тестируешь свой код, работающий с БД?» — отвечай после модуля 12 (testcontainers, sqlx::test).
