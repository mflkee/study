# Теория модуля 00: как устроен курс и окружение

## Карта курса

Курс — 16 модулей, идут строго по порядку: каждый следующий опирается на предыдущие.

```
00 окружение ─► 01 SQL ─► 02 схемы ─► 03 транзакции ─► 04 Rust+БД
                                                       │
                                               05 асинхронность
                                                       │
                                               06 sqlx вглубь ─► 07 производительность
                                                       │                │
                                               10 паттерны ◄── 08 временные ряды
                                                       │                │
                                               11 web-API         09 триггеры
                                                       │                │
                                               12 тесты ──► 13 эксплуатация
                                                       │
                                               14 капстоун (проект) ─► 15 собеседование
```

Каждый модуль имеет одинаковую структуру (см. `course/PLAN.md`):

- `README.md` — цели, план, чеклист готовности;
- `theory.md` — сжатый конспект-справочник;
- `lessons/` — пошаговые уроки;
- `examples/` — рабочие примеры (SQL/Rust), которые запускаются;
- `exercises/` — задания с заготовками и автопроверкой, решения в `solutions/`;
- `labs/` — длинные практики и «сломай и почини».

Правила самостоятельного обучения:

1. **Примеры запускать, а не читать.** Каждый пример в модуле выполняется на стенде.
2. **Упражнения писать самому.** Заглядывать в `solutions/` только после того, как автопроверка приняла твой вариант (или когда застрял — и тогда честно переделать).
3. **Автопроверки не обманывать.** Скрипт проверки вернёт ненулевой код, если задание не выполнено.
4. **Лабы «сломай и почини» — обязательны.** Это способ узнать, как система умирает, до того, как она умрёт на проде.
5. **Отмечать прогресс** в `course/PROGRESS.md` после каждого модуля.

## Окружение

Минимальный набор для курса:

| Инструмент | Версия в курсе | Для чего |
|---|---|---|
| Rust toolchain (`rustc` + `cargo`) | 1.98 | компиляция кода на Rust |
| Docker (+ compose) | 29.x | стенд PostgreSQL и сервисы |
| `sqlx-cli` | 0.9 | миграции БД, диагностика (`sqlx migrate`, `sqlx db`) |
| `psql` (клиент PostgreSQL) | 18.x | работает внутри контейнера стенда (`docker compose exec postgres psql`) |

- **Rust** устанавливается и обновляется через `rustup` (или ставится системным пакетом дистрибутива — на Arch: `pacman -S rust`). Проверка: `rustc --version`.
- **Docker** состоит из daemon (фоновый процесс) и CLI (`docker`). Для compose нужен плагин `docker compose` (двухсловная команда). Проверка: `docker --version`, `docker compose version`.
- **sqlx-cli** — утилита экосистемы sqlx для миграций: `cargo install sqlx-cli --no-default-features --features rustls,postgres --locked`.
- **psql** отдельно устанавливать не обязательно: клиент лежит в образе стенда.

## Стенд

Единый стенд — `infra/docker-compose.yml`. Профили:

| Профиль | Что поднимает | Порт (host) | Когда нужен |
|---|---|---|---|
| (по умолчанию) | PostgreSQL 18.6 | 15432 | всегда |
| `tools` | pgAdmin 4 (веб-UI) | 5050 | по желанию |
| `obs` | Prometheus + exporter + Grafana | 9090 / 9187 / 3000 | модуль 13 |
| `timescale` | TimescaleDB (PG18) | 15433 | модуль 08 |

Доступы по умолчанию: user `course`, password `course`, база `course`. Порт хоста 15432 (не стандартный 5432) — чтобы не конфликтовать с локальными сервисами.

Команды стенда (из каталога `infra/`):

```bash
docker compose up -d                 # поднять PostgreSQL
docker compose ps                    # статус
docker compose exec -T postgres psql -U course -d course   # psql внутри контейнера
./apply-db.sh path/to/file.sql       # применить SQL-миграцию
docker compose down                  # остановить (данные сохраняются в volume)
```

Миграции и тестовые данные лежат в репозитории (`infra/db/init/` выполняется при первом создании тома; дальнейшие изменения применяются через `apply-db.sh` или `sqlx migrate`).

## Самооценка

Перед стартом оцени себя 1–5 по каждой компетенции курса (урок 03): SQL, проектирование схем, транзакции и MVCC, Rust (язык), Rust + БД, асинхронность (tokio), производительность SQL, временные ряды, триггеры и события, паттерны приложений, веб-API, тестирование, эксплуатация. Стартовый балл не важен — важна честность: она укажет, на какие модули заложить больше времени.
