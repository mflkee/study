# Упражнения модуля 06

## Заготовка и решение

- Заготовка: `exercises/src/ex01_evolution.rs` — «Эволюция схемы — новый тип датчика» (кейс 10).
- Дополнительно ты пишешь миграцию `migrations/0003_add_flow_calc.sql` (в репозитории её НЕТ — это часть задания; образец — миграция 0002).
- Решения: `solutions/ex01_evolution.rs` и `solutions/0003_add_flow_calc.sql` (открыть после попытки).
- Заготовка подключена через `src/lib.rs` (`#[path]`), тесты в `src/lib.rs`.

## Как проверять

```bash
cargo test ex01_        # тесты упражнения
cargo test              # всё
```

Поведение «до/после»:

- **До решения**: тесты парсинга падают (`not yet implemented`), интеграционный тест падает с подсказкой «напиши миграцию migrations/0003_add_flow_calc.sql».
- **После решения** (Rust-код + миграция 0003): 3 «исторических» теста (retry, url) + 2 теста упражнения — зелёные. Интеграционный тест сам применяет миграции к `course_m06` и проверяет constraint + вставку нового типа.

Внимание: интеграционный тест требует **поднятого стенда** (создаёт/использует `course_m06`). Чистые тесты (retry, url, парсинг) — без БД.

## Контроль качества

```bash
cargo check --all-targets   # собирается БЕЗ DATABASE_URL: макросы берут .sqlx/ (offline)
cargo clippy --all-targets  # 0 предупреждений в заготовках и решениях
cargo fmt --check
```

Offline-кэш `.sqlx/` закоммичен: после изменения SQL в макросах его надо перегенерировать (`cargo sqlx prepare`), иначе сборка на другой машине упадёт (урок 03).
