# Урок 01: async/await, Future и блокирующие операции

**Модуль / кейс:** 05-async-rust-tokio / кейс 2 (телеметрия — задел)
**Время:** 2 ч

## Зачем это нужно

БД-слой и сеть — асинхронные по своей природе: запрос в PostgreSQL идёт по TCP и ждёт ответа. Если блокировать поток на каждом запросе — под нагрузкой потоки кончаются, а с ними и масштабирование. В этом уроке — базовые механики async/await и первая грабли: блокирующий вызов внутри async-кода.

## Ключевые идеи (сжато)

- `async fn` — возвращает `Future`; тело выполняется при `.await`.
- `.await` — «уступи поток рантайму»: пока будущее не готово, поток занят другими задачами.
- **Кооперативность**: конкурентность работает и на одном потоке (одна задача уступает через `.await`).
- `tokio::join!` — две задачи одновременно; `tokio::spawn` — отдельная задача.
- `std::thread::sleep` / синхронный IO в async — **стопорят поток рантайма**: все задачи на этом потоке замирают. Для тяжёлой работы — `spawn_blocking`.

## Разбор на примере

```bash
cargo run --example 01-async-basics
```

Код — `examples/01-async-basics.rs`. Рантайм — `current_thread` (один поток), чтобы было видно: конкурентность не требует потоков, а одна блокировка останавливает всё.

**1. Последовательно — время складывается (~400 мс):**

```rust
let a = work("a", 200ms).await;   // ждём
let b = work("b", 200ms).await;   // потом ждём вторую
```

**2. Конкурентно — время не складывается (~200 мс):**

```rust
let (a, b) = tokio::join!(work("a", 200ms), work("b", 200ms));
```

Фактический вывод:

```
последовательно: a готово за 200ms; b готово за 200ms; всего 402.870775ms
join!:            a готово за 200ms; b готово за 200ms; всего 200.47284ms
```

**3. Блокирующий вызов — беда.** Тикер каждые 100 мс печатает «тик». Затем `std::thread::sleep(350 мс)` — единственный поток рантайма заблокирован, и тики «пропадают»:

```
после блокирующего сна: 350.156653ms, тики пропали
  тик 1 на 451 мс        <- был бы на 100 мс, пришёл на 451
  тик 2 на 553 мс
  ...
```

**4. Правильно — `spawn_blocking`.** Тяжёлая работа уходит в отдельный поток, тики продолжают идти (101, 202, 304 …):

```
  тик 1 на 101 мс
  тик 2 на 202 мс
  тик 3 на 304 мс
spawn_blocking: тяжёлая работа сделана (350.668824ms) — тики идут
```

## Как это устроено под капотом

- `Future::poll` — рантайм опрашивает задачи; когда задача возвращает `Pending`, рантайм берёт следующую. «Готов» — значит, источник готовности (таймер, сеть, канал) разбудил задачу.
- Один поток = один `poll` в момент времени; несколько задач чередуются на нём. Потоки нужны для параллелизма CPU/блокировок, а не для конкурентности IO.
- `spawn_blocking` — отдельный пул потоков (по умолчанию ~num_cpus) для кода, который нельзя написать через `.await`.

## Типичные ошибки и грабли

1. **Синхронный `sleep`/IO внутри async** — «зависает» вся очередь задач на потоке. Лечится: асинхронной версией или `spawn_blocking`. В СИКН это скрытая мина: раз в месяц ночью что-то дёргает диск — и весь консьюмер молчит.
2. **«Почему у меня всё по очереди?»** — забыл `.await`/`join!`/`spawn`: `join!(a, b)` — конкурентно, а `a.await; b.await` — последовательно.
3. **Долгий CPU-цикл без `.await`** — держит поток: другие задачи голодают до конца цикла.
4. **Ловить панику JoinHandle** — `spawn` возвращает `Result`; игнор `?`/`.unwrap()` на `JoinHandle` прячет панику задачи.

## Мини-задание

Напиши `async fn` с двумя задержками и запусти сначала последовательно, потом через `join!`; замерь `Instant` в обоих случаях и убедись, что второй почти вдвое быстрее.

<details>
<summary>Ответ</summary>

```rust
async fn work(name: &str, ms: u64) -> String {
    tokio::time::sleep(Duration::from_millis(ms)).await;
    format!("{name}")
}
let t = std::time::Instant::now();
let _ = work("a", 200).await;
let _ = work("b", 200).await;
println!("посл.: {:?}", t.elapsed());          // ≈ 400 мс
let t = std::time::Instant::now();
let _ = tokio::join!(work("a", 200), work("b", 200));
println!("join!: {:?}", t.elapsed());          // ≈ 200 мс
```

## Как это спросят на собеседовании

1. «Что происходит при `.await`?» — задача отдаёт поток рантайму, при готовности получает управление.
2. «В чём разница конкурентности и параллелизма?» — конкурентность = чередование (один поток), параллелизм = несколько потоков.
3. «Почему нельзя `std::thread::sleep` в async?» — блокирует поток рантайма; для блокирующей работы есть `spawn_blocking`.
4. «Что вернёт `JoinHandle::await` и что будет при панике в задаче?» — `Result<_, JoinError>`.
