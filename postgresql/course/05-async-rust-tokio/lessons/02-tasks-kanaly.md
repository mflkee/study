# Урок 02: Задачи, каналы mpsc и select!

**Модуль / кейс:** 05-async-rust-tokio / кейсы 2 (телеметрия), 7 (очередь задач)
**Время:** 2.5 ч

## Зачем это нужно

Каналы — «почта» между задачами: производитель шлёт измерения, потребитель пишет. `select!` позволяет ждать несколько событий сразу (данные ИЛИ таймер ИЛИ сигнал). Это каркас очередей задач (модули 07/10), а bounded-канал даёт **backpressure** — защиту от безграничного роста очереди.

## Ключевые идеи (сжато)

- `tokio::spawn` — задача; `JoinHandle::await` — дождаться завершения.
- **mpsc** = multi-producer → single-consumer. `channel(N)` — bounded (буфер N); `unbounded_channel()` — без границ (опасно!).
- `send().await` на полном канале **ждёт** — это backpressure (урок про каналы + пример 04).
- `recv()` → `Some` (есть) / `None` (канал закрыт: все senders упали) — признак «данные кончились».
- `select!` — первое готовое событие из веток.

## Разбор на примере

```bash
cargo run --example 02-tasks-kanaly
cargo run --example 04-backpressure
```

**1. Передача сообщений** (`examples/02-tasks-kanaly.rs`):

```rust
let (tx, mut rx) = mpsc::channel(32);
let producer = tokio::spawn(async move {
    for i in 0..10 { tx.send(format!("сообщение {i}")).await.unwrap(); }
    // tx упадёт — канал закроется
});
let mut got = Vec::new();
while let Some(msg) = rx.recv().await { got.push(msg); }
producer.await?;
```

Фактический вывод:

```
получено 10 сообщений: сообщение 0, сообщение 1, ..., сообщение 9
```

**2. `select!`** — сообщение приходит через 100 мс, тик раз в 300 мс; кто готов первым — тот и выиграл:

```
первым пришло СООБЩЕНИЕ: данные с датчика
```

**3. Backpressure** (`examples/04-backpressure.rs`): потребитель «пишет в БД» по 50 мс, канал на 4 элемента, производитель шлёт почти мгновенно. Если бы канал был безграничным, очередь росла бы до бесконечности (память!). Bounded-канал заставляет производителя ждать:

```
готово: обработано 20/20; производитель ждал место в канале суммарно 770.183295ms
```

Потребитель медленнее — производитель подождал 770 мс суммарно, но **ничего не потерял** (20/20).

## Как это устроено под капотом

- mpsc состоит из «входа» (Sender) и «выхода» (Receiver); при падении последнего Sender канал помечается закрытым, и `recv` отдаёт буферизованное, затем `None`.
- `send().await` на полном bounded-канале — задача встаёт в очередь ожидания места; свободное место появляется после `recv` потребителя.
- `select!` опрашивает все ветки: таймер готов по расписанию, канал — по приходу. Если веток несколько готовых — выбор случайный; для детерминизма — `biased;` (урок 03).

## Типичные ошибки и грабли

1. **`unbounded_channel` под нагрузкой** — очередь и память растут до OOM. Для телеметрии почти всегда нужен bounded + backpressure.
2. **Полный канал без плана** — `send().await` просто ждёт: если потребитель умер, производитель встанет навсегда (или до отмены).
3. **Держать Sender в живых** — канал «не закрывается», `recv()` вечно ждёт: типичная причина «зависшего» потребителя. Падает — канал закрывается.
4. **Путать канал с очередью задач на БД** — mpsc — передача между задачами процесса; персистентная очередь на Postgres (SKIP LOCKED) будет в модуле 10.
5. **`select!` «не видит» редкую ветку** — если другая ветка готова всегда; решение — `biased;` или приоритет (урок 03).

## Мини-задание

Сделай producer/consumer: producer шлёт 100 чисел, consumer складывает их в сумму, канал bounded(8). Дождись завершения и выведи сумму.

<details>
<summary>Ответ</summary>

```rust
let (tx, mut rx) = mpsc::channel(8);
let producer = tokio::spawn(async move {
    for i in 0..100 { let _ = tx.send(i).await; }
});
let mut sum = 0u64;
while let Some(v) = rx.recv().await { sum += v; }
producer.await?;
println!("сумма = {sum}"); // 4950
```
</details>

## Как это спросят на собеседовании

1. «Чем bounded-канал отличается от unbounded и когда что?» — bounded даёт backpressure и ограничивает память; unbounded — для редких коротких пачек.
2. «Что произойдёт с `recv()` после закрытия канала?» — отдаст буферизованное, потом `None`.
3. «Зачем `select!`?» — ждать несколько независимых событий (данные/таймер/сигнал) без гонок и блокировок.
