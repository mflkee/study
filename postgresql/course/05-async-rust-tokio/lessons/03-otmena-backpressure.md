# Урок 03: Отмена, select! и грациозный останов

**Модуль / кейс:** 05-async-rust-tokio / кейс 7 (очередь задач — задел)
**Время:** 2 ч

## Зачем это нужно

Приложение должно корректно завершаться: по Ctrl-C (`SIGINT`), по стоп-команде, при рестарте. Дёрнуть процесс — потерять взятые из очереди задачи («а мы же их обработали?»). Грациозный останов: остановить приём нового → **дренаж** (дообработать взятое) → выйти с чистым итогом. Это же понадобится для воркеров и REST-сервера (модули 10, 11).

## Ключевые идеи (сжато)

- `tokio::signal::ctrl_c()` — future, готовая по SIGINT; `tokio::signal::unix::signal(SignalKind::…())` — другие сигналы (SIGTERM и т.п.).
- **Держи future сигнала ОДНИМ на программу**: `tokio::pin!` + `&mut` в select!. Пересоздание `ctrl_c()` в цикле теряет сигнал в окне между drop и перерегистрацией (проверено на стенде — грабли!).
- Остановка производителя — `watch<bool>`: потребитель на сигнале делает `send(true)`, производитель в select! ловит `changed()`.
- Дренаж: после остановки — `while let Some(x) = rx.recv().await` — дообработать остаток, потом `producer.await`.
- `biased;` — детерминированный порядок проверки веток: редкая ветка не «голодает».

## Разбор на примере

```bash
cargo run --example 03-otmena-graceful -- --limit 8   # автономно
timeout -s INT 2 cargo run --example 03-otmena-graceful  # Ctrl-C через 2 с
```

Код — `examples/03-otmena-graceful.rs` (и `05-pipeline.rs` — тот же принцип + статистика).

**1. Стоп-сигнал производителю через watch:**

```rust
let (stop_tx, mut stop_rx) = watch::channel(false);
let producer = tokio::spawn(async move {
    loop {
        tokio::select! {
            biased;
            _ = stop_rx.changed() => break,              // стоп — первый
            _ = tokio::time::sleep(Duration::from_millis(50)) => {}
        }
        if tx.send(seq).await.is_err() { break; }
        seq += 1;
    }
});
```

**2. Приём в потребителе с сигналом (future живёт всю программу):**

```rust
let sigint = tokio::signal::ctrl_c();
tokio::pin!(sigint);                                     // один на программу
loop {
    tokio::select! {
        biased;
        _ = &mut sigint => { stop_tx.send(true); break; } // стоп + дренаж
        maybe = rx.recv() => { /* обработать */ }
    }
}
while let Some(seq) = rx.recv().await { /* дренаж */ }
producer.await?;
```

**Фактический вывод (Ctrl-C на 2-й секунде):**

```
  обработано 0
  ...
  обработано 37
SIGINT пойман: останавливаем производителя и дренируем очередь…
  производитель остановлен (стоп-сигнал)
итог: обработано 38 значений; очередь пуста, выходим с кодом 0
```

Обработано 38, очередь пуста, выход с кодом 0 — ничего не потеряно. `05-pipeline` — то же самое с мини-статистикой: `итог: обработано 73 значений; min=990.000 max=1009.999 avg=1000.235`.

## Как это устроено под капотом

- **Сигналы в tokio**: при первом `poll` `ctrl_c()` регистрируется обработчик SIGINT (self-pipe/пробуждение рантайма). Если future уронили и создали новую — между «drop старой» и «регистрацией новой» пришедший SIGINT теряется. Поэтому future держат одним (`pin!`) или используют `Signal::recv()` на живом экземпляре.
- **`watch`** — хранит одно значение + подписчики; `changed()` готово, когда значение изменилось. Идеален как флаг «остановиться».
- **Дренаж**: канал честно отдаёт буферизованное даже после закрытия; приём до `None` — «всё обработано».
- **`biased;`** — ветки опрашиваются по порядку: первая готовая выигрывает. Нужен, когда одна ветка «почти всегда готова» (обычный сообщений) — иначе редкая (сигнал) может вечно проигрывать случайный выбор.

## Типичные ошибки и грабли

1. **`ctrl_c()` в цикле** — сигнал теряется в окне между будущими (на стенде: пример «без pin!» не ловил SIGINT вообще — пришлось диагностировать). Держи future одним через `tokio::pin!`.
2. **Забыл `biased;`** — при постоянно готовой ветке `recv` сигнал может «не выиграть» случайный выбор.
3. **Остановка только потребителя** — производитель продолжает слать: канал не закрыт, дренаж не заканчивается. Останавливай ОБОИХ (стоп-сигнал производителю).
4. **Дренаж без таймаута** — если обработка элемента вечная, «грациозный» останов превращается в вечный. Промышленно — дренаж с дедлайном (лаба 01, «со звёздочкой»).
5. **Сигнал без `?`** — `ctrl_c()` возвращает `Result`; в бинарнике можно и `unwrap`, но в библиотеке — пробросить.

## Как это спросят на собеседовании

1. «Как корректно остановить воркер на деплое?» — сигнал (SIGTERM/SIGINT), остановка приёма, дренаж, таймаут дренажа, затем выход.
2. «Что будет, если пересоздавать `ctrl_c()` в цикле?» — потеря сигнала в окне между будущими (перерегистрация).
3. «Зачем `biased;` в select!?» — детерминизм при постоянно готовых ветках; иначе случайный выбор.
