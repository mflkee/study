# Урок 03: Массовая запись — построчно, batch (UNNEST), COPY

**Модуль / кейс:** 07-performance / кейс 2 (приём телеметрии), 8 (буферизация)
**Время:** 3 ч

## Зачем это нужно

Шлюз опрашивает устройства каждые 500 мс — за сутки это ~173 000 строк по одному устройству, а устройств много. Построчная запись («каждое показание — свой INSERT») — это сотни тысяч round-trip'ов. Нужны техники: пачки через `UNNEST` и быстрый протокол `COPY`.

## Ключевые идеи (сжато)

- **Построчно**: N INSERT'ов = N сетевых round-trip'ов, N транзакций, N планирований. Правильно только для редких операций.
- **Batch (UNNEST)**: один запрос на пачку — массивы мапятся в `UNNEST($n::тип[], …)`. Уже на порядки быстрее.
- **COPY**: специальный протокол массового импорта (`COPY FROM STDIN`), в sqlx — `copy_in_raw` + `send`/`finish`. Самый быстрый путь «файл-пачка → таблица».
- **Идемпотентность**: `UNIQUE(device_id, seq)` + `ON CONFLICT DO NOTHING` (модуль 10) — повторная доставка без дублей.

## Разбор на примере

```bash
cargo run --example 03-insert-methods -- --n 50000
```

Код — `examples/03-insert-methods.rs`: 50 000 точек, три метода на чистой таблице. Фактический вывод со стенда автора (цифры зависят от машины, соотношение стабильно):

```
метод       строк        время        строк/с
row         50000   218.010 с          229
batch       50000     0.295 с       169363
copy        50000     0.208 с       240622

быстрее всех: copy — 1049.2x против построчной записи
```

**Построчно** (`row`):

```rust
for pt in pts {
    sqlx::query("INSERT INTO telemetry_raw (device_id, seq, ts, value) VALUES ($1,$2,$3,$4)
                 ON CONFLICT (device_id, seq) DO NOTHING")
        .bind(pt.device_id).bind(pt.seq as i32).bind(pt.ts).bind(pt.value)
        .execute(pool).await?;
}
```

**Батч** (`batch`):

```rust
sqlx::query("INSERT INTO telemetry_raw (device_id, seq, ts, value)
             SELECT * FROM UNNEST($1::int[], $2::int[], $3::timestamptz[], $4::numeric[])
             ON CONFLICT (device_id, seq) DO NOTHING")
    .bind(&device_ids).bind(&seqs).bind(&ts).bind(&values)
    .execute(pool).await?;
```

**COPY** (`copy`):

```rust
let mut conn = pool.acquire().await?;
let mut copy = conn
    .copy_in_raw("COPY telemetry_raw (device_id, seq, ts, value) FROM STDIN WITH (FORMAT csv)")
    .await?;
copy.send(buf.as_bytes()).await?;   // текстовая пачка
copy.finish().await?;               // обязательно: иначе conn «сломан»
```

## Как это устроено под капотом

- Один INSERT = полный цикл «SQL → план → сеть → транзакция → коммит». Единичная стоимость мала, но суммарная — линейна по N.
- `UNNEST` разворачивает массивы в строки на сервере; один план, одна транзакция, N строк.
- `COPY` — протокол уровня протокола PostgreSQL: данные идут потоково без разбора SQL на строку; самый экономичный. `send` — байты CSV, `finish` — закрыть пачку и получить число строк.
- `ON CONFLICT DO NOTHING` требует `UNIQUE`-ограничения — это и есть «защита от дублей» при повторной отправке (кейс 8).

## Типичные ошибки и грабли

1. **COPY «не работает» для одной строки** — накладные на пачку занимают больше, чем выигрыш; COPY — для пачек (шлюз копит, потом разово шлёт: пример шлюза в 10-кратном буфере).
2. **Забыл `finish()`** — соединение остаётся в состоянии copy; следующий запрос падает. `abort()` — на ошибке.
3. **UNNEST с деФолтными типами** — явные касты `::int[]`, `::numeric[]` обязательны: иначе sqlx не смапит `Vec<Decimal>` в `numeric[]` гарантированно (см. код).
4. **Приём по одному значению раз в 500 мс** — не повод для COPY; копим в памяти шлюза N секунд → пачка (или буфер при потере связи — модуль 10).
5. **Дубли без `ON CONFLICT`** — повторный прогон удвоит данные.

## Мини-задание

Собери массив 10 000 показаний и запиши всеми тремя способами (пример 03); нарисуй таблицу «время × способ». Ответь: во сколько раз batch/COPY быстрее построчно и почему.

<details>
<summary>Ответ</summary>

На стенде курса: построчно ~ минуты (сотни строк/с), batch ~ сотни тыс. строк/с, COPY ~ ещё быстрее. Разница в количестве round-trip'ов и протоколе.

## Как это спросят на собеседовании

1. «Как вставить 1 000 000 строк быстрее?» — batch `UNNEST` или `COPY`; предпочитаю `COPY`, либо пачки по 5–50 тыс.
2. «Чем COPY отличается от INSERT?» — протокол потоковой передачи, без построчного плана; требует особого формата пачки.
3. «Как не допустить дублей при повторной доставке?» — `UNIQUE` + `ON CONFLICT (… ) DO NOTHING` (иначе точный `DO UPDATE SET`).
