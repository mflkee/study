# Теория модуля 07: производительность

Конспект-справочник. Развёрнутые примеры с фактическими выводами — в уроках (`lessons/`).

## EXPLAIN (урок 01)

- `EXPLAIN (ANALYZE, BUFFERS) <sql>` — фактические план/время/строки/чтения; без `ANALYZE` — оценки.
- Читаем от вложенных узлов: ищем `Seq Scan` на больших таблицах, «дорогие» `Nested Loop`, несовпадение `rows` (оценка vs факт).
- `Index Scan`/`Index Only Scan`/`Bitmap Heap Scan`/`Sort` — ориентиры плана.
- `ANALYZE` обновляет статистику; при кривых планах — статистика устарела.

## pg_stat_statements (урок 02)

- Агрегированная статистика по нормализованным запросам: `calls`, `total_exec_time`, `mean_exec_time`.
- Включение: `shared_preload_libraries=pg_stat_statements` + `CREATE EXTENSION` (стенд уже настроен).
- Сортируем по `total_exec_time` (= «съел больше всего времени суммарно»); `pg_stat_reset()` для чистых замеров.
- `dbid`/`query` — фильтры по базе/тексту.

## Массовая запись (урок 03)

- Построчно: N round-trip'ов (сотни строк/с). Батч `UNNEST`: один запрос, массивы → строки (сотни тыс./с). `COPY`: потоковый протокол, быстрее всех (пример на стенде: row 218 с vs batch 0.3 с vs copy 0.2 с на 50 тыс.).
- sqlx: `copy_in_raw("COPY … FROM STDIN …")` → `send(bytes)` → `finish()` (или `abort()`; без finish соединение «сломано»).
- Идемпотентность: `UNIQUE (device_id, seq)` + `ON CONFLICT DO NOTHING` (модуль 10).
- COPY уместен для пачек, не для «одно значение в 500 мс» — шлюз копит в памяти и шлёт пачку.

## Тюнинг пула (урок 04)

- Размер пула — компромисс: очередь в приложении vs давка на сервере. Эмпирика «ядра × 2…4», отдельный пул под тяжёлые.
- Симптомы: `PoolTimedOut`/рост ожиданий — пул мал; деградация CPU/память сервера — пул велик.
- Генератор нагрузки (пример 05) + `pgbench` — измеряем TPS × pool и ищем «плечо»; генератор не должен замерять сам себя.
