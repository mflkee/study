# Урок 02: Downsampling — агрегаты по интервалам, материализованные представления

**Модуль / кейс:** 08-timeseries-partitioning / кейс 5 (сменные и суточные отчёты)
**Время:** 2 ч

## Зачем это нужно

Миллион измерений — не для отчёта: нужны агрегаты «за смену», «за сутки». Их считают дважды: на лету (на маленьких окнах) и заранее (материализованные представления) — чтобы отчёт не сканировал исходную таблицу. Плюс календарная семантика смен и суток.

## Ключевые идеи (сжато)

- **date_bin(интервал, ts, origin)** — режет ts на бакеты от заданного начала (в отличие от `date_trunc`, у него управляемый «ноль»).
- Сменный/суточный отчёт = `GROUP BY` по бакету + агрегаты (count/sum). Отсюда же перцентили — `percentile_cont` (модуль 01).
- **Materialized View** — результат запроса «как таблица»: считаем один раз, читаем много.
- `REFRESH MATERIALIZED VIEW` — полное пересоздание (дорогое); «свежесть» — твоя забота (TimescaleDB умеет инкрементально — урок 03).

## Разбор на примере

```bash
docker compose exec -T postgres psql -U course -d course_m06 -f - < course/08-timeseries-partitioning/examples/03-downsampling.sql
```

**Сменный отчёт (12 часов) по устройствам** — бакеты `date_bin('12 hours', ts, origin)`:

```sql
SELECT date_bin('12 hours', ts, '2026-08-01 00:00:00+00'::timestamptz) AS shift,
       device_id, count(*) AS n, round(sum(value)::numeric, 2) AS total
  FROM measurements_part
 GROUP BY shift, device_id
 ORDER BY shift, device_id
 LIMIT 12;
```

**Суточный отчёт** — тот же запрос с `'1 day'` в `date_bin` (пример в файле 03).

**Материализованное представление** (суточники):

```sql
CREATE MATERIALIZED VIEW daq_daily AS
SELECT date_bin('1 day', ts, '2026-08-01 00:00:00+00'::timestamptz) AS day,
       device_id, count(*) AS n, sum(value) AS total
  FROM measurements_part GROUP BY day, device_id;
REFRESH MATERIALIZED VIEW daq_daily;
```

Фактический вывод (фрагмент, 24 строки за три дня × 8 устройств):

```
 2026-08-25 00:00:00+00 | 5 | 2021 |  989316.26
 2026-08-25 00:00:00+00 | 6 | 2104 | 1065529.29
 ...
```

Размеры на стенде: матвью суточников ≈ единицы МБ против ~60 МБ исходной таблицы (порядок: читать отчёт из матвью в разы быстрее и без скана сырья).

## Как это устроено под капотом

- `date_bin(interval, ts, origin)` — «округляет» ts к сетке с указанным сдвигом; ровные сутки/смены, привязанные к календарю СИКН (смена начинается в 00:00 и 12:00).
- Матвью — физическая таблица (хеп) + метаданные запроса; чтение из неё — как из таблицы.
- `REFRESH` пересчитывает всё (полный скан исходной); если данных много — это минуты и нагрузка; поэтому матвью «стареет» между REFRESH'ами (ловушка: отчёт вчерашний).

## Типичные ошибки и грабли

1. **`date_trunc` вместо `date_bin`** — сдвиг сетки не контролируется; смены «поедут» от полуночи UTC.
2. **Отчёт из «старого» REFRESH** — матвью не следит за новыми строками; в лабе 01 — ловушка «отчёт вчерашний».
3. **Редкий REFRESH на больших данных** — минуты простоя/нагрузки; TimescaleDB решает это частичным обновлением (урок 03).
4. **Агрегаты без индексов по бакету** — отчёты «на лету» сканируют; для партиций — фильтр по диапазону партиций ускоряет.
5. **Суммируешь `numeric` пачками** — суммы в отчётах регулярно большие; округляй на выходе (`round(sum(..)::numeric, 2)`), не поштучно.

## Мини-задание

Напиши «недельный отчёт»: по каждому устройству — сумма и среднее за неделю (2026-09-07..14), 7-дневными бакетами с `date_bin('7 days', ts, origin)`. Сверь сумму с прямым запросом, как в упражнении 01.

<details>
<summary>Ответ</summary>

`date_bin('7 days', ts, '2026-08-01'::timestamptz)` + фильтр по диапазону недели + `GROUP BY day, device_id`; сумма сверяется с `SELECT sum(value) FROM measurements_part WHERE ts >= … AND ts < …` (в упражнении 01 — тот же приём с 12-часовыми бакетами и ассертами).
</details>

## Как это спросят на собеседовании

1. «Чем date_bin отличается от date_trunc?» — у `date_bin` управляемое начало сетки (origin).
2. «Что такое матвью и зачем?» — предварительно посчитанный результат; читается как таблица; требует REFRESH.
3. «Как быть со свежестью?» — расписание REFRESH, инкрементальные агрегаты (TimescaleDB), лямбда-подходы — в модуле 09–10.
