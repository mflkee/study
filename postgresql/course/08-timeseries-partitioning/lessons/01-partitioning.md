# Урок 01: Партиционирование по времени, ретеншн, BRIN

**Модуль / кейс:** 08-timeseries-partitioning / кейс 5 (отчёты), 8 (буферизация)
**Время:** 2.5 ч

## Зачем это нужно

Временные ряды растут без остановки: «год телеметрии» — это десятки миллионов строк. Один `DELETE` по старью порождает bloat (модуль 03), один индекс — десятки ГБ. **Партиционирование** (разбиение по времени) решает три задачи разом: чтение ограничивается нужной партицией (pruning), а удаление устаревшего = `DROP TABLE` партиции (мгновенно, без VACUUM-хвоста).

## Ключевые идеи (сжато)

- Мастер-таблица `PARTITION BY RANGE (ts)` + партиции `FOR VALUES FROM … TO …` (у нас — по месяцам).
- **Pruning**: фильтр по ts читает только нужные партиции; в плане — один `Append`-узел с нужными.
- Партиционирование ≠ индекс: узкий запрос по device_id сканирует партицию целиком без индекса.
- **Ретеншн** = `DROP TABLE партиции` (менее чем мгновенно против DELETE); ловушка — «запоздалые данные» (лаба 01).
- **BRIN** — компактный индекс «диапазоны страниц» (24 кБ против 15 МБ B-tree на нашем стенде) — для больших таблиц и диапазонных запросов.

## Разбор на примере

```bash
docker compose exec -T postgres psql -U course -d course_m06 -f - < course/08-timeseries-partitioning/examples/01-partition-queries.sql
```

Сценарий (`00-setup-partitions.sql`: 1 М строк, партиции по месяцам). Фактические планы со стенда:

**1. Запрос «за день» читает ТОЛЬКО партицию сентября:**

```
Parallel Seq Scan on measurements_part_2026_09 measurements_part
```

**2. Тот же запрос по device_id без индекса — две партиции, Sequences:**

```
Parallel Append
  -> Parallel Seq Scan on measurements_part_2026_08 measurements_part_1
  -> Parallel Seq Scan on measurements_part_2026_09 measurements_part_2
  -> Parallel Seq Scan on measurements_part_2026_10 measurements_part_3   (0 строк)
```

**3. После индекса `(device_id, ts)` — время с 23 мс до 1.6 мс:**

```
Bitmap Heap Scan on measurements_part_2026_09 measurements_part
  -> Bitmap Index Scan on measurements_part_2026_09_device_id_ts_idx
```

**4. Размеры индексов на одной партиции (какой выберешь для своей задачи?):**

```
measurements_part_2026_09_device_id_ts_idx | 15 MB
measurements_part_2026_09_ts_idx           | 24 kB   (BRIN!)
```

Ретеншн — отдельный пример `02-retention.sql` (работает на своей таблице `hist`): дроп партиции убирает строки мгновенно.

## Как это устроено под капотом

- Мастер-таблица — «пустышка» (self-row не хранит: `pg_inherits` направляет в партиции).
- Планировщик раскрывает `RANGE`-ограничения партиций (по `pg_partitioned_table`/`pg_constraint`) и отбрасывает несовместимые — отсюда pruning.
- `CREATE INDEX ON мастер` создаёт индекс **в каждой партиции** (отсюда имена `…_2026_09_device_id_ts_idx`).
- BRIN хранит по одной записи на диапазон страниц (по умолчанию 128): дёшево по памяти, но «грубый» — для очень больших таблиц и широких диапазонов. Планировщик сам решает, когда его использовать (пример 01: на нашем диапазоне он предпочёл Seq Scan).

## Типичные ошибки и грабли

1. **«Партиционировали — и всё быстро»** — это работает только для фильтров по ts; узкий запрос по device_id без индекса по-прежнему сканирует партицию.
2. **Индекс забыли добавить** — партиции не дают индексов сами по себе.
3. **Ретеншн по «имени месяца» без проверки границ** — уничтожаются данные ещё «в пути» с буфера (лаба 01: `no partition of relation found for row`).
4. **`DELETE` в партиционированной таблице** — bloat; для ретеншна — `DROP PARTITION`/`DETACH`.
5. **BRIN ради BRIN** — проверяй `EXPLAIN`, а не верь «он быстрый»: маленькие выборки часто выгоднее по B-tree или Seq Scan.

## Мини-задание

Возьми запрос «последние 5 показаний устройства 7» и сравни EXPLAIN на партиционированной таблице до/после `CREATE INDEX ON measurements_part (device_id, ts DESC)`. Объясни, почему порядок колонок/сортировки важен.

<details>
<summary>Ответ</summary>

`(device_id, ts DESC)` позволяет взять 5 строк прямо из индекса (`Index Scan … Backward`/Descending) без сортировки. С `(device_id, ts)` ASC — планировщик возьмёт по хвосту либо отсортирует. Порядок колонок — под запрос: селективный первый, сортируемый второй.
</details>

## Как это спросят на собеседовании

1. «Что даёт партиционирование?» — pruning для чтения, мгновенный ретеншн, управление размером.
2. «Чем партиционирование отличается от индекса?» — физическое разбиение против логического ускорения; вместе они работают.
3. «Как безопасно удалять старое?» — по границам завершившихся партиций, с запасом на задержку доставки (лаба 01).
