# Урок 03: Property-based тесты (proptest)

**Модуль / кейс:** 12-testing / кейс 3 (точность расчётов)
**Время:** 2 ч

## Зачем это нужно

Пример-тесты ловят один кейс; **property-based** генерирует тысячи случайных входов и проверяет ИНВАРИАНТЫ. Для метрологических расчётов (кейс 3) это ключевое: накопление ошибки `f64` или нарушение границ не видны на «красивых» числах — proptest их выкапывает.

## Ключевые идеи (сжато)

- `proptest! { #[test] fn prop(a in range, b in range) { assert!(инвариант) } }` — генерирует входы, при провале жмёт к минимальному (shrinking).
- В proptest стиль единый: либо `assert!` (+ `()`), либо `prop_assert!` (+ `Result<(), TestCaseError>`) — смешивать нельзя.
- Инварианты массы нетто: `0 ≤ нетто ≤ брутто`, конечность, валидация неверных входов.
- Демонстрация vs f64: `diff_on` — расхождение decimal/f64 на «десятых» (свойство: всегда есть малая разница на некратных дробях).

## Разбор на примере

```bash
cargo test --test property
```

Код — `tests/property.rs`. Три инварианта:

```rust
proptest! {
    #[test]
    fn netto_bounded_and_non_negative(gross10 in 0..1_000_000i64, w10 in 0..1_000i64, s10 in 0..1_000i64) {
        // …
        if let Ok(n) = massa_netto(g, w, s) {
            assert!(n >= Decimal::ZERO, "нетто неотрицательна: {n}");
            assert!(n <= g, "нетто <= брутто: {n} > {g}");
        }
    }
}
```

Фактический итог (стенд): `test result: ok. 4 passed` — proptest прогнал инварианты на тысячах комбинаций за сотые доли секунды (на чистом decimal).

Плюс детерминированный тест «накопления»: сетка «десятых» ищет максимальное расхождение f64 vs decimal (печать `максимальное расхождение …`).

## Как это устроено под капотом

- proptest держит генераторы стратегий (`0..N`, `-1000.0f64..`, `prop::option`, …) и запускает тело много раз (по умолчанию 256 прогонов на случайных значениях).
- При провале — `shrinking`: уменьшает контрпример до минимального (удобно отлаживать).
- Инварианты — это «законы» функции; если функция их нарушает на хоть одном входе — тест падает с примером.

## Типичные ошибки и грабли

1. **Входы, нарушающие предусловия** — тестируйте инварианты «на валидной области» (воду+примеси < 100), иначе шум ложных падений.
2. **Смесь `assert!` и `prop_assert!`** — типы не сходятся; выбери один стиль (в курсе: `assert!`).
3. **Инвариант слабый (всегда истинный)** — тест «зелёный», пользы ноль; инварианты должны РЕАЛЬНО ломаться при баге (сломай функцию — тест падает).
4. **Не используется shrinking-вывод** — при провале читай минимальный пример, а не «тыщу значений».
5. **f64 в инвариантах** — «почти равно» с эпсилоном, не `==`; decimal — точные сравнения.

## Мини-задание

Добавь инвариант: «если вода = 0 и примеси = 0, то нетто = брутто (с точностью округления)» — и проверь, что он ломается, если округление неправильное.

fn zero_impurities_noop(gross10 in 0..1_000_000i64) {
    let g = dec_tenths(gross10);

## Как это спросят на собеседовании

1. «Что такое property-based тестирование?» — генерация случайных входов + проверка инвариантов; shrinking при провале.
2. «Какие инварианты у метрологических расчётов?» — границы, знак, точность, согласованность decimal/f64.
3. «Чем proptest отличается от обычных тестов?» — покрытие «пространства входов», а не фиксированных кейсов.
