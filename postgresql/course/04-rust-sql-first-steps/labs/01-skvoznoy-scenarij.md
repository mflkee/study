# Лаба 01: Считать из PG → посчитать → записать обратно

**Кейсы:** 1 (каталог на Rust), 3 (точность расчётов), 5 (отчёты)
**Модуль:** 04-rust-sql-first-steps
**Время:** 2 ч
**Тип:** реши сам (сквозной сценарий)

## Цель

Сквозной сценарий «историей данных»: взять из PostgreSQL сырую массу брутто массомера **M-01-001** за последние сутки (по данным сида), посчитать массу нетто по методике упражнения 02 (вода 0.50 %, примеси 0.05 %), записать результат в отдельную таблицу `derived_measurements` — и убедиться, что записанное совпадает с ручным расчётом.

Это заготовка будущих модулей: где данные лежат в PG, считаются метрики и пишутся обратно (модули 07–10, капстоун 14).

## Схема стенда

- Стенд курса (PostgreSQL 18.6, порт 15432) со схемой каталога: `examples/00-setup.sql` применён.
- Файл `examples/07-netto.rs` — заготовка: `main` написан полностью, два места с `todo!()` — чтение (`fetch_readings`) и запись (`write_derived`).
- Пререквизит: **решено упражнение 02** (`massa_netto` в `exercises/src/ex02_massa_netto.rs`) — лаба вызывает его.

## Шаги

1. Открой `examples/07-netto.rs`. Три секции уже готовы: таблица результата (`CREATE TABLE IF NOT EXISTS derived_measurements`), `TRUNCATE` перед запуском (идемпотентность), формат вывода в `main`.
2. **Чтение** — допиши `fetch_readings`: выбрать `m.ts, m.value AS gross` из `measurements m JOIN devices d ON d.id = m.device_id`, фильтр по `d.tag = $1` и `m.ts >= (SELECT max(ts) FROM measurements) - interval '24 hours'`, сортировка по `m.ts`. Используй `query_as::<_, RawReading>` + `bind(DEVICE_TAG)` + `fetch_all(pool)` (образец — пример 03).
3. **Запись** — допиши `write_derived`: `INSERT INTO derived_measurements (device_id, ts, gross, water, sediment, netto) VALUES ((SELECT id FROM devices WHERE tag = $1), $2, $3, $4, $5, $6)`, `bind` в порядке `$1..$6`, верни `Ok(res.rows_affected())`.
4. Запусти: `cargo run --example 07-netto`.

### Ожидаемый вывод (фактический, снят автором на стенде курса)

```
устройство: M-01-001 (последние сутки по данным сида)
считано измерений: 5
  2026-09-22 12:00:00 UTC  1005.250000  кг/ч
  2026-09-22 18:00:00 UTC  990.125000   кг/ч
  2026-09-23 00:00:00 UTC  995.000000   кг/ч
  2026-09-23 06:00:00 UTC  1002.750000  кг/ч
  2026-09-23 12:00:00 UTC  998.500000   кг/ч
записано строк: 5
```

5. **Сверка с руками.** Проверь в БД:

```bash
cd infra && docker compose exec -T postgres psql -U course -d course \
  -c "SELECT ts, gross, water, sediment, netto FROM derived_measurements ORDER BY ts;"
```

```text
           ts           |    gross    | water  | sediment |   netto
------------------------+-------------+--------+----------+------------
 2026-09-22 12:00:00+00 | 1005.250000 | 0.5000 |   0.0500 | 999.721100
 2026-09-22 18:00:00+00 |  990.125000 | 0.5000 |   0.0500 | 984.679300
 ...
```

Ручной расчёт первой строки: `1005.25 × (1 − 0.0055) = 1005.25 × 0.9945 = 999.721125` → округление до 4 знаков половиной от нуля → `999.7211`. В таблице — `999.721100` (numeric(20,6) хранит 6 знаков). Совпало.

## Критерии успеха

- [ ] `cargo run --example 07-netto` выводит 5 чтений и `записано строк: 5`
- [ ] В `derived_measurements` ровно 5 строк для массомера M-01-001
- [ ] Каждое `netto` совпадает с ручным расчётом (`gross × 0.9945`, округление до 4 знаков)
- [ ] Повторный запуск лабы не дублирует строки (идемпотентность через `TRUNCATE`)
- [ ] В коде нет `f64` для `gross`/`netto` — только `Decimal`

## Разбор типичных проблем

| Симптом | Причина | Решение |
|---|---|---|
| `считано измерений: 0` | фильтр по `now()`: сид датирован 22–23 сентября, а «сейчас» позже | фильтруй по `max(ts)` сида, как в заготовке |
| `netto` с длинным хвостом (`999.721125` вместо `999.7211`) | забыл округление или деление дало лишние знаки | `round_dp_with_strategy(4, MidpointAwayFromZero)` в упражнении 02 |
| ошибка «bind message supplies 0 parameters» | порядок `bind` не совпадает с `$1..$6` | привязывай строго по порядку или переименуй параметры |
| тип ошибки декодирования `Decimal` | `value` прочитан не в `Decimal`, а во `f64`/строку | поле структуры — `rust_decimal::Decimal` |
| в таблице строки с новым `id`, но данные не изменились | не делаешь `TRUNCATE` перед запуском | скрипт идемпотентен: `TRUNCATE ... RESTART IDENTITY` в начале |
| «netto не бьётся с SQL-калькулятором» | разный порядок округления | округляй один раз в конце, стратегия половина от нуля |

## Задания «со звёздочкой»

1. **Батч**: замени построчную запись на один запрос с `UNNEST` (образец — пример 05). Замерь время на 10 000 строк.
2. **Смена**: посчитай сумму «масса нетто за смену» (12 часов) — оконные функции прямо в SQL (модуль 01/08) либо суммируй `Decimal` в коде.
3. **Объём**: добавь плотность из сида (`D-01-001`) и посчитай объём `V = m_нетто / ρ`, округление 4 знака.
4. **Миграции**: вынеси `CREATE TABLE` в `sqlx migrate` (модуль 06) вместо `CREATE TABLE IF NOT EXISTS` в коде.
