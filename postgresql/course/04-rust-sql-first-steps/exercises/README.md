# Упражнения модуля 04

Как устроены упражнения и автопроверка.

## Заготовки и решения

- Заготовки: `exercises/src/ex01_katalog.rs` (кейс 1, CRUD каталога) и `exercises/src/ex02_massa_netto.rs` (кейс 3, масса нетто). В них — `todo!()` в местах, которые нужно написать самому.
- Заготовки включены в проект через `src/lib.rs` (`#[path = "../exercises/src/..."]`), поэтому компилируются и могут быть протестированы.
- Решения: `solutions/` — **открывай только после своей попытки**. Чтобы применить: скопируй содержимое файла решения в соответствующую заготовку.
- Лаба 01 использует заготовку `examples/07-netto.rs` (решение — `solutions/07-netto.rs`).

## Как проверять

Чистая логика (парсинг, форматирование, расчёты) проверяется юнит-тестами в `src/lib.rs` — без запуска PostgreSQL:

```bash
cargo test ex01_    # упражнение 01
cargo test ex02_    # упражнение 02
cargo test          # всё сразу
```

Поведение «до/после»:

- **До решения** тесты падают с `not yet implemented` (это нормально — так устроены todo!()-заготовки).
- **После решения** (скопировал из `solutions/`) — все тесты зелёные.

Код, работающий с БД, проверяется запуском против стенда:

```bash
cargo run --example 06-katalog-cli -- list-devices   # упражнение 01
cargo run --example 07-netto                          # лаба 01
```

## Контроль качества

```bash
cargo check --all-targets   # компилируется (в т.ч. все примеры)
cargo clippy --all-targets  # без предупреждений — и в заготовках, и в решениях
cargo fmt --check           # единый стиль
```

Заготовки поддерживаются в clippy-чистом состоянии: параметры с `_`-префиксом — намеренный приём «ещё не используется, будет использоваться в решении».
