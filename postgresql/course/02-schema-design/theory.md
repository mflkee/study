# Теория модуля 02: проектирование схемы

Конспект-справочник. Развёрнутые примеры — в уроках.

## Нормализация

- **1NF**: атомарные значения в ячейках, нет повторяющихся групп колонок.
- **2NF**: неключевые атрибуты зависят от всего первичного ключа (не от части).
- **3NF**: нет транзитивных зависимостей (неключевое → неключевое).
- На практике для производственных схем достаточно «разумной» 3NF; денормализация — осознанный шаг под производительность (агрегаты, кэши), а не лень.

Симптомы денормализации, которую надо чинить: повторяющиеся строки («линия + модель» в каждой записи измерения), массивы с «зашитыми» справочными данными, обновление одной сущности в N местах.

## Ключи и связи

- PK — уникальная идентификация строки; по умолчанию в PostgreSQL `serial`/`bigserial` (или `IDENTITY`).
- FK — целостность ссылок + выбор поведения `ON DELETE` (CASCADE / RESTRICT / SET NULL).
- UNIQUE — бизнес-ключ (тег устройства `M-01-001` уникален), создаёт индекс.
- Связи: 1:N (линия → устройства), 1:N (устройство → измерения), N:M — через таблицу-связку.

## Индексы (PG 18)

| Тип | Механика | Когда | Когда нет |
|---|---|---|---|
| B-tree (по умолчанию) | сбалансированное дерево | точные совпадения, диапазоны, ORDER BY, FK-проверки | колонки низкой кардинальности, «всё подряд» |
| BRIN | блочные мин/макс | большие append-only таблицы, выборки по диапазону упорядоченной колонки (`ts`) | точечные поиски, частые UPDATE |
| GIN | инвертированный индекс | jsonb/array/полнотекст | простые колонки (B-tree дешевле) |
| partial | B-tree + WHERE при создании | подзапросы по подмножеству строк | если предикат не совпадает с запросами |
| expression | индекс от выражения `lower(tag)` | запросы с функцией в WHERE | если функция редко используется |

- Индекс не бесплатен: занимает диск, замедляет INSERT/UPDATE.
- `pg_indexes` — системное представление: имена, определения.

## EXPLAIN — как читать

```sql
EXPLAIN (ANALYZE, BUFFERS, COSTS OFF) SELECT ...;
```

- Снизу вверх: операторы плана (Seq Scan → Index Scan → Bitmap Heap Scan → Hash Join...).
- `actual time` (ANALYZE) — реальное время; `rows` — оценки против факта.
- Шаги: Seq Scan = чтение всей таблицы; Index Scan = поиск по индексу; Bitmap Index Scan + Bitmap Heap Scan = индекс выбрал страницы, затем чтение кучи.
- Для телеметрии типичный вопрос: «запрос по времени» — BRIN отсекает блоки, точечные запросы по `device_id` — B-tree.

## Проектирование под временные ряды

Правила для потока измерений (measurements):

1. **Append-only**: пишем, редко обновляем; ретеншн — удаление старых блоков.
2. **Ключевой запрос определяет индекс**: «значения устройства за период» → индекс `(device_id, ts)`.
3. **BRIN на `ts`** — когда таблица большая и упорядочена по времени (пакетная запись по возрастанию ts).
4. **Точность**: числовые значения — `numeric`, время — `timestamptz` (модуль 01).
5. **Качество данных**: отдельная колонка `quality` (flags), partial-индекс для выборок «только брак».
6. **Справочники отдельно от потока**: линии/устройства — в справочниках, в потоке — только FK.
