Конспект-справочник. Развёрнутые примеры — в уроках; здесь — сжато, для быстрого повторения.

## Устройство данных курса (каталог оборудования)

Схема из `examples/00-schema-katalog.sql` — основа сквозных кейсов:

```
equipment_lines (id, name, description)
       │ 1:N
devices (id, line_id→lines, device_type, tag UNIQUE, model)
       │ 1:N
measurements (id, device_id→devices, ts timestamptz, value numeric(20,6), quality)
```

- `device_type` — `mass_meter` (массомер), `density_meter` (плотномер), `moisture_meter` (влагомер).
- `tag` — уникальный тег, напр. `M-01-001`.
- `value` — всегда `NUMERIC(20,6)`: метрологические величины храним без потери точности.

## WHERE — трёхзначная логика NULL

- `NULL` означает «нет значения», а не «ноль».
- `x = NULL` никогда не истина: сравнения с NULL дают NULL, который в `WHERE` трактуется как false.
- Проверка отсутствия: `x IS NULL` / `x IS NOT NULL`.

## Топ-5 типов под телеметрию

| Тип | Что хранит | Когда брать | Когда нет |
|---|---|---|---|
| `numeric(p,s)` | точное десятичное | деньги, массы, расчёты (метрология) | большие объёмы агрегатов — медленнее float8 |
| `float8` | приближённое | инженерная математика, «достаточно точности» | метрология, сравнения на равенство |
| `timestamptz` | момент времени (UTC внутри) | всё, что связано с «когда произошло» | — |
| `timestamp` | «стенное» время без пояса | календарь, расписание (осторожно!) | телеметрия и аудит |
| `jsonb` | документ, ключи нормализуются | разреженные/меняющиеся атрибуты | данные, по которым нужны жёсткие индексы и FK |

## Порядок выполнения SELECT

```
FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT
```

Фильтрация групп — `HAVING`, строк — `WHERE`. Оконные функции вычисляются после `HAVING`, перед `ORDER BY`.

## JOIN

- `INNER JOIN` — только совпавшие строки обеих сторон.
- `LEFT JOIN` — все строки левой + совпадения правой (нет совпадения → NULL справа).
- Условие связи всегда явное: `ON d.line_id = l.id`. Без `ON` получишь декартово произведение.

## Агрегаты и GROUP BY

- `count(*)` считает строки; `count(col)` — только не-NULL значения колонки.
- Всё, что не в агрегатной функции в `SELECT`, обязано быть в `GROUP BY`.
- `HAVING` — фильтр по результату агрегации.

## Оконные функции (для отчётов)

```sql
fn() OVER (PARTITION BY col ORDER BY ts)   -- окно = строки с тем же col, упорядоченные
row_number()  -- номер строки в окне
lag(x)        -- значение предыдущей строки окна
rank()        -- место с пропусками
sum(x) OVER() -- накопительная сумма
```

В отличие от `GROUP BY`, строки НЕ схлопываются: каждая строка остаётся, а окно добавляет вычисленное значение.
