# Лаба 01: REST API для дашборда — токены и кэш

**Кейсы:** 9 (REST API для дашборда), 6 (события)
**Модуль:** 11-web-api-axum
**Время:** 1.5 ч
**Тип:** доработай API (безопасность + производительность)

## Цель

Прод-готовность API дашборда: защита от посторонних (токен) и снижение нагрузки на БД (кэш текущих значений). Работаем с примером `02-measurements` и `src/lib.rs`.

## Задачи

**Часть A. Токен (простая аутентификация).**
1. В `AppState` добавь `token: String` (из env `API_TOKEN`, дефолт `'dev'`).
2. Хендлеры защищённого контура проверяют заголовок `Authorization: Bearer <token>`: неверный/отсутствующий → `401 {"error":"unauthorized"}`.
3. `/healthz` и `/metrics` остаются открытыми.
4. Проверь: `curl -s http://127.0.0.1:3091/devices` → 401; `curl -s -H "Authorization: Bearer dev" …/devices` → 200.

**Часть B. Кэш текущих значений.**
1. `GET /devices/{tag}/current` сейчас ходит в БД на каждый запрос; дашборд опрашивает каждые 5–10 с. Добавь кэш: `Mutex<HashMap<String, (DateTime<Utc>, CurrentValueDto)>>` в State; TTL 10 с.
2. При запросе: если кэш свежий — отдать без SQL; иначе обновить из БД и сохранить.
3. Проверь в логах/`metrics`: повторные запросы не пишут в БД (стенд: `pg_stat_statements.calls` для `current`-запроса не растёт).

## Критерии успеха

- [ ] Токен: 401 без токена, 200 с валидным; `/healthz`, `/metrics` открыты
- [ ] Кэш: второй запрос в пределах TTL не увеличивает `calls` в `pg_stat_statements`
- [ ] Кэш инвалидируется: новая запись в measurements → не позже TTL дашборд видит свежее значение
- [ ] Код: `cargo clippy`/`fmt` чисты, тесты зелёные

## Разбор типичных проблем

| Симптом | Причина | Решение |
|---|---|---|
| «401 виден в логе, но клиент получает 200» | проверил токен не в том хендлере/слое | сделай общий слой (middleware) или проверку в начале каждого защищённого хендлера |
| кэш «не работает» | ключ/время не обновляются либо TTL не проверяется | `Instant`/`DateTime<Utc>` рядом с кэш-значением, сравнение при чтении |
| утечка памяти кэша | HashMap растёт на каждый tag | ограничь размер (retain старые) или используй TTL-чистку |
| кэш живёт «вечно» | забыл TTL | храни метку времени записи; fresh = now - ts < ttl |
| тесты упали после кэша | тесты ждут свежих значений | в тестах TTL=0 или прогрев кэша явно |

## Задания «со звёздочкой»

1. **Cursor-пагинация**: замени `offset` на `cursor` (по `(ts, id)`) — стабильно на растущей таблице.
2. **Лимиты enter**: `tower-http` `RequestBodyLimitLayer`/`TimeoutLayer` — защита от зависших запросов.
3. **Prometheus-метрики**: подключи крейт `metrics`/`prometheus`, отдавай latency-percentiles.
