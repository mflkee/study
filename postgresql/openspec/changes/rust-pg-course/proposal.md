# Proposal

## Why

Ученик — взрослый инженер из области СИКН (измерение количества и качества нефти): данные сходятся по Modbus на промежуточный сервер, SCADA работает на PostgreSQL. Он хочет уверенно строить на Rust приложения поверх PostgreSQL — от SQL и проектирования схем до асинхронного доступа, миграций, тестов, производительности и эксплуатации. Готового курса нет: есть только бриф (промт), который требует превратить в практический курс с деревом файлов, автопроверками и воспроизводимым стендом. Репозиторий `study/tarantool` переориентирован под новую задачу (переименован в `postgresql`), старый бриф про Tarantool устарел.

## What Changes

- Создаётся `course/` — полный практический курс «Rust + PostgreSQL для СИКН» из 16 модулей (`00-orientation` … `15-interview-prep`), где каждый модуль имеет единую структуру: `README.md`, `theory.md`, `lessons/`, `examples/`, `exercises/`, `labs/` (+ cargo-проект с `src/lib.rs` и тестами в Rust-модулях).
- Rust-модули — отдельные cargo-проекты (`Cargo.toml`, `examples/`, `exercises/src/exNN_*.rs` + `lib.rs`), решения в `solutions/` (не открываются по умолчанию). Основной стек: `sqlx` 0.9 (async), `tokio` 1.53, `axum` 0.8, `rust_decimal` 1.43, `tokio-modbus` 0.17; Rust 1.98.
- Корневые файлы: `README.md` (карта курса), `PROGRESS.md` (чеклист прогресса), `resources/README.md` (ссылки на официальную доку), `infra/docker-compose.yml` (единый стенд с profiles: PostgreSQL 18.6, клиент psql/pgAdmin, Prometheus+Grafana и TimescaleDB — по мере нужды).
- Все 12 сквозных кейсов СИКН из брифа становятся основой упражнений и лаб (каталог оборудования, приём телеметрии Modbus, точность расчётов, журнал аудита, сменные/суточные отчёты, тревоги через NOTIFY, очередь задач, буферизация при потере связи, REST API для дашборда, эволюция схемы, нагрузочный стенд, инцидент «сломай и почини»).
- Процесс исполнения: планирование — в этом change (OpenSpec), исполнение — модуль за модулем через apply: после каждого модуля прогоняются проверки, обновляется `PROGRESS.md`, следует отчёт и пауза до команды «дальше».
- Каждое изменение контента проходит верификацию: `cargo check` / `cargo test` / `cargo clippy` для Rust, реальный запуск SQL в PostgreSQL через Docker, `docker compose config` для compose-файлов. Что проверить нельзя — помечается `<!-- UNVERIFIED -->` с объяснением.

## Capabilities

### New Capabilities

- `course-content`: структура и качество контента курса — рамка каждого модуля (README/theory/lessons/examples/exercises/labs), формат урока, формат упражнений (заготовка + автопроверка + решения в `solutions/`), формат лаб (стенд, шаги, критерии успеха, задания со звёздочкой), сквозные кейсы СИКН, правила качества (точность версий, без заглушек, без дословного копирования доков, 30/70 чтение/практика, грабли и ошибки обязательны).
- `course-stand`: стенд и верификация курса — единый `infra/docker-compose.yml` с profiles, воспроизводимый одной командой, зафиксированные версии (PostgreSQL 18.6, Rust 1.98, крейты), миграции и тестовые данные в репозитории, runner'ы проверок (cargo, SQL против живого PG, compose config), маркер `<!-- UNVERIFIED -->` для непроверенного.

### Modified Capabilities

- Нет (спеки проекта пусты, всё вводится впервые).

## Impact

- Весь репозиторий `study/postgresql` (бывший `tarantool`): переименование директории, новый бриф в `prompt.md`, новый корень `course/`.
- Код на Rust компилируется и тестируется локально (Rust 1.98.1) и в контейнерах; SQL выполняется против живого PostgreSQL 18.6 в Docker.
- Новые внешние зависимости: образы `postgres:18`, `timescale/timescaledb` (опция), `prom/prometheus`, `grafana/grafana`; крейты sqlx/tokio/axum/rust_decimal/tokio-modbus и их транзитивные зависимости.
- Изменений существующего кода нет: курс — новый контент в репозитории, где сейчас только `prompt.md`.
