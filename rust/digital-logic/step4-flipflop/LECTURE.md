# Ступень 4. Триггеры и регистры (состояние)

## Комбинационная vs последовательная логика

Всё до сих пор — **комбинационные** схемы: выход = чистая функция входа.
**Последовательные** схемы хранят состояние: выход зависит от прошлого.
Появляется память, а в Rust — `struct` + `impl` + `&mut self`.

## RS-триггер

Два NOR-гейта, замкнутых друг на друга (обратная связь). Хранит один бит.

| S | R | Q (следующее)          |
|---|---|------------------------|
| 0 | 0 | **держит** прежнее     |
| 1 | 0 | 1 (set)                |
| 0 | 1 | 0 (reset)              |
| 1 | 1 | запрещено (оба выхода 0) |

Как именно связаны входы и выходы двух NOR-гейтов — восстанови сам.

**Гонка (race).** В железе сигнал «устаканивается» через обратную связь за
пару проходов. В Rust присваивания последовательны, поэтому недостаточно
посчитать один шаг — нужно **прогнать обратную связь до стабилизации**
(пока значения не перестанут меняться). Это и есть модель «триггер щёлкнул».

## D-защёлка / D-триггер

Проще предыдущего: при активном сигнале «защёлкнуть» (`enable` / клок)
запоминает вход `D`, иначе держит прежнее значение.

## Регистр и сдвиг

Регистр — набор защёлок. **Сдвиговый регистр** на каждый клок сдвигает биты
влево и вдвигает новый бит в младший разряд — оба действия склеиваются в одно
выражение, собери его сам.

## Главная грабля: одновременное обновление

Обратная связь в железе меняется **одновременно**, а код исполняется
**последовательно**. Отсюда два правила:

1. Для комбинационной «одношаговой» связи — сначала вычисли новые значения в
   локальные переменные, затем присвой.
2. Для настоящей обратной связи (триггер) — итерируй до стабилизации.
