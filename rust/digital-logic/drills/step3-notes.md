## Инструменты

Главная идея ступени: сложение — поразрядное, перенос идёт в следующий разряд.

Структура мыслей:

- **Полусумматор** — сумма 2 бит без входного переноса: `sum = a ^ b`, `carry = a & b`.
- **Полный сумматор** — сумма 2 бит + входной перенос: удобно строить из двух полусумматоров. Или напрямую по таблице.
- **Многоразрядный** — цикл от 0 до 7 (или 15), держим `carry`, для каждого разряда считаем через полный сумматор; каждый разряд суммы вставляем в результат через `get_bit`/`set_bit`.
- **Вычитание** — `a - b = a + (-b)`, а `-b` в дополнительном коде — `!b + 1`.

Особенности:

- В решениях **запрещено** использовать встроенный `overflowing_add`/`overflowing_sub` — они только для сверки в тестах (проверки в adder8/adder16/add_cin/increment/overflowed/sub8 идут через встроенный).
- Для переполнения `u8` результата (переход через 255) достаточно смотреть, истинно ли перенос из старшего разряда (бит 7).
- `u16` нужен там, где сумма трёх байтов > 255: `add_three` должен вернуть `u16`.
- `wrapping_add/wrapping_sub` иногда нужны (например, `negate: (!x).wrapping_add(1)`).

## Блок 1. Слагаемые

### `half_adder`

Полусумматор складывает два бита `a,b`. Сумма — 1, если ровно один из них 1 (XOR). Перенос — 1, если оба 1 (AND).

```rust
fn half_adder(a: bool, b: bool) -> (bool, bool) {
    (a ^ b, a & b)
}
```

### `half_sum`, `half_carry`

Удобно выражать через `half_adder`, либо напрямую.

```rust
fn half_sum(a: bool, b: bool) -> bool { a ^ b }
fn half_carry(a: bool, b: bool) -> bool { a & b }
```

### `full_adder`

Три входа: `a, b, cin` (входной перенос). Строим из двух полусумматоров.

Логика: сначала сложить `a,b` → `(s1, c1)`, затем сложить `s1` с `cin` → `(sum, c2)`. Перенос из полного сумматора возникает, если есть перенос из первой половины ИЛИ из второй: `carry = c1 | c2`.

```rust
fn full_adder(a: bool, b: bool, cin: bool) -> (bool, bool) {
    let (s1, c1) = half_adder(a, b);
    let (s2, c2) = half_adder(s1, cin);
    (s2, c1 | c2)
}
```

Можно проверить по таблице (все 8 комбинаций) — совпадёт.

### `full_carry`

«Хотя бы два из трёх входов истинны» — это перенос полного сумматора. Прямая проверка: `a&b | a&cin | b&cin`.

```rust
fn full_carry(a: bool, b: bool, cin: bool) -> bool {
    (a & b) | (a & cin) | (b & cin)
}
```

## Блок 2. Многоразрядные

Фишка: идём по разрядам **от младшего к старшему** (бит 0 → бит 1 → ...), держим `carry`, для каждого разряда вставляем бит суммы в результат.

### `adder4`

Сложить **только младшие 4 бита** входов. Старшие биты входов игнорировать, результат тоже не выходит за 4 бита. Цикл по 0..4.

```rust
fn adder4(a: u8, b: u8) -> (u8, bool) {
    let mut sum = 0u8;
    let mut carry = false;
    for i in 0..4 {
        let (s, c) = full_adder(get_bit(a, i), get_bit(b, i), carry);
        if s { sum = set_bit(sum, i); }
        carry = c;
    }
    (sum, carry)
}
```

Перенос из бита 3 — это «отбросили» ли мы часть? В 4-битном контексте он обозначает, что сумма > 15. Тесты это проверяют.

### `adder8`

Тот же паттерн, только по 0..8. Перенос из бита 7 — это **переполнение** 8-битного результата.

```rust
fn adder8(a: u8, b: u8) -> (u8, bool) {
    let mut sum = 0u8;
    let mut carry = false;
    for i in 0..8 {
        let (s, c) = full_adder(get_bit(a, i), get_bit(b, i), carry);
        if s { sum = set_bit(sum, i); }
        carry = c;
    }
    (sum, carry)
}
```

Тесты сверяют с `a.overflowing_add(b)` — оба компонента должны совпасть.

### `add_cin`

Сложение с входным переносом `cin`. Отличие от `adder8` — не начинать с `carry = false`, а с `carry = cin`.

```rust
fn add_cin(a: u8, b: u8, cin: bool) -> (u8, bool) {
    let mut sum = 0u8;
    let mut carry = cin;
    for i in 0..8 {
        let (s, c) = full_adder(get_bit(a, i), get_bit(b, i), carry);
        if s { sum = set_bit(sum, i); }
        carry = c;
    }
    (sum, carry)
}
```

Тесты проверяют через `a as u16 + b as u16 + cin as u16` — сумма может быть 512+, поэтому для проверки переполнения сравнивают с `total > 0xFF`.

### `adder16`

Тот же цикл, но по 16 разрядам и тип `u16`. Для чтения битов можно использовать `(a >> i) & 1 == 1` напрямую (без `get_bit` из u8-помощников) — так экономнее. Для записи — `sum |= 1u16 << i`.

```rust
fn adder16(a: u16, b: u16) -> (u16, bool) {
    let mut sum = 0u16;
    let mut carry = false;
    for i in 0..16 {
        let a_bit = (a >> i) & 1 == 1;
        let b_bit = (b >> i) & 1 == 1;
        let (s, c) = full_adder(a_bit, b_bit, carry);
        if s { sum |= 1u16 << i; }
        carry = c;
    }
    (sum, carry)
}
```

Перенос из бита 15 — переполнение 16-битного результата. Тесты сверяют с `a.overflowing_add(b)`.

### `increment`

Прибавить 1 — частный случай сумматора: `x + 1`. Проще всего через `adder8(x, 1)`. Результат и переполнение должны совпадать с `x.overflowing_add(1)`.

```rust
fn increment(x: u8) -> (u8, bool) {
    adder8(x, 1)
}
```

Можно и вручную по младшему биту, но через сумматор понятнее и реже ошибиться.

## Блок 3. Применение

### `overflowed`

Было ли переполнение при сложении `a+b`? Переполнение — перенос из старшего бита в `adder8`. Значит достаточно вернуть `.1` от результата.

```rust
fn overflowed(a: u8, b: u8) -> bool {
    adder8(a, b).1
}
```

Тесты также сверяют с `a.overflowing_add(b).1`.

### `add_three`

Сумма трёх байтов может быть 765 — максимум для `255+255+255`. `u8` вмещает только 255, поэтому результат **должен** быть `u16`.

Проще всего сложить в `u16`: `a as u16 + b as u16 + c as u16`. Но в духе ступени можно было бы последовательно суммировать через свой `adder8` и учесть перенос, потом добавить третий — но арифметика в `u16` лаконична и точно показывает, что мы думаем «арифметически». Тесты ожидают именно это значение.

```rust
fn add_three(a: u8, b: u8, c: u8) -> u16 {
    a as u16 + b as u16 + c as u16
}
```

### `negate`

Дополнительный код (two's complement) для `u8`: `-x` представляется как `!x + 1`. Идея проста, но есть ловушка: `(!0) + 1 = 255 + 1`, и если делать обычный `+` — это может рассматриваться как переполнение; в Rust `255u8 + 1` в debug вызовет паника. Поэтому нужен `wrapping_add`.

```rust
fn negate(x: u8) -> u8 {
    (!x).wrapping_add(1)
}
```

Проверки: `negate(0)=0`, `negate(1)=255`, `negate(255)=1`, `negate(128)=128` (самый старший бит — «минус 128»). Тесты сверяют с `0u8.wrapping_sub(x)`.

### `sub8`

Вычитание `a - b` строим через дополнительный код: `a - b = a + (-b) = a + negate(b)`. Перенос здесь — не то же самое, что в чистом сложении; важно то, что **заём** возникает, когда `a < b`.

Тесты для `sub8(a,b)` сверяют с `a.overflowing_sub(b)`. Результат tuple — `(result, borrow)`, где `borrow` в тестах интерпретируется как «был ли заём» (результат ушёл в минус). Для представления беззнакового вычитания, `a < b` как раз означает заём.

```rust
fn sub8(a: u8, b: u8) -> (u8, bool) {
    let (r, _) = adder8(a, negate(b));
    (r, a < b)
}
```

Почему игнорируем второй компонент от `adder8(a, negate(b))`? Потому что биты результата те же самые, что и при математическом вычитании в 8-битном дополнительном коде; интерпретация переноса/заёма для беззнакового случая разная. Тесты ожидают `(a-b в беззнаковом смысле, a < b)`, что именно так и получается. Сверка с `overflowing_sub` подтверждает корректность.

Проверки: `sub8(5,3) = (2, false)`, `sub8(3,5) = (254, true)`, `sub8(0,1) = (255, true)`.
