## Инструмент на все упражнения: из таблицы в выражение

Напомню процедуру из лекции (раздел «Как вывести выражение по таблице») — она
механическая, и её хватает для большинства упражнений:

1. **Кирпич строки.** Вход `1` → имя как есть (`a`), вход `0` → имя с `!`
   (`!a`); соединить через `&`. Такой кирпич истинен ровно на одной строке.
2. **Мало единиц** → соединить кирпичи строк с единицей через `|` (ДНФ).
   **Мало нулей** → обернуть кирпич каждой нулевой строки в `!` и соединить
   через `&` (КНФ). Выбирай по тому, каких строк меньше.
3. **Упростить** по шпаргалке: Морган, `x & !x = 0`, `x | !x = 1`, вынесение,
   поглощение.

Дальше у каждого упражнения — за что зацепиться и где подводный камень.

## Блок 1. Гейты и их смыслы

Базовые гейты — это чтение определения в код. Полезно уметь в обе стороны: по
названию написать выражение и по выражению назвать гейт.

### `not` — NOT

Определение: истина, когда вход ложен. Это ровно `!a`, и ничего больше.

```rust
fn not(a: bool) -> bool {
    !a
}
```

Проверка: `not(false)` → `!false` = `true` ✔, `not(true)` → `false` ✔.

### `nand` — NAND

«Не-и» = NOT(AND) = `!(a & b)`. Ложь ровно в одном случае — когда оба входа
истинны; поэтому и записывается как отрицание AND.

```rust
fn nand(a: bool, b: bool) -> bool {
    !(a & b)
}
```

Грабли, на которых легко поскользнуться: `!&a` — это **не** «не-и». `&a` здесь
унарный `&`, то есть взятие ссылки, и всё выражение означает `!(ссылка на a)`,
что равно `!a`. Вход `b` при этом не используется, поэтому компилятор скажет
`warning: unused variable: b`, а тест упадёт на `nand(true, false)` (вернётся
`false` вместо `true`). Признак ошибки простой: NAND — операция от **двух**
входов, значит `b` обязан участвовать в выражении.

### `nor` — NOR

«Не-или» = `!(a | b)`. Истина только когда оба входа ложны.

```rust
fn nor(a: bool, b: bool) -> bool {
    !(a | b)
}
```

Полезно заметить симметрию: NAND и NOR — это AND и OR «вверх ногами». У NAND три
истины и один ноль, у NOR — один истина и три нуля. Поэтому тесты у них
зеркальные, и это хороший самоконтроль.

### `xnor` — XNOR

«Равенство»: истина, когда входы совпадают. Самый быстрый путь — заметить, что
XOR истинно при **различии**, а значит XNOR = `!(a ^ b)`.

```rust
fn xnor(a: bool, b: bool) -> bool {
    !(a ^ b)
}
```

Проверка: `xnor(false, false)` → `!(false)` = `true` ✔ (совпадают),
`xnor(false, true)` → `!(true)` = `false` ✔ (разные).

Второй способ — прямо по таблице: совпадения это строки `(F,F)` и `(T,T)`, значит
`(!a & !b) | (a & b)`. Это одна и та же функция с `!(a ^ b)`, и в блоке 4
упражнение `gates_equal` сравнивает именно эти две записи.

### `implies` — импликация

Разобран подробно в лекции (разделы «Импликация» и «Как вывести выражение по
таблице»). Короткая версия: запрещённая строка одна — `a=1, b=0`, её кирпич
`a & !b`, поэтому ответ `!(a & !b)`, а после Моргана — `!a | b`.

```rust
fn implies(a: bool, b: bool) -> bool {
    !a | b
}
```

Осторожно с соблазном «импликация звучит как И»: `a & b` — это AND, у него три
нуля и одна единица, а у импликации наоборот — три единицы и один ноль. Тест на
`implies(true, false)` это ловит сразу.

## Блок 2. Собрать из NAND

Это блок про **NAND-полноту**: снаружи разрешён только NAND, то есть выражения
вида `!(x & y)`. Запрещены `|`, `^`, `&&`, `||` — всё, кроме `&`, `!` и скобок
внутри NAND.

Стратегия: не угадывать выражение целиком, а собрать **маленькие заготовки** и
комбинировать их.

| Что нужно | Заготовка | Почему |
|---|---|---|
| NOT x | `!(x & x)` | `x & x = x`, значит `!(x & x) = !x` |
| x AND y | `!(!(x & y) & !(x & y))` | NAND уже даёт `!(x & y)`; вторым NAND снимаем отрицание |
| x OR y | `!(!(x & x) & !(y & y))` | по Моргану `x \| y = !(!x & !y)` |

Два главных приёма. Первый — **инвертор** `!(x & x)`: он превращает любое
выражение в его отрицание, и нужен почти везде. Второй — **двойное отрицание**:
чтобы вернуть инвертированное обратно, инвертируй ещё раз.

Отсюда и вывод блока: из NOT, AND, OR можно собрать любую таблицу (это ДНФ из
блока 1), а NOT, AND, OR собираются из одного NAND — значит из одного NAND
собирается **вообще всё**. Это и называется NAND-полнота; поэтому в железе NAND
так любят.

### `not_from_nand` — начни с него

Самый простой, и он же нужен остальным. Ход мысли: NAND двух **одинаковых**
входов — это «не-и от x и x», то есть `!(x & x)`, а `x & x` это просто `x`.
Значит `!(a & a)` = `!a`.

```rust
fn not_from_nand(a: bool) -> bool {
    !(a & a)
}
```

### `and_from_nand`

Внутри NAND уже есть `a & b`, но завёрнутое в `!`. Чтобы получить просто `a & b`,
надо снять отрицание — то есть **инвертировать ещё раз**. Инвертор у нас есть из
предыдущего упражнения, только теперь вместо `x` подставляем весь `!(a & b)`:

```text
x     = !(a & b)
NOT x = !(x & x)      ← инвертор
```

Получается NAND, применённый к самому себе. Смысл — двойное отрицание:
`!!!(a & b) = !(a & b)`, то есть знак `!` гаснет.

```rust
fn and_from_nand(a: bool, b: bool) -> bool {
    !(!(a & b) & !(a & b))
}
```

### `or_from_nand`

NAND напрямую не годится: это «не-и», а нужно «или». Мост — **закон де Моргана**:
`a | b = !(!a & !b)`. Иначе говоря, «или» — это «не (не a и не b)» — ровно то,
что написано в подсказке к упражнению.

Осталось заметить, что `!(!a & !b)` — это NAND, применённый к `!a` и `!b`, а
`!a` и `!b` делает инвертор:

```text
!a  = !(a & a)
!b  = !(b & b)
a|b = !(!a & !b)        ← это NAND(!a, !b)
```

```rust
fn or_from_nand(a: bool, b: bool) -> bool {
    !(!(a & a) & !(b & b))
}
```

Если при чтении длинного выражения «теряется смысл» — считай его по шагам,
подставляя значения. `a=true, b=false`: `!(a&a)` = `!true` = `false`,
`!(b&b)` = `!false` = `true`, итог `!(false & true)` = `!false` = `true` ✔.

### `xor_from_nand`

Здесь четыре NAND, и угадывать бесполезно — иди по схеме из подсказки. Идея: XOR
истинно, когда входы **разные**, то есть «есть хотя бы один, но не оба».

```text
n1  = NAND(a, b)    → истинно, когда не оба сразу («не и»)
n2  = NAND(a, n1)
n3  = NAND(b, n1)
out = NAND(n2, n3)
```

Почему это XOR. `n1` — «не оба». Тогда `a & n1` означает «a истинно, и при этом
не оба» = «a истинно, а b ложно», и после отрицания `n2 = !(a & n1)` читается как
«a ложно **или** b истинно». Симметрично `n3 = !(b & n1)`. Последний NAND от них
двоих даёт «ровно один из двух» — это и есть XOR. Проворачивать эту алгебру в
голове до конца не обязательно: подстановка строк `TT` и `TF` даёт уверенность
быстрее.

```rust
fn xor_from_nand(a: bool, b: bool) -> bool {
    let n1 = !(a & b);
    let n2 = !(a & n1);
    let n3 = !(b & n1);
    !(n2 & n3)
}
```

`let n1 = ...` — это не «ещё одно упражнение», а просто имя для промежуточного
результата, чтобы не переписывать `!(a & b)` четыре раза. Компилятор такие имена
бесплатно убирает.

## Блок 3. Три входа

Здесь появляются два новых инструмента:

1. **Входов больше — строк больше, но процедура та же.** У трёх входов восемь
   строк, кирпич строки — AND из трёх членов. Выбор «ДНФ или КНФ» работает так
   же: считай единицы и нули.
2. **Иногда функция описывается арифметикой, а не таблицей.** `count_true` — это
   буквально сумма, и через неё часть упражнений становится короче и понятнее.

### `count_true`

Единственное упражнение блока, возвращающее не `bool`, а число. У `bool` есть
приведение в целое: `true as u8` → `1`, `false as u8` → `0`. Значит «сколько
входов истинны» — это сумма трёх приведений.

```rust
fn count_true(a: bool, b: bool, c: bool) -> u8 {
    a as u8 + b as u8 + c as u8
}
```

Почему `u8`, а не `bool`: сумма трёх битов бывает 0, 1, 2, 3 — это уже не бит.
Тип возврата задан сигнатурой, менять его не нужно.

### `majority`

«Хотя бы две единицы». Два способа, оба полезны.

**Через арифметику** — короче и читается сразу:

```rust
count_true(a, b, c) >= 2
```

**Через таблицу** — тренировки ради. Единицы в строках с двумя и тремя истинами:
`(T,T,F)`, `(T,F,T)`, `(F,T,T)`, `(T,T,T)`:

```text
(a & b & !c) | (a & !b & c) | (!a & b & c) | (a & b & c)
```

Упрощается красиво: вынесем `a & b` из первой и последней щепотки, `a & c` из
второй, `b & c` из третьей:

```text
(a & b) | (a & c) | (b & c)
```

Читается как «истинна любая пара входов» — и это ровно «хотя бы две единицы».

```rust
fn majority(a: bool, b: bool, c: bool) -> bool {
    (a & b) | (a & c) | (b & c)
}
```

### `all_equal`

Все три равны. Самый короткий путь — вспомнить, что равенство это `==` и что оно
**транзитивно**: если `a == b` и `b == c`, то и `a == c` автоматически.

```rust
fn all_equal(a: bool, b: bool, c: bool) -> bool {
    a == b && b == c
}
```

Обрати внимание: сравнений два, а не три — третье следует из первых двух.

Через таблицу тоже собирается, и тоже красиво: все равны = все единицы или все
нули = `(a & b & c) | (!a & !b & !c)`. Длиннее, зато напрямую из определения.

Грабли: `&&` — логическое «и» для `bool` (короткое замыкание), `&` — побитовое.
Для отдельных `bool` результат совпадает, но в условиях идиоматичнее `&&`.

### `odd_ones`

«Нечётное число единиц» — это **чётность**, а про чётность в курсе уже было: это
свойство XOR. XOR истинно, когда единиц нечётно, и он «складывается» по всем
входам: `a ^ b ^ c`.

Почему: XOR взаимно уничтожает одинаковые биты (`x ^ x = 0`). Значит пары единиц
гасят друг друга, и остаётся «одна лишняя единица» ровно тогда, когда их было
нечётно.

```rust
fn odd_ones(a: bool, b: bool, c: bool) -> bool {
    a ^ b ^ c
}
```

По таблице получилось бы четыре строки с единицей и длинное выражение; XOR — та
же функция, но в разы короче. Вот это и есть «узнавание формы»: таблица дала бы
верный ответ, а узнавание подсказывает, что это XOR.

### `exactly_one`

Ровно одна единица. В лоб — три строки с единицей: `(T,F,F)`, `(F,T,F)`,
`(F,F,T)`:

```text
(a & !b & !c) | (!a & b & !c) | (!a & !b & c)
```

Строки `(T,T,T)` в списке нет: там три единицы, а не одна.

Но если `count_true` уже сделан — выражай через него, читается мгновенно:

```rust
fn exactly_one(a: bool, b: bool, c: bool) -> bool {
    count_true(a, b, c) == 1
}
```

Работает потому, что `count_true(...)` возвращает `u8`, и `1` в этом сравнении —
тоже `u8`.

Красивое наблюдение: `exactly_one` и `odd_ones` — соседи. `odd_ones` истинно при
1 или 3 единицах, значит «ровно одна» = «нечётно, но не три». Отсюда третий
вариант — `odd_ones(a, b, c) && !(a & b & c)`.

## Блок 4. Выбор и функции как значения

Блок про то, что функция в Rust — это **значение**: её можно передать в другую
функцию и вызывать там.

### `mux`

Мультиплексор — переключатель: по сигналу `s` выбрать один из двух входов.
Словами: «если `s` — вернуть `a`, иначе вернуть `b`». В Rust это буквально есть:

```rust
fn mux(s: bool, a: bool, b: bool) -> bool {
    if s { a } else { b }
}
```

Через логику то же самое — `(s & a) | (!s & b)`: «взять `a`, когда `s`, и `b`,
когда не `s`». Оба варианта верны; `if` читается лучше и не требует ни `&`, ни
`|`.

Грабли: следи за порядком аргументов. Сигнатура `mux(s, a, b)`, и в тесте
`mux(true, true, false)` → `true` видно, что первый аргумент — селектор.

### `gates_equal`

Сравнить две функции на **всех четырёх** парах входов. Здесь появляется то, чего
раньше не было, — **цикл с ранним выходом**.

Ход мысли:

1. Перебрать четыре пары: `(F,F)`, `(F,T)`, `(T,F)`, `(T,T)`.
2. На каждой паре сравнить результаты двух функций.
3. Если где-то разошлись — ответ `false`, дальше проверять незачем.
4. Если дошли до конца — `true`.

```rust
fn gates_equal(g1: fn(bool, bool) -> bool, g2: fn(bool, bool) -> bool) -> bool {
    for a in [false, true] {
        for b in [false, true] {
            if g1(a, b) != g2(a, b) {
                return false;
            }
        }
    }
    true
}
```

Две вещи, на которых тут спотыкаются.

- **`true` нельзя возвращать внутри цикла.** Если вернуть `true` на первом же
  совпадении, функция скажет «гейты одинаковые», проверив одну пару из четырёх.
  Поэтому `true` стоит **после** цикла и означает «я прошёл всё и расхождений не
  нашёл». А `false` — наоборот, возвращается в момент находки, потому что одного
  расхождения достаточно.
- **Сравнивать надо результаты, а не текст.** В тесте сравниваются `!(a ^ b)` и
  `(a & b) | (!a & !b)` — два разных выражения и одна и та же функция (XNOR).
  Никакое сравнение исходников этого не поймает; ловит только вызов на всех
  парах.

Про сигнатуру: `g1: fn(bool, bool) -> bool` — это **указатель на функцию**.
Лямбды из тестов (`|a, b| a & b`) сюда подходят, потому что не захватывают
окружение. Отличие от `Fn(bool, bool) -> bool` в том, что `fn` — конкретный тип,
а `Fn` — обобщение; для этой задачи хватает `fn`.

Вариант без `return` — через «все ли»:

```rust
[(false, false), (false, true), (true, false), (true, true)]
    .iter()
    .all(|&(a, b)| g1(a, b) == g2(a, b))
```

`.all()` возвращает `true` только если предикат верен для **всех** элементов —
это и есть «дошёл до конца». Семантика та же, а грабли с `return` исчезают вовсе.

### `truth_table_rows`

Задача — «отпечаток»: сжать всю таблицу истинности в одно число `u8`, где строке
таблицы соответствует бит результата.

Почему это вообще возможно: у функции от двух `bool` ровно 4 строки, у `u8` ровно
8 бит — значит четыре бита взаимно однозначно задают функцию. Это тот же приём,
что в ступени 2: битовая маска хранит набор флагов.

Порядок строк задан в подсказке: `(F,F)` → бит 0, `(F,T)` → бит 1, `(T,F)` →
бит 2, `(T,T)` → бит 3. Алгоритм:

1. Начать с нуля: `let mut rows = 0u8;`
2. Пройти пары **по порядку**, помня номер `i` (для этого удобен `.enumerate()`).
3. Если функция на паре истинна — выставить бит `i`: `rows |= 1 << i;`
4. Вернуть накопленное.

```rust
fn truth_table_rows(g: fn(bool, bool) -> bool) -> u8 {
    let mut rows = 0u8;
    let pairs = [(false, false), (false, true), (true, false), (true, true)];
    for (i, (a, b)) in pairs.into_iter().enumerate() {
        if g(a, b) {
            rows |= 1 << i;
        }
    }
    rows
}
```

Разбор деталей:

- `rows |= 1 << i` — «или с единицей, сдвинутой на i позиций». Это
  `rows = rows | (1 << i)`: выставить бит, не затирая уже выставленные.
- `1 << i` для `i = 0..3` даёт `0b0001`, `0b0010`, `0b0100`, `0b1000` — ровно
  «бит номер i».
- `pairs.into_iter().enumerate()` даёт пары «(номер, значение)», а деструктуризация
  `(i, (a, b))` разбирает вложенность: элемент — это кортеж `(usize, (bool, bool))`.

Проверка логики на AND: единица только на `(T,T)` → бит 3 → `0b1000` ✔. На OR:
нули только на `(F,F)` → бит 0 пуст → `0b1110` ✔.

Без цикла то же самое выглядит так — иногда так даже нагляднее:

```rust
fn truth_table_rows(g: fn(bool, bool) -> bool) -> u8 {
    (g(false, false) as u8)
        | ((g(false, true) as u8) << 1)
        | ((g(true, false) as u8) << 2)
        | ((g(true, true) as u8) << 3)
}
```

Здесь видно соответствие «строка → её сдвиг» без арифметики индексов. Оба
варианта верны; цикл пригодится, если строк станет 8 или 16.

Бонус-проверка всего блока 2: отпечаток NAND (`0b0111`) — это инверсия отпечатка
AND (`0b1000`) в пределах четырёх бит. Если `and_from_nand` написан верно, это не
совпадение, а следствие.
