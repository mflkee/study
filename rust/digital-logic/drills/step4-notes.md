## Инструменты

Главное различие:

- **Защёлка (latch)** — управляется **уровнем** сигнала. Она «прозрачная»: меняет состояние, пока сигнал активен.
- **Триггер (flip-flop)** — срабатывает по **фронту** сигнала такта. Нужен переход `false → true` (rising edge). Поэтому структуры хранят **прошлое состояние такта** в поле `clk` (или просто запоминают предыдущий уровень).

Что такое фронт:

```rust
fn rising_edge(prev: bool, now: bool) -> bool {
    now && !prev
}
```

Другие идеи, которые пригодятся:

- **RS-триггер на NAND** — входы **инверсные (активные низким уровнем)**: `s == false` означает «поставить» (`Set`), `r == false` — «сбросить» (`Reset`). Оба `true` — держит состояние. Оба `false` — **запрещённое** состояние (оба выхода становятся `true`), тест его отдельно проверяет.
- **Обратная связь.** У RS-NAND формулы: `q = NAND(s, nq)`, `nq = NAND(r, q)`. При установке нового состояния надо пересчитать, пока не стабилизируется (небольшой цикл из нескольких итераций достаточно, потому что обратная связь небольшая).
- **Сдвиги и вставка бита.** Для регистров удобно вспоминать `shift_in` из ступени 2: `(x << 1) | (bit as u8)` — сдвиг влево, в младший разряд вставляем бит.
- **Кольцевой сдвиг**: старший бит не теряется, а «заворачивается» в младший. В Rust есть `u8::rotate_left(1)`.
- **Детектирование фронта в `&mut self`-методах.** Сравниваем `clk` текущий с `self.clk` (предыдущим). Если был фронт — делаем действие, затем **обязательно** сохраняем текущий такт: `self.clk = clk`.

## Блок 1. Триггеры

### `SrNandLatch::set(&mut self, s: bool, r: bool)`

RS-триггер на двух NAND с обратной связью. Входы инверсные: `s==false` активирует установку, `r==false` — сброс. При нормальной работе `s` и `r` не должны быть одновременно `false`.

Формулы схемы:

```text
q  = NAND(s, nq)
nq = NAND(r, q)
```

Поскольку они зависят друг от друга (обратная связь), при изменении входов значения могут сходиться не мгновенно. Поэтому в решении делается **небольшой итерационный цикл** (например, до 8 итераций) — пока `q, nq` не перестанут меняться. Это корректная модель работы такой схемы.

Ключевые точки из тестов:

- `new()` → `q = false, nq = true` (Q=0, Q̄=1)
- `set(false, true)` — `s` активен (низкий уровень) → установить Q=1: `q=true, nq=false`
- `set(true, true)` — оба неактивны → держит состояние (memory)
- `set(true, false)` — `r` активен → сбросить: `q=false, nq=true`
- `set(false, false)` — **запрещённое** состояние, ожидается `q==true && nq==true`

```rust
fn set(&mut self, s: bool, r: bool) {
    let (mut q, mut nq) = (self.q, self.nq);
    for _ in 0..8 {
        let next_q  = !(s & nq);
        let next_nq = !(r & q);
        if next_q == q && next_nq == nq { break; }
        q = next_q; nq = next_nq;
    }
    self.q = q; self.nq = nq;
}
```

### `DFlipFlop::clock(&mut self, d: bool, clk: bool)`

D-триггер запоминает `d` **по фронту** такта `clk` (переход `false → true`). Если фронта нет — состояние не меняется. Обязательно обновляем `self.clk = clk` в конце, чтобы на следующем вызове мы знали предыдущее значение такта.

Условие фронта: `clk && !self.clk`.

```rust
fn clock(&mut self, d: bool, clk: bool) {
    if clk && !self.clk {
        self.q = d;
    }
    self.clk = clk;
}
```

Обрати внимание на тесты: если такт держится высоким (`clk == true` и остался `true`) — фронта нет, `q` не меняется. Спад (`true → false`) тоже не записывает.

### `TFlipFlop::clock(&mut self, t: bool, clk: bool)`

T-триггер по фронту такта **переключает** выход (`q = !q`), если `t` истинно. Если `t` ложно — держит. Фронт тот же: `clk && !self.clk`.

```rust
fn clock(&mut self, t: bool, clk: bool) {
    if clk && !self.clk && t {
        self.q = !self.q;
    }
    self.clk = clk;
}
```

Тесты чётко разделяют: фронт есть/нет и значение `t`.

## Блок 2. Регистры

### `Counter8::clock(&mut self, enable: bool, clk: bool)`

8-битный счётчик увеличивается на 1 **по фронту** такта, **если** `enable == true`. При переполнении (255 → 256) обнуляется (нет выхода за пределы u8). Используем `wrapping_add(1)`, чтобы корректно получить 0 при переходе через 255.

```rust
fn clock(&mut self, enable: bool, clk: bool) {
    if clk && !self.clk && enable {
        self.value = self.value.wrapping_add(1);
    }
    self.clk = clk;
}
```

Тест: после установки `value = 255` и фронта с `enable=true` ожидается 0.

### `ShiftRight::clock(&mut self, din: bool)`

Сдвиговый регистр **вправо**. Биты уезжают в сторону младших позиций (`bits >> 1`), а новый бит `din` входит в **старший** разряд (бит 7).

Сдвиг влево на 1 старшим битом делает место для входа в старший разряд при сдвиге вправо? Формула: `(bits >> 1) | ((din as u8) << 7)`.

Объяснение: `bits >> 1` сдвигает всё вправо (бит 7 «выпадает», бит 0 исчезает). `((din as u8) << 7)` ставит `din` в позицию бита 7. OR их объединяет.

Тесты: `clock(true)` → `0b1000_0000`, потом `clock(false)` → `0b0100_0000`, `clock(true)` → `0b1010_0000`, `clock(true)` → `0b1101_0000`. Совпадает с формулой.

```rust
fn clock(&mut self, din: bool) {
    self.bits = (self.bits >> 1) | ((din as u8) << 7);
}
```

Обрати внимание: в этой структуре **нет поля `clk`** — метод назван `clock`, но принимает только `din`. По смыслу — «один такт = один вызов метода». Это важно (тесты вызывают `s.clock(...)` без второго параметра).

### `RotateLeft::clock(&mut self, clk: bool)`

Кольцевой сдвиг **влево** по фронту такта. Старший бит не теряется, а **заворачивается в младший** разряд.

В Rust для этого есть готовый метод `u8::rotate_left(1)`. Он делает именно кольцевой сдвиг влево на 1 бит: старший бит перемещается в позицию 0.

```rust
fn clock(&mut self, clk: bool) {
    if clk && !self.clk {
        self.bits = self.bits.rotate_left(1);
    }
    self.clk = clk;
}
```

Тест: начальное `0b1000_0001`, фронт → старший бит (7-й) заворачивается в младший → `0000_0011`. Ещё один фронт → `0000_0110`. Корректно.

### `LoadReg::load(&mut self, data: u8, load: bool, clk: bool)`

Параллельный регистр: по фронту такта, **если `load == true`**, целиком принимает `data`. Если `load == false` — держит текущее значение.

```rust
fn load(&mut self, data: u8, load: bool, clk: bool) {
    if clk && !self.clk && load {
        self.value = data;
    }
    self.clk = clk;
}
```

Тесты: фронт без `load` не меняет значение; фронт с `load` загружает новое; такт, оставшийся высоким, не даёт нового фронта.

## Блок 3. Применение

### `rising_edge(prev: bool, now: bool)`

Детектор фронта как чистая функция. Фронт — переход `false → true`: `now` истинно, а `prev` ложно.

```rust
fn rising_edge(prev: bool, now: bool) -> bool {
    now && !prev
}
```

### `serial_to_u8(bits: &[bool])`

Принять последовательность битов в байт. Первый бит в срезе — **самый старший**. Если битов больше 8 — учитывать только первые 8.

Алгоритм: накапливаем результат, сдвигаем влево на 1 и добавляем следующий бит в младший разряд (`acc = (acc << 1) | (*b as u8)`).

Почему первый бит — старший? Приём последовательности обычно идёт от старшего разряда к младшему (MSB-first). Например `[true, false, true, true]` → `0b1011` = 11. Первые 4 бита формируют байт: после приёма первого `true` acc=1 (00000001), второго `false` → (00000010)|0=00000010, третьего `true` → (00000100)|1=00000101, четвёртого `true` → (00001010)|1=00001011. Да, корректно.

Ограничение: `.iter().take(8)`. Если срез пустой — `acc` остаётся 0.

```rust
fn serial_to_u8(bits: &[bool]) -> u8 {
    let mut acc = 0u8;
    for b in bits.iter().take(8) {
        acc = (acc << 1) | (*b as u8);
    }
    acc
}
```

Тест с 10 битами: `[false,...,false,true,true]` (первые 8 нулевые) → результат 0. Корректно.

### `count_pulses(signal: &[bool])`

Посчитать импульсы (фронты) в сигнале. До начала записи сигнал был `false`. Один импульс = одна последовательность `false → true`.

Алгоритм: держим `prev = false`, для каждого `now` в сигнале проверяем `rising_edge(prev, now)` — если да, увеличиваем счётчик; затем `prev = now`.

```rust
fn count_pulses(signal: &[bool]) -> u8 {
    let mut count = 0u8;
    let mut prev = false;
    for &now in signal {
        if rising_edge(prev, now) {
            count += 1;
        }
        prev = now;
    }
    count
}
```

Проверки тестов: `[true]` даёт 1 (переход false→true в первый момент), `[true,true,true]` даёт 1 (только первый фронт), `[false,true]` даёт 1, `[true,false,true]` даёт 2, `[false,false,true,true,false,true]` даёт 2. Всё совпадает.

## Подсказка по фронту в методах со структурой

Ключевое правило: **сохраняй такт после проверки**. Порядок в методе с фронтом всегда один и тот же:

1. Если есть фронт `clk && !self.clk` (и, при необходимости, другие условия) — выполнить действие.
2. Обновить `self.clk = clk`.

Если забыть пункт 2 — фронт будет детектироваться повторно при следующих вызовах, пока `clk` не упадёт.
