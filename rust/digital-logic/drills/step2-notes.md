## Инструменты

Главный приём: «сдвиг + маска».

- `(x >> i) & 1` — прочитать бит `i` (биты нумеруются от 0 справа)
- `1u8 << i` — маска для бита `i`
- `x | (маска)` — установить бит
- `x & !маска` — сбросить бит
- `x ^ маска` — инвертировать бит

Особенности:

- `i` в сдвиге имеет тип `u32` (у `<<` и `>>` в Rust); число — `u8`. Не путай типы.
- Сдвиг на 8 для `u8` «переполняется» в поведении, но в задачах обычно `i < 8`. Учти это только в местах, где просили считать через `u16` (например, `mask_range`).
- `wrapping_sub` — нужен там, где обычное вычитание могло бы теоретически давать переполнение (но логически надо обходить проблему, например `clear_lowest_set_bit(0)`).

## Блок 1. Один бит

### `get_bit`

Надо определить, равен ли бит номер `i` единице. Сдвигаем вправо, чтобы нужный бит оказался в самом младшем, маскируем лишние.

```rust
fn get_bit(x: u8, i: u32) -> bool {
    ((x >> i) & 1) == 1
}
```

### `set_bit`

Поставить бит `i` в 1, остальные не трогать. Создаём маску `1 << i`, потом `OR`: там где был 0 — станет 1, там где был 1 — останется 1.

```rust
fn set_bit(x: u8, i: u32) -> u8 {
    x | (1u8 << i)
}
```

### `clear_bit`

Сбросить бит `i` в 0. Маска инвертируется: `!(1 << i)` — там, где маска имела 1 в позиции `i`, станет 0; остальные биты — 1. `AND` с такой маской обнулит только бит `i`.

```rust
fn clear_bit(x: u8, i: u32) -> u8 {
    x & !(1u8 << i)
}
```

Проверка: `clear_bit(0b1011, 2)` → маска для бита 2 `0b0100`, инверсия `0b1011`; `1011 & 1011 = 1011`? Жди: `0b1011` (11) & `!(0b0100)` = `0b1011 & 0b1011` (если брать младшие 4 бита для наглядности) = `0b1011`? Но тест хочет `0b1011` → `clear_bit(0b1011, 2)` должен дать `0b1011`? Подожди, посмотри тест: `assert_eq!(clear_bit(0b1111, 2), 0b1011)`. Да, сбрасываем бит 2 → `1111` становится `1011`.

### `flip_bit`

Инвертировать бит — XOR с маской. Там где маска 1 — бит меняется, где 0 — не трогается.

```rust
fn flip_bit(x: u8, i: u32) -> u8 {
    x ^ (1u8 << i)
}
```

### `write_bit`

Ставим бит в заданное значение: либо `set_bit`, либо `clear_bit`.

```rust
fn write_bit(x: u8, i: u32, value: bool) -> u8 {
    if value { set_bit(x, i) } else { clear_bit(x, i) }
}
```

Плюс: по смыслу он просто «присваивает» значению, не переворачивает случайно.

## Блок 2. Нибблы и маски

Ниббл — 4 бита. Младший ниббл: биты 0..3, старший: биты 4..7.

### `low_nibble`

Оставить только младшие 4 бита, старшие обнулить. Маска `0x0F = 0b0000_1111`.

```rust
fn low_nibble(x: u8) -> u8 {
    x & 0x0F
}
```

### `high_nibble`

Взять старшие 4 бита, но «прижать» к младшим позициям (сдвиг вправо на 4). Значение 0..15.

```rust
fn high_nibble(x: u8) -> u8 {
    x >> 4
}
```

Проверка: `0xAB` = `1010_1011`, сдвиг на 4 → `0000_1010` = `0x0A` ✔.

### `swap_nibbles`

Меняем местами младший и старший нибблы. Берём старший, сдвигаем влево на 4; берём младший, сдвигаем вправо на 4; объединяем через OR.

```rust
fn swap_nibbles(x: u8) -> u8 {
    (x << 4) | (x >> 4)
}
```

Работает даже с «перекрывающимися» битами? У каждого ниббла 4 бита — после сдвигов они оказываются в разных позициях, так что OR не конфликтует. Классика.

### `pack_nibbles`

Собираем байт из старшего и младшего нибблов. **Обязательно** отбрасываем лишние биты в каждом: `hi & 0x0F`, `lo & 0x0F`. Потом старший сдвигаем в верхние 4 бита.

```rust
fn pack_nibbles(hi: u8, lo: u8) -> u8 {
    ((hi & 0x0F) << 4) | (lo & 0x0F)
}
```

Объяснение теста `pack_nibbles(0xFF, 0xFF)` → `(0x0F << 4) | 0x0F = 0xF0 | 0x0F = 0xFF`? Ожидание `0xFF`. Да, правильная очистка даёт именно это.

### `unpack_nibbles`

Обратно: старший = верхние 4 бита, младший = нижние 4.

```rust
fn unpack_nibbles(x: u8) -> (u8, u8) {
    (x >> 4, x & 0x0F)
}
```

В тесте есть цикл обратного преобразования — хорошая проверка.

## Блок 3. Счёт и поиск

### `parity`

Чётность единиц — нечётное число единиц? Тест: `parity(1)` = true (1 единица), `parity(0b1010_0000)` = false (2 единицы), `parity(0b0000_0111)` = true (3). Значит true, если **нечётное** число единиц.

Классика — свёртка XOR по всем битам. Почему XOR: `1^1 = 0` (пара), `1^1^1 = 1` (тройка), `1^0=1`. XOR «накапливает» чётность.

Можно проверять все 8 бит вручную через `get_bit`:

```rust
fn parity(x: u8) -> bool {
    let mut acc = false;
    for i in 0..8 {
        acc ^= get_bit(x, i);
    }
    acc
}
```

В решениях есть и `x.count_ones() % 2 == 1` — красивое, но в тренажёре акцент на ручном способе. У тебя есть `get_bit`, так что цикл подходит.

### `count_bits`

Сколько единичных битов. В Rust есть встроенный `u8::count_ones()` — он короткий и корректный. В решении используется он, и это нормально (проверяет знания стандартных методов тоже). Тест просто сверяется со встроенным.

```rust
fn count_bits(x: u8) -> u32 {
    x.count_ones()
}
```

### `is_power_of_two`

Число — степень двойки, если в битах ровно **одна** единица. Ноль — не степень двойки.

Классический трюк: для числа с ровно одной единицей `x & (x - 1) == 0`, но при `x == 0` это даст `0 & (0xFF)` = 0 — ложноположительное. Поэтому нужен отдельный флаг `x != 0`.

```rust
fn is_power_of_two(x: u8) -> bool {
    x != 0 && (x & (x - 1)) == 0
}
```

Проверь на примерах: `1 = 0001 → 0001 & 0000 = 0` ✔; `2 = 0010 → 0010 & 0001 = 0` ✔; `4 → 0100 & 0011 = 0` ✔; `3 = 0011 → 0011 & 0010 = 0010 != 0` ✔; `0` отсекается ✔.

### `lowest_set_bit`

Номер самого младшего единичного бита (наименьший `i`, ближайший к младшему концу справа). Если единиц нет (`x == 0`) — `None`.

В Rust есть `trailing_zeros()` — считает, сколько нулей справа до первой единицы. Значит, это и есть индекс младшей единицы.

```rust
fn lowest_set_bit(x: u8) -> Option<u32> {
    if x == 0 { None } else { Some(x.trailing_zeros()) }
}
```

Подтверждение тестом: `0b1100` (12) — младший единичный бит это бит 2? `1100` в двоичном: биты 3 и 2 установлены, остальные 0. Младший единичный бит = наименьший индекс среди установленных → бит 2. Тест ожидает `Some(2)`. Да, верно. `0b1010_0000` — биты 7 и 5 установлены, младший единичный — 5. Тест ожидает `Some(5)`. Да.

### `clear_lowest_set_bit`

Сбросить самый младший единичный бит, остальные не трогать. Классика: `x & (x - 1)`. Почему работает? Вычитание 1 обнуляет самый младший единичный бит и переворачивает все нули справа от него; AND с оригиналом сохраняет старшие биты, обнуляет младший единичный и затирает перевёрнутую хвостовую часть.

```rust
fn clear_lowest_set_bit(x: u8) -> u8 {
    x & x.wrapping_sub(1)
}
```

Грабля: при `x == 0` обычное `x - 1` для `u8` — это underflow (паника в debug, или wrapping в release), поэтому нужен `wrapping_sub`. Тест для `0` ожидает `0`. Результат `0 & 255 = 0` — корректный.

Проверки: `1 (0001) → 1 & 0 = 0` ✔; `0b1011 (1011) → 1011 & 1010 = 1010` ✔; `0xFF (1111_1111) → 1111_1111 & 1111_1110 = 1111_1110` ✔.

## Блок 4. Байт целиком

### `byte_gates`

Один побитовый гейт работает сразу на всех 8 битах параллельно в битовой арифметике. Вернуть тройку (AND, OR, XOR).

```rust
fn byte_gates(a: u8, b: u8) -> (u8, u8, u8) {
    (a & b, a | b, a ^ b)
}
```

Проверка: `(0b1100_1010, 0b1010_0110)` → AND: `1000_0010`, OR: `1110_1110`, XOR: `0110_1100`. Да.

### `reverse_bits`

Развернуть порядок всех 8 бит: бит 0 меняется местами с битом 7, бит 1 — с битом 6 и т.д. Собрать руками через `get_bit`/`set_bit` в цикле (закрепление).

```rust
fn reverse_bits(x: u8) -> u8 {
    let mut out = 0u8;
    for i in 0..8 {
        if get_bit(x, i) {
            out = set_bit(out, 7 - i);
        }
    }
    out
}
```

Алгоритм: для каждого бита в исходном, если он 1 — ставим 1 в зеркальной позиции результата.

Тест проверяет соответствие `x.reverse_bits()` (встроенный) на всех 256 значениях — так что разница легко заметна.

### `mask_range`

Маска битов от `from` до `to` включительно (нумерация справа 0). Примеры: `mask_range(4, 7) == 0xF0`, `mask_range(0, 7) == 0xFF`.

Грабля: для ширины 8, `1u8 << 8` переполнится — надо считать в `u16`. Ширина = `to - from + 1`. Создаём `ones = (1u16 << width) - 1` (например ширина 4 → `1<<4=16=0x10, 16-1=15=0x0F`). Потом приводим к `u8` и сдвигаем на `from`.

```rust
fn mask_range(from: u32, to: u32) -> u8 {
    let width = to - from + 1;
    let ones = (1u16 << width) - 1;
    (ones as u8) << from
}
```

Проверки: width 1, from 0 → `(1<<1)-1=1`, `1<<0=1` ✔; width 1, from 7 → `1 << 7 = 128 = 0x80` ✔; width 4, from 4 → `15 << 4 = 240 = 0xF0` ✔; width 8, from 0 → `(1<<8)-1=255`, `255<<0 = 0xFF` ✔. Да, корректно с `u16` для width==8.

### `shift_in`

Сдвинуть байт влево на 1 и вдвинуть `bit` в младший разряд. Именно так работает сдвиговый регистр из ступени 4.

Формула: `(x << 1) | (bit as u8)`. При сдвиге влево старший бит теряется — тест это отражает (`0b1000_0000` → `0b0000_0000` при сдвиге без входа, если вход `false`).

```rust
fn shift_in(x: u8, bit: bool) -> u8 {
    (x << 1) | (bit as u8)
}
```

Проверки: `0b0000_0001, false` → `0000_0010 | 0 = 0010` ✔; `0b0000_0010, true` → `0000_0100 | 1 = 0101` ✔; `0, true` → `1` ✔.
