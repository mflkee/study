# Память проекта через Obsidian

У тебя подключен MCP-сервер `obsidian-memory` к vault `/home/mflkee/obs_main`.

## Когда обращаться к памяти

- В начале сессии — если в vault есть контекст по текущему проекту/задаче.
- При необходимости — для поиска по заметкам, тегам, ссылкам.
- В конце сессии — если были важные решения, выводы или ссылки, которые стоит сохранить.

## Как использовать

Используй инструменты MCP `obsidian-memory`:

- `search-vault` — поиск по содержимому vault.
- `read-note` — чтение конкретной заметки.
- `create-note` — создание новой заметки.
- `edit-note` — редактирование существующей заметки.
- `add-tags` / `remove-tags` / `rename-tag` — управление тегами.

## Работа с проектами

- При старте сессии, если пользователь упоминает проект или просит «перейти к проекту X», сначала найди и прочитай `opencode-memory/projects/<X>.md`.
- Если project-заметки нет — предложи создать её по шаблону `opencode-memory/templates/project-template.md`.
- Пиши в project-заметку цель, контекст, промпты и промежуточные результаты по ходу работы.

## Работа со сессиями

- В конце сессии, если были значимые результаты, создай или обнови `opencode-memory/sessions/<YYYY-MM-DD>.md`.
- Связывай сессию с проектом через тег `#project/<имя>` и вики-ссылку `[[opencode-memory/projects/<имя>]]`.
- Используй шаблон `opencode-memory/templates/session-template.md`.

## Поддержание контекста

- Читай `opencode-memory/projects/index.md` для понимания активных проектов.
- Перед ответом на сложный вопрос по проекту проверяй, есть ли в vault релевантные заметки через `search-vault`.
- Обновляй существующие заметки вместо создания дублей.

## Рекомендуемая структура памяти

В vault `/home/mflkee/obs_main` используй папку:

```
opencode-memory/
├── projects/
│   └── <название-проекта>.md
├── sessions/
│   └── <YYYY-MM-DD>.md
├── insights/
│   └── <тема-инсайта>.md
└── index.md
```

## Теги

- `#opencode` — для заметок, созданных через opencode.
- `#memory` — для долгосрочной памяти.
- `#project/<имя>` — для привязки к проекту.
- `#session/<YYYY-MM-DD>` — для привязки к сессии.

## Правила записи

- Храни конкретные факты, решения, ссылки и ошибки, а не полные логи.
- Используй frontmatter для метаданных: `date`, `tags`, `project`.
- Обновляй существующие заметки, а не создавай дубли.
- Перед записью проверяй, нет ли уже связанной заметки через `search-vault`.

## GitHub MCP

Подключен MCP-сервер `github` для работы с репозиториями, issues, pull requests и Actions.

- Доступные toolsets: `context`, `repos`, `issues`, `pull_requests`, `actions`.
- Используй `github` tools, когда нужно:
  - посмотреть статус workflow runs или логи Actions;
  - запустить workflow;
  - получить список issues/PRs;
  - прочитать содержимое файла в удалённом репозитории.
- Перед запуском destructive операций (например, `actions_run_trigger`) сверься с контекстом проекта из Obsidian.
