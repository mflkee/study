## 1. Что требуют практики

### Практика 5 — пагинация, сортировка, ошибки

| Требование (слайд) | Суть |
|---|---|
| Пагинация `page` + `per_page` | метаданные `total`, `page`, `per_page`, `total_pages`; `per_page ≤ 100` |
| Динамическая сортировка | `sort_by` + `sort_order=asc|desc`, **белый список** полей (иначе SQL-инъекция) |
| Единый формат ошибок | `ErrorResponse {detail, error_code, field?}`, глобальные обработчики |
| Кастомные исключения | `NotFoundError`, `ConflictError`, `ValidationError` |
| Валидация query-параметров | ограничения `ge/le`, разрешённые значения |

### Практика 6 — фильтрация, поиск, статистика

| Требование | Суть |
|---|---|
| Фильтрация | точное совпадение, диапазон (`min_`/`max_`), фильтр по связи (JOIN) |
| Поиск | LIKE/ILIKE минимум по 2 текстовым полям, работает **вместе** с фильтрами |
| Комбинирование | фильтры + поиск + сортировка + пагинация в одном эндпоинте |
| Статистика | 2–3 эндпоинта: `count/sum/avg/min/max`, `GROUP BY`, `HAVING` |
| Оптимизация | индексы под частые фильтры, `EXPLAIN ANALYZE`, `joinedload` против N+1 |

## 3. Чего не хватает (по слайдам)

| № | Пробел | Что сделать | Оценка |
|---|---|---|---|
| 1 | **Единый формат ошибок** | добавить `ErrorResponse {detail, error_code, field?}`, кастомные `NotFoundError/ConflictError/ValidationError` и глобальные `exception_handler`-ы | ~2–3 ч |
| 2 | **Нотация `page/per_page/total_pages`** | добавить `page`/`per_page` как алиасы к `limit`/`offset` (или новый `*_page`-эндпоинт), досчитать `total_pages` | ~1 ч |
| 3 | **Эндпоинты статистики** | `GET /api/v1/stats/equipment?group_by=status` — `count`, `sum`, `avg` через `func.count/sum`, `GROUP BY` | ~2 ч |
| 4 | Cursor-based пагинация | опционально: `after_id` для журнала событий | ~1 ч |
| 5 | Полнотекстовый поиск | опционально: `pg_trgm`/`tsvector` на `equipment.name` | ~2 ч |

Первые три пункта — ровно то, что просят на практиках 5 и 6; четвёртый и пятый в задании
идут как «плюс в карму».

## 4. Демо для пары (готовые команды)

```bash
BASE=http://localhost:8080/api/v1

# 1. Пагинация + метаданные
curl -s "$BASE/equipment/page?limit=5&offset=0" | jq '{total, limit, offset, n: (.items|length)}'

# 2. Сортировка (белый список полей — невалидное поле даст 422)
curl -s "$BASE/equipment/page?sort_key=name&sort_direction=desc&limit=3" | jq '.items[].name'

# 3. Фильтр по связи + точное совпадение
curl -s "$BASE/equipment/page?folder_id=1&status=active" | jq '.total'

# 4. Поиск вместе с фильтрами
curl -s "$BASE/equipment/page?query=При%2081&status=active" | jq '.items[].name'

# 5. Очередь поверок с метаданными
curl -s "$BASE/equipment/verifications/page?limit=10&offset=0" | jq '{total_items, n:(.items|length)}'

# 6. Отчёт (XLSX)
curl -s -o /tmp/equipment.xlsx "$BASE/equipment/export/xlsx" && file /tmp/equipment.xlsx
```

В Swagger (`/docs`) всё то же видно руками: три эндпоинта `/equipment/page`,
`/equipment/verifications/page`, `/equipment/repairs/page`, у каждого — параметры и примеры ответа.

## 5. Что говорить на паре

1. Пагинация и сортировка реализованы в нотации **limit/offset + Literal-whitelist**, метаданные
   отдаются (`total`, `limit`, `offset`); объяснить, почему это эквивалентно `page/per_page`
   и что `total_pages` — производное значение.
2. Фильтрация — 6 фильтров, включая по связи; поиск — термовый ILIKE, работает вместе с фильтрами.
3. Отчётность — экспорт XLSX по трём сущностям и журналу событий.
4. **Честно сказать, чего нет:** единый `ErrorResponse` с `error_code` и эндпоинты статистики —
   и назвать срок (2–3 дня). Это как раз следующие шаги по курсу.
5. Домашнее задание практики 6 (статистика + отчёт) закрывается экспортом и добавлением
   `/stats/*`; отчёт уже есть в виде XLSX-выгрузок.
