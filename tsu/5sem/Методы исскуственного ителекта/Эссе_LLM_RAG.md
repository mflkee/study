# Эссе: LLM + RAG в работе инженера по метрологии и АСУ ТП

**Дисциплина:** Методы искусственного интеллекта I · **Тема:** Лекция 4 (NLP и генеративный ИИ)
**Автор:** Макеев Глеб · **Дата:** 04.11.2026

## Задача

В моей профессии — инженер по метрологии и АСУ ТП на объектах с системами измерений
количества и показателей качества нефти (СИКН) — значительная часть времени уходит не на
работу с железом, а на поиск ответа в документах. Нужно быстро найти: какой межповерочный
интервал у конкретного преобразователя расхода, какую погрешность допускает методика
измерений, что именно требует ГОСТ при оформлении свидетельства о поверке, чем отличается
порядок ввода СИКН в эксплуатацию от порядка её аттестации. Ответы «размазаны» по десяткам
файлов: федеральный закон, ГОСТы, методики измерений, руководства по эксплуатации, паспорта
средств измерений, внутренние регламенты предприятия и переписка с поставщиками.

**LLM + RAG решает именно эту задачу:** ассистент получает вопрос на естественном языке,
находит в корпоративной базе знаний три-пять релевантных фрагментов и формулирует ответ со
ссылками на источники. В отличие от «голой» модели, RAG не выдумывает: ответ строится только
на документах, а ссылка на фрагмент позволяет инженеру проверить цитату за десять секунд.
Это критично в метрологии, где неверная цифра — это не «неточность формулировки», а
некорректный результат измерений и спор с надзорным органом.

## Облачный API или on-premise

Ключевой вопрос — где считать. Для нашей предметной области решающим является не стоимость
токена, а **контур обращения данных**.

| Критерий | Облачный API | On-premise |
|---|---|---|
| Данные | уходят внешнему провайдеру | не покидают контур предприятия |
| Старт | часы, оплата по факту | недели: сервер или GPU, обслуживание |
| Качество модели | лучшее доступное | ограничено железом |
| Сеть | нужен интернет, на промплощадке часто изолированный контур | работает в закрытом сегменте |
| Стоимость при больших объёмах | растёт с числом запросов | фиксированные CAPEX/OPEX |

**Мой выбор — гибридная схема с on-premise акцентом.** Векторная база и эмбеддинги
размещаются внутри контура: паспорта средств измерений, схемы СИКН, внутренние регламенты и
переписка не должны покидать предприятие. Генерация ответа — переключаемая: локальная модель
для запросов, затрагивающих конфиденциальные документы, и облачный API для «публичной» части
базы (ГОСТы, федеральные нормы), где качество ответа важнее режима. Такое разделение даёт
главное — воспроизводимость и проверяемость: инженер всегда видит, на каком фрагменте
построен ответ, а администратор — какие модели и где использовались.

Облако «в чистом виде» я бы допустил только для внутренней справочной системы без реальных
данных объектов. Полный on-premise с локальной LLM — следующий шаг: сегодня качество
русскоязычных локальных моделей достаточное для извлечения фактов по контексту, но требует
GPU и сопровождения, что для одного инженера избыточно.

## Вывод

Для моей профессии LLM + RAG — не «модная надстройка», а инструмент, снимающий рутину поиска
по нормативной документации и снижающий риск ошибки из-за устаревшей или неверно понятой
редакции документа. Оптимальная архитектура — RAG-контур с локальным хранением документов и
переключаемой моделью генерации: конфиденциальность внутри, качество ответа — снаружи.
