# П02. Постановка на миграционный учёт по месту пребывания

| Поле | Значение |
|---|---|
| **Название** | Постановка на миграционный учёт по месту пребывания |
| **Рамки** | Система «Дорожная карта миграционного учёта» |
| **Уровень** | Задача пользователя (пользовательский прецедент) |
| **Основной исполнитель** | Принимающая сторона — собственник (наниматель) жилого помещения (A2) |
| **Участники** | Принимающая сторона; Иностранный гражданин (A1); сотрудник ОВМ МВД (A4); ЕПГУ (A7); МФЦ (A6) |
| **Связанные прецеденты** | Включается в П12; предусловие для П03, П04, П08, П10, П11 |

## Заинтересованные лица и их интересы

| Лицо | Интерес |
|---|---|
| Иностранный гражданин | Быть на учёте в срок, не получить штраф и не лишиться права на патент |
| Принимающая сторона | Исполнить обязанность по уведомлению, не нести ответственность за просрочку и недостоверные сведения |
| Сотрудник ОВМ МВД | Уведомление корректно, адрес и срок соответствуют закону, учётные данные полны |
| Работодатель | Работник законно находится в РФ, трудовой договор не оспорят |
| Система (интерес владельца) | Данные учёта доступны для расчёта остальных сроков |

## Предусловия

- ИГ въехал в РФ; известны дата въезда, гражданство и адрес предполагаемого пребывания.
- Принимающая сторона дала согласие на проживание ИГ и имеет подтверждённое право на помещение.
- В Системе для профиля ИГ определён нормативный срок постановки на учёт (7, 15, 30 или 90 дней — по гражданству и статусу).

## Постусловия

- Уведомление о прибытии подано в подразделение по вопросам миграции (через ЕПГУ, МФЦ или лично) в установленный срок.
- В Системе зафиксирован результат: номер уведомления, дата постановки на учёт, адрес, срок пребывания; получена отрывная часть (при личной подаче) либо уведомление о приёме.
- Шаг «Миграционный учёт» в дорожной карте закрыт; при смене адреса запланирован новый срок.
- Принимающая сторона получила подтверждение выполнения своей обязанности.

## Основной успешный сценарий

| № | Действия исполнителя | Отклик системы |
|---|---|---|
| 1 | ИГ сообщает Системе адрес проживания и данные принимающей стороны | Система проверяет, что адрес заполнен полностью, и направляет принимающей стороне приглашение подтвердить готовность принять ИГ |
| 2 | Принимающая сторона подтверждает согласие и указывает сведения о помещении и о себе | Система проверяет комплект: паспорт ИГ, миграционная карта (при наличии), виза (для визовых стран), сведения о помещении |
| 3 | | Система рассчитывает крайнюю дату подачи уведомления, сравнивает её с текущей датой и показывает запас времени |
| 4 | Принимающая сторона заполняет уведомление о прибытии | Система проверяет обязательные поля и соответствие данных документу ИГ, формирует уведомление |
| 5 | Принимающая сторона подписывает и отправляет уведомление | Система передаёт уведомление в ЕПГУ (или формирует комплект для МФЦ / личного приёма) и фиксирует факт отправки |
| 6 | | Система получает подтверждение приёма: регистрационный номер, дату, отрывную часть |
| 7 | | Система сохраняет результат в деле ИГ, закрывает шаг, показывает ИГ подтверждение и памятку о сроке пребывания |
| 8 | | Система планирует контроль смены места пребывания: при переезде отсчёт пойдёт с даты прибытия по новому адресу |

## Альтернативные сценарии

**1а. Принимающая сторона отказывается подавать уведомление.**
1. Система фиксирует отказ и объясняет ИГ последствия (нарушение режима пребывания).
2. Система предлагает варианты: иное место пребывания, гостиница, организация, принимающая ИГ по договору.
3. Карта не закрывает шаг; ИГ получает задачу «найти принимающую сторону» с крайним сроком.

**2а. Срок постановки на учёт уже истёк.**
1. Система помечает шаг как просроченный и показывает риск административной ответственности для ИГ и для принимающей стороны.
2. Система формирует порядок действий по исправлению и предлагает обратиться в подразделение по вопросам миграции.

**4а. Данные в уведомлении расходятся с документом ИГ.**
1. Система указывает конкретные расхождения (ФИО, дата рождения, номер паспорта, адрес).
2. Принимающая сторона исправляет данные; отправка блокируется до устранения расхождений.

**5а. ЕПГУ недоступен или уведомление отклонено.**
1. Система сохраняет черновик и предлагает альтернативный канал — МФЦ или личный приём.
2. После подачи результат вносится в Систему вручную либо подтягивается из ЕПГУ при восстановлении связи.

**\*а. ИГ сменил место пребывания.**
1. ИГ сообщает новый адрес; Система рассчитывает срок постановки на учёт по новому адресу (по общему правилу — с даты прибытия).
2. Система открывает новый экземпляр шага, сохраняя историю предыдущего учёта.

## Специальные требования

- Уведомление должно быть отправлено не позднее рассчитанной даты; Система обязана предупреждать заранее (например, за 3 дня и в день срока).
- Все действия с уведомлением журналируются: кто, когда, какие данные изменил — это доказательная база при споре о просрочке.
- Персональные данные принимающей стороны обрабатываются на том же основании, что и данные ИГ.

## Частота использования

Один раз при въезде и при каждой смене места пребывания; для регулярно приезжающих ИГ — несколько раз в год.

## Открытые вопросы

- Обязана ли Система проверять право собственности принимающей стороны или достаточно заявления о согласии?
- Кто отвечает за достоверность сведений при подаче через МФЦ — принимающая сторона или сотрудник МФЦ?
- Нужно ли поддерживать постановку на учёт в гостинице и в организации (коллективное размещение) отдельным сценарием?
