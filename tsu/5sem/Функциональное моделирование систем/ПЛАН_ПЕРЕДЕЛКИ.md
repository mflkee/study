## Главное правило лабы 1: без «прецедентного каннибализма»

По записи защиты 20.11 (со слов пользователя, уточнить по транскрипту): у большинства команд
два-три прецедента, но один **поглощает** другой, а сценарии пересекаются так, что шаги одного
влияют на исходы другого. Это недопустимо, потому что:

- расширение системы должно быть **точечным**, в одном месте;
- изменение входных данных (анкета, загрузка документа) не должно менять результаты в нескольких
  прецедентах;
- разработчику неудобно и легко забыть, что менять нужно в двух местах.

Проверка для каждого прецедента:
1. Свой **результат** (что ИГ получает в итоге), не совпадающий с результатом соседнего.
2. Свои **входные данные**: данные анкеты и документов не переиспользуются в других прецедентах
   напрямую; если пересекаются — выносится в один прецедент, второй на него не влияет.
3. Альтернативы прецедента не вызывают шагов другого прецедента.

## Лабораторная 1 — прецеденты (переделываем полностью)

**Что убираем:**
- акторов МВД, работодателя, администратора системы, ЕПГУ/почты и т.п. — в акторах остаётся
  только **иностранный гражданин** (ИГ);
- внутреннюю логику системы и инварианты (не относятся к первой лабе);
- прецеденты-«техники» и 4-й прецедент.

**Что делаем:**
1. **Диаграмма прецедентов:** 1 актор (ИГ), **2–3 прецедента**, каждый — действие пользователя,
   а не работа системы. Кандидаты (по дорожной карте, раздел 7):
   - П1. Внести выданный патент и узнать сроки (7.1 — старт срока);
   - П2. Заключить трудовой договор или ГПХ (7.1);
   - П3. Получить напоминание и подтвердить уведомление МВД (7.2).
2. **Для каждого прецедента — свой сценарий:** таблица из двух колонок
   «Действия пользователя» | «Отклик системы», строки чередуются (сначала действие, потом отклик).
   Пример для П1: ИГ загружает патент → система показывает реквизиты → ИГ подтверждает →
   система запускает срок 2 месяца.
3. **Альтернативные исходы** в конце каждого прецедента — 1–2 штуки, «что могло пойти не так»
   (например, ИГ ввёл неверные реквизиты; срок уже истёк).
4. Без лишних разделов: границы, предусловия, длинные инварианты — не нужны.
