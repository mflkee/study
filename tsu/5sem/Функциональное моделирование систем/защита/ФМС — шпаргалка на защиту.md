```bash
cd ~/projects/fms-course/lab6-implementation
uv venv && uv pip install -r requirements.txt
.venv/bin/python -m pytest            # ожидаем: 84 passed
.venv/bin/uvicorn app.main:app --port 8099
# второй терминал:
BASE=http://127.0.0.1:8099 bash scripts/demo.sh
```

**Что происходит (7 шагов):** регистрация патента → трудовой договор → уведомление МВД через
ЕПГУ → авансовый платёж НДФЛ → настройка напоминаний → реестр → выгрузка CSV. В конце —
**повторное уведомление → 409** (это ИНВ-8, а не ошибка).

**Грабли:** номер патента `000777` фиксирован → на «грязном» процессе будет 409 `DUPLICATE_PATENT`;
перед показом перезапустить uvicorn. Хранилища in-memory → после перезапуска состояние чистое.
Порт в `demo.sh` — **8099**, в README — 8000: в Swagger открывать тот, что запущен.

Если демо не идёт — открыть `/docs` и прогнать 2–3 запроса руками (регистрация патента,
заключение договора, уведомление → 409).

## 6. Вопросы — короткие ответы (по одному предложению)

1. **Почему только 7.1 и 7.2?** Тема распределена по командам; остальные разделы — предусловия или чужие темы.
2. **Почему МВД вспомогательный?** В теме 7 система уведомление готовит и отправляет, а решения по патенту принимает МВД.
3. **Почему 7, а не 2 прецедента?** 7.1 и 7.2 — разные обязанности разных исполнителей; плюс расширения (НДФЛ, прекращение договора, отчётность).
4. **От какой даты считаются 2 месяца?** От даты выдачи патента (ИНВ-2/3); поздний ввод в систему срок не сдвигает.
5. **Чем SSD отличается от диаграммы коммуникаций?** SSD — «чёрный ящик»: актор и одна линия системы; коммуникации — внутренние объекты и сообщения.
6. **Почему 19 SSD при 16 операциях?** Одна операция может встречаться в нескольких сценариях; альтернативы показывают ветви, а не новые операции.
7. **Почему 16 операций, а ориентир 10–14?** Альтернативы потребовали отдельных операций (архивирование, отмена, возврат, подтверждение платежа, прекращение из-за неуплаты).
8. **Где живёт правило «2 месяца»?** Один класс `МодульКонтроляСроков` + `Clock` в коде; сроки считаются от даты выдачи.
9. **Что такое BCE?** Boundary (экран) → Control (сценарий/инварианты) → Entity (понятие предметной области), вниз — репозитории и шлюзы.
10. **Почему классы без типов языка?** Требование лаб. 5: предметные типы (`Дата`, `Сумма`, `Идентификатор`), ни `String`, ни `int`.
11. **Как проверяются инварианты?** `app/control/invariants.py`, вызов из сервисов (не из роутеров), на каждый инвариант — тест.
12. **Почему инварианты в сервисах?** Роутер можно обойти, сервис — нет; тесты бьют прямо в сервисы.
13. **Почему 46 классов, а сущностей меньше?** 19 сущностей + 4 вспомогательные структуры; остальное — экраны, управляющие, репозитории, шлюзы.
14. **Что заглушки?** ЕПГУ, Почта, ФНС — детерминированные ответы + режим отказа; подписи не проверяются.
15. **Аутентификация?** Учебная: логин в заголовке `X-User-Login` (по умолчанию `admin`), без пароля и ЕСИА.
16. **Хранение?** In-memory за интерфейсами репозиториев; без `delete` — так реализован ИНВ-8.
17. **Деньги?** `Decimal`, в JSON — строкой `"6000.00"`, чтобы не терять копейки.
18. **Как тестируются сроки?** `Clock`/`FixedClock`, без `freezegun` и «сегодня» в коде.
19. **Идемпотентность?** Повторный платёж за тот же период с той же суммой → 200 и тот же платёж, без дубля.
20. **Права?** `МодульПравДоступа`: `auditor` формирует отчёт, но выгрузка принудительно обезличена (`anonymize=false` → 403 + аудит).
21. **Что не реализовано?** PostgreSQL/ORM, реальные шлюзы, фоновый планировщик, хранение файлов, форматная валидация ИНН/серии.
22. **Что дальше?** PostgreSQL + Alembic (инварианты закрепить индексами), реальные ЕПГУ/СМЭВ/Почта/ФНС, APScheduler/Celery.
23. **Кто что делал?** Лаб. 1–5 — Макеев, лаб. 6 — Малышева; на защите уметь провести трассировку по обеим частям.
24. **Как трассируется операция?** Таблица 3.3 в README лаб. 6 и `operations-mapping.md` лаб. 5: операция → класс → метод → эндпоинт.
25. **Почему FastAPI?** Pydantic-валидация, Swagger для демо, скорость; модель от фреймворка не зависит.
