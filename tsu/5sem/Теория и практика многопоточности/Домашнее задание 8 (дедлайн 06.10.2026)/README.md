## 2. Этапы выполнения

### Этап 1. Входной список адресов

Список берётся из конфигурации `app.hw08.urls` (по умолчанию 20 публичных API) либо формируется
локальным сервером-заглушкой в режиме `local`. Режим задаётся `app.hw08.mode` (`local`, `external`,
`mixed`); список и режим меняются аргументами запуска без правки кода. В локальном режиме сервер
поднимается на **свободном порту** (порт 0 — выбирает ОС), поэтому прогон воспроизводим и не зависит
от внешней сети; фактический порт печатается и попадает в сводку.

### Этап 2. Ручная настройка `ThreadPoolExecutor`

Пул собирается из явных параметров, **без** фабрик `Executors.*`:

| Параметр | Значение по умолчанию | Почему |
|---|---|---|
| `corePoolSize` | 4 | число одновременных запросов в спокойном режиме |
| `maximumPoolSize` | 8 | вдвое больше ядра — запас на пик |
| `queueCapacity` | 8 (ограничена) | при неограниченной очереди максимум недостижим |
| `keepAlive` | 30 с | время жизни простаивающего сверхядерного потока |
| фабрика потоков | `http-worker-<N>` | осмысленные имена для дампа (см. ДЗ 7) |
| обработчик отказа | `CallerRunsPolicy` | задача не теряется, обратный откат по потокам |
| `connectTimeout` / `requestTimeout` | 1000 / 3000 мс | без таймаутов один адрес держит задачу вечно |

**Почему очередь обязательно ограничена.** При неограниченной очереди `ThreadPoolExecutor` набирает
только потоки ядра, кладёт остальные задачи в очередь и до `maximumPoolSize` **не доходит никогда**:
«пул из восьми потоков» молча превращается в «четыре потока + очередь». Ограничение ёмкости — то
единственное, что делает максимум достижимым (проверено тестом `boundedQueueLetsPoolGrow`: с
ограниченной очередью фактический размер превышает ядро, с неограниченной — остаётся на ядре).

**Почему именно `CallerRunsPolicy`.** При переполнении задача выполняется потоком, который её
отправил: она не теряется и не превращается в исключение, требующее обработки в каждом месте отправки.
Побочный эффект — обратный откат по потокам: если источник отправляет быстрее, чем пул успевает,
отправляющий поток сам выполняет работу, и суммарное время прогона растёт. Это честно видно в сводке и
подаётся как плата за гарантию «ни одна задача не потеряна».

### Этап 3. Асинхронная отправка запросов

`java.net.http.HttpClient` (из JDK, без зависимостей) с `sendAsync`; задача пула дожидается результата.
Клиент несёт собственные таймауты соединения и запроса. Задача на каждый адрес подаётся в общий пул —
потоки переиспользуются, не создаются на каждый запрос.

### Этап 4. Сбор результатов

Результат каждого запроса пишется в массив **по индексу адреса**: индекс уникален и принадлежит одному
адресу, поэтому гонки нет без дополнительной синхронизации, а порядок сводки совпадает с порядком
входного списка без сортировки. Ожидание всех результатов — через `CountDownLatch`; по мере завершения
печатается прогресс «выполнено N из M».

### Этап 5. Сводка и остановка пула

Печатаются построчные результаты (адрес, категория, код, время) в порядке списка и агрегаты: счётчики
по категориям, распределение по кодам, минимум/среднее/максимум времени ответа, суммарное время прогона
и сумма времён ответов. Сводка дополнительно сохраняется в файл `target/hw08-summary.txt`. Пул
останавливается обязательно (потоки не демоны): инициация остановки → ожидание с таймаутом → при
превышении принудительное завершение с предупреждением и числом не завершённых задач.

## 4. Классификация исходов: фактические примеры

| Категория | Пример из прогона | Что означает |
|---|---|---|
| `получен ответ` (успешный) | `local/0 → 200, 184.402 мс` | сервер ответил кодом 200 |
| `получен ответ` (неуспешный) | `local/3 → 500, 186.245 мс`; `local/2 → 404`; `local/5 → 503` | сервер ответил, но код неуспешный — это **не** ошибка сети |
| `таймаут` | `local/19 → таймаут, 3000.000 мс` | ответа не было дольше таймаута; время равно границе таймаута |
| `сетевая ошибка` | внешний режим: `https://example.com → соединение не установлено`; `worldtimeapi.org → SSLHandshakeException` | подключиться/разрешить имя/завершить TLS не удалось |
| `отказ в выполнении` | `это-не-url` (в тесте) | адрес непригоден, до сети дело не дошло |

**Ошибка транспорта против ответа сервера.** Ответ `500` означает, что запрос дошёл, сервер его
обработал и вернул код — это состоявшийся обмен, и он попадает в сводку как код `500`. Ошибка
транспорта означает, что обмена не было вовсе (нет соединения, имя не разрешено, истёк таймаут) — у
такой записи **нет** статус-кода, и код для неё не выдумывается (в сводке стоит «—»). Именно поэтому
это разные категории: «20 успешных запросов» может оказаться «20 ответов с кодом 404», а один таймаут в
куче из двадцати — это 95 % успеха, если их смешать.

## 10. Как запустить и сдать

### Запуск

```bash
cd "Теория и практика многопоточности"

# Локальный режим по умолчанию — 20 адресов заглушки, процесс завершается с кодом 0
mvn -pl app spring-boot:run -Dspring-boot.run.arguments=--app.hw=hw08

# Если порт 8081 занят — случайный свободный порт
mvn -pl app spring-boot:run -Dspring-boot.run.arguments="--app.hw=hw08 --server.port=0"

# Внешний режим с публичными API
mvn -pl app spring-boot:run -Dspring-boot.run.arguments="--app.hw=hw08 --app.hw08.mode=external"

# Переопределение настроек пула и списка адресов
mvn -pl app spring-boot:run -Dspring-boot.run.arguments="--app.hw=hw08 --app.hw08.pool.core-size=6 --app.hw08.pool.max-size=12 --app.hw08.pool.queue-capacity=4 --app.hw08.pool.request-timeout-millis=1500"

# Обычный запуск без демонстраций (поднимет Tomcat и будет ждать запросов)
mvn -pl app spring-boot:run
```

Сводка прогона сохраняется в `app/target/hw08-summary.txt`.

### Сдача

1. Скопировать содержимое этого файла в Google Документ или Яндекс Документ.
2. Вложить туда же сводку из `target/hw08-summary.txt` либо исходники/ссылку на репозиторий.
3. **Открыть доступ по ссылке** всем, у кого есть ссылка, — иначе задание не засчитают.
4. В личном кабинете LMS прикрепить ссылку на документ.

Пункт «ссылка прикреплена в ЛМС, доступ открыт» выполняется вручную — автоматизировать его нельзя.

### Примечание о числах и об окружении

Все времена и коды — **фактические**, полученные на этой машине (OpenJDK 21.0.12.1). Во внешнем режиме
числа зависят от внешних сервисов; поэтому режим по умолчанию локальный, а выводы сформулированы как
«на этой машине».

Оговорки:

1. **Стенд сборки.** Проект компилируется под `--release 21`; для сборки и запуска использован JDK 21
   (Temurin) и Maven 3.9.16, развёрнутые локально. Новых зависимостей не добавлено: HTTP-клиент и
   сервер-заглушка — из JDK.
2. **Порт 8081** на этой машине занят сторонним процессом, поэтому контрольные прогоны выполнялись с
   `--server.port=0`; демонстрация от порта веб-контекста не зависит.
3. **Известный нестабильный тест ДЗ 2.** `LifecycleObservationServiceTest.repeatedRunsProduceIdenticalStateSets`
   иногда не успевает застать состояние `WAITING` под суммарной нагрузкой сборки (описано в отчёте ДЗ 5).
   К ДЗ 8 он отношения не имеет; при повторном прогоне сборка зелёная (383 теста).
