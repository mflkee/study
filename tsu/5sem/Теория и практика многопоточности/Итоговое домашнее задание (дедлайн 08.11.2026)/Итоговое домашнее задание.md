## Описание задания

Задание выполняется индивидуально и по вариантам. Перейдите [по ссылке](https://disk.yandex.ru/edit/d/md0FjXlr3zSYIUFscOm8QiPegnqahzm72s0qoIz-cKg6a25pSWRidDhCdw?from_public=1) и узнайте свой номер варианта. В домашнем задании вам будет необходимо разработать полностью функциональное многопоточное веб-приложение, демонстрирующее современные практики конкурентного программирования в контексте реальной задачи сбора и обработки данных.

### Варианты итогового домашнего задания

**Вариант 1.** Разработать краулер контактных данных, который ищет данные об организации.

Пример работы: входные данные — стартовые URL-адреса сайтов компаний, каталогов организаций или бизнес-директорий (например, 2GIS, Яндекс.Справочник, корпоративные сайты). Сервис извлекает все ссылки на странице и собирает следующую открытую информацию: телефоны, Email-адреса, почтовые адреса и т. д.

**Вариант 2.** Парсер цен на товары, который будет собирать заголовки и краткое описание товара.

Пример работы: входная ссылка — на товар. Сервис обходит каждую ссылку, собирает цену, краткое содержание, дату публикации. Может использоваться как агрегатор цен.

**Вариант 3.** Разработать парсер вакансий, который будет собирать информацию о вакансиях с сайтов (hh.ru, SuperJob, Habr Career и т. п.).

Пример работы: входная ссылка — страница вакансии. Сервис собирает: название вакансии, компанию, зарплату, требования, город, дату размещения. Этот сервис может быть полезен для анализа рынка труда или создания собственного агрегатора.

**Вариант 4.** Разработать парсер курсов валют или криптовалют, который будет собирать актуальные курсы валют с финансовых сайтов.

Пример работы: входная ссылка — страница с курсами на ЦБ РФ, CoinMarketCap и т. д. Сервис собирает: название валюты, курс к рублю/доллару, изменение за день. Этот парсер может быть частью приложения для трейдинга или аналитики.

**Вариант 5.** Разработать парсер отзывов, который будет собирать отзывы пользователей с маркетплейсов или специализированных форумов.

Пример работы: входная ссылка — страница товара на AliExpress / Ozon / Отзовик. Сервис собирает текст отзыва, рейтинг, имя автора, дату.

### Общие требования к проекту

Вам необходимо реализовать MVC-приложение на Spring Boot (достаточно бековой части, фронт можете реализовать по своему желанию).

При проверке итоговый проект должен быть минимально настраиваемым со стороны проверяющего проект преподавателя. Проверяющий должен нажать кнопку пуск и без дополнительных настроек проверить логику проекта.

Логику последовательности действий для проверяющего нужно описать в файле `readme.md` (например: запустить проект, выполнить POST-запрос на полный URL (указать по примеру `http://localhost:8080/post`), приложить JSON запроса.

Требования по многопоточности:

- Использовать кастомный `ExecutorService` или `ForkJoinPool`.
- Добавить запуск по расписанию `@Scheduled` или использовать `ScheduledExecutorService`.
- Использовать встроенную базу данных H2. Если не знакомы с JPA — можете использовать просто файлы для хранения информации.
- Сервис должен запускаться, работать и отдавать результаты через эндпоинт получения результатов, например: `/answer`. (параметры пагинации и сортировки добавьте по желанию).
- Для варианта 4 (парсер курса валют) продумайте эндпоинт по ответу на конкретную дату и конкретную валюту (стек валют — например, 5).
- Добавьте извлечение результатов, возможность сортировки по входным параметрам из H2 через `parallelStream()` API.
- Для межсервисного взаимодействия используйте WebFlux, RestTemplate, FeignClient.
- Используйте потокобезопасные структуры данных.
