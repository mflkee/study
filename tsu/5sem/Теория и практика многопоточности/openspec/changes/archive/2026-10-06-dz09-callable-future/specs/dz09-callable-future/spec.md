# Spec Delta

## Purpose

Возможность запускать задачи, возвращающие результат, управлять ими во времени и по результату:
получать `Future`, отменять длительную задачу, одновременно запускать набор задач и собирать их
результаты, выполнять работу периодически и агрегировать данные из источника, который может частично
сбоить.

## ADDED Requirements

### Requirement: Отмена длительной задачи через Future

Система SHALL предоставлять возможность отправить в пул потоков длительную задачу (5–10 секунд),
получить объект `Future` и отменить задачу через `cancel()` по истечении 2–3 секунд. Отменяемая задача
SHALL реагировать на прерывание и прекращать работу, а система SHALL подтверждать отмену наблюдаемым
образом.

#### Scenario: Задача отправлена и Future получен

- **WHEN** длительная задача отправлена в пул потоков
- **THEN** система получает объект `Future`, связанный с этой задачей

#### Scenario: Отмена через 2–3 секунды

- **WHEN** по истечении 2–3 секунд у `Future` вызывается `cancel()`
- **THEN** задача помечается отменённой, её результат недоступен, а запрос результата завершается
  исключением отмены

#### Scenario: Отменённая задача прекращает работу

- **WHEN** задача отменена с прерыванием
- **THEN** выполняющий поток прерывается, задача завершается, не доходя до конца, и не остаётся в
  работе после отмены

#### Scenario: Задача успевает завершиться до отмены

- **WHEN** длительность задачи меньше момента отмены
- **THEN** `Future` возвращает результат, а отмена не изменяет уже завершённую задачу

### Requirement: Одновременный запуск набора задач через invokeAll

Система SHALL формировать набор из 3–5 задач, каждая из которых имитирует работу случайной
длительности (1–3 секунды) и возвращает результат, и SHALL запускать их одновременно через
`invokeAll()`. Результаты SHALL собираться в порядке исходного списка задач.

#### Scenario: Все задачи запускаются одновременно

- **WHEN** набор задач передаётся в `invokeAll()`
- **THEN** задачи выполняются параллельно, и суммарное время набора близко к длительности самой долгой
  задачи, а не к сумме длительностей всех задач

#### Scenario: Результат каждой задачи получен

- **WHEN** `invokeAll()` завершается
- **THEN** у каждой задачи есть свой результат, соответствующий её позиции в исходном списке

#### Scenario: Набор задач не меньше требуемого

- **WHEN** формируется список задач
- **THEN** в нём не меньше трёх задач, каждая возвращает результат

### Requirement: Периодическая фоновая задача через ScheduledExecutorService

Система SHALL создавать `ScheduledExecutorService` и настраивать периодическую задачу, имитирующую
фоновую операцию, которая выполняется многократно с заданным интервалом и подсчитывает число
выполненных циклов.

#### Scenario: Периодическая задача выполняется многократно

- **WHEN** периодическая задача запущена с заданным интервалом и выдерживается несколько интервалов
- **THEN** задача выполняется не менее двух раз, а счётчик циклов растёт

#### Scenario: Остановка периодической задачи

- **WHEN** сервис периодических задач останавливается
- **THEN** новые выполнения не запускаются, а ранее начатое завершается в пределах таймаута

### Requirement: Периодическая агрегация данных с устойчивостью к частичным сбоям

Система SHALL предоставлять сервис, который каждые N секунд получает список идентификаторов
сущностей, для каждой сущности асинхронно запрашивает данные из источника, который может выбрасывать
исключения, и обрабатывает успешные результаты. Сбой одной сущности SHALL NOT прерывать обработку
остальных сущностей и SHALL NOT останавливать сервис.

#### Scenario: Успешный цикл агрегации

- **WHEN** источник данных отвечает по всем идентификаторам
- **THEN** сервис собирает данные по всем сущностям цикла и обрабатывает успешные результаты

#### Scenario: Частичный сбой источника

- **WHEN** источник данных выбрасывает исключение по части идентификаторов
- **THEN** данные по остальным идентификаторам всё равно получены и обработаны, сбойные случаи
  зафиксированы отдельно, а сервис продолжает работу

#### Scenario: Циклы идут периодически

- **WHEN** сервис запущен с периодом N
- **THEN** выполняется несколько циклов, и каждый цикл обрабатывает список идентификаторов
  актуального запроса

#### Scenario: Остановка сервиса

- **WHEN** сервис останавливается
- **THEN** новые циклы не запускаются, а уже начатый цикл завершается в пределах таймаута

### Requirement: Корректное завершение исполнителей

Все созданные исполнители SHALL корректно завершаться по окончании работы: инициация остановки,
ожидание с ограничением по времени и принудительное завершение при превышении. По завершении работы
SHALL не оставаться незавершённых потоков исполнителей.

#### Scenario: Исполнители завершаются

- **WHEN** работа сценария завершена
- **THEN** исполнители переведены в состояние остановки и завершились в пределах таймаута

#### Scenario: Процесс не остаётся жить из-за потоков

- **WHEN** демонстрация завершила вывод
- **THEN** процесс приложения завершается штатно без незавершённых потоков исполнителей

### Requirement: Изолированный запуск и штатное завершение демонстрации

Демонстрация SHALL выполняться только при явном указании при запуске приложения, SHALL печатать
промежуточные результаты каждого этапа и SHALL завершаться штатно. Все сценарии SHALL быть
ограничены по времени.

#### Scenario: Явный запуск демонстрации

- **WHEN** выполняется запуск приложения с указанием демонстрации ДЗ 9
- **THEN** демонстрация выполняет сценарии, печатает результаты и завершает процесс с кодом `0`

#### Scenario: Демонстрация не запрошена

- **WHEN** приложение запускается без указания демонстрации ДЗ 9
- **THEN** демонстрация не выполняется, а приложение поднимает HTTP-контекст и ждёт запросов

#### Scenario: Автоматические проверки не зависают

- **WHEN** выполняется прогон автоматических проверок
- **THEN** он завершается в ограниченное время и не оставляет работающих потоков исполнителей

### Requirement: Отчёт по ДЗ 9

По ДЗ 9 SHALL быть подготовлен отчёт, описывающий особенности каждого этапа задания и промежуточные
результаты, с фактическими значениями и сверкой с чек-листом самопроверки.

#### Scenario: Отчёт описывает этапы

- **WHEN** открывается отчёт ДЗ 9
- **THEN** в нём описан каждый этап задания: отмена через `Future`, набор задач и `invokeAll`,
  периодическая задача, сервис агрегации

#### Scenario: Отчёт содержит промежуточные результаты

- **WHEN** открывается отчёт ДЗ 9
- **THEN** в нём приведены фактические результаты этапов: подтверждение отмены, одновременность
  запуска, число циклов периодической задачи, результаты агрегации

#### Scenario: Отчёт сверён с чек-листом

- **WHEN** отчёт сверяется с чек-листом самопроверки из текста задания
- **THEN** каждый пункт отражён отдельным разделом, а пункт о ссылке отмечен как выполняемый вручную
