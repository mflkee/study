# Proposal

## Why

ДЗ 9 (дедлайн 09.10.2026, тема «Callable и Future») — переход от «задача без результата» (`Runnable`,
ДЗ 8) к задачам, **возвращающим значение** и **управляемым по времени**: `Future`/`FutureTask`,
`invokeAll`, `ScheduledExecutorService` и периодический сервис `PeriodicDataAggregator`. Все предыдущие
ДЗ запускали задачи и лишь наблюдали их; здесь впервые нужно получить результат задачи, отменить её по
таймауту и выполнять работу периодически. Без явного проектного решения по отмене (реагирует ли задача
на прерывание), по одновременности `invokeAll` и по обработке частичных сбоёв в
`PeriodicDataAggregator` задание невыполнимо: отменённая задача может продолжать работу, а один
упавший запрос не должен ронять весь цикл агрегации.

Связь с предыдущими ДЗ: ДЗ 8 дал вручную настроенный `ThreadPoolExecutor` и приёмы сбора результатов;
ДЗ 7 — приёмы диагностики. Здесь пул/исполнители используются как средство, а новыми темами становятся
`Future`, отмена, `invokeAll` и периодические задачи.

## What Changes

- Появляется пакет `ru.tsu.tpm.vacancyparser.hw09.callable` с подпакетами по этапам: `cancel`
  (`Future` и отмена), `batch` (`invokeAll`), `scheduled` (`ScheduledExecutorService`), `aggregator`
  (`PeriodicDataAggregator`); демонстрация — `CallableFutureDemo` в корне пакета.
- **`ExecutorService` и отмена задач:** пул потоков, долгая задача на 5–10 секунд (реализуется
  `Callable`/`FutureTask`), получение `Future`, отмена через `cancel(true)` через 2–3 секунды. Задача
  обязана быть прерываемой (реагировать на прерывание и завершаться), а не «отменяться на бумаге».
- **Список задач и `invokeAll`:** от 3 до 5 `Callable`, каждая имитирует работу случайной длительности
  1–3 секунды и возвращает результат; все запускаются одновременно через `invokeAll(...)`, результаты
  собираются по порядку.
- **`ScheduledExecutorService`:** периодическая задача-имитация фоновой операции («мониторинг
  очереди») через `scheduleAtFixedRate`, счётчик циклов и корректная остановка.
- **`PeriodicDataAggregator`:** каждые N секунд получает список идентификаторов сущностей, для каждой
  асинхронно запрашивает данные из внешнего источника, который **может выбрасывать исключения**;
  успешные результаты обрабатываются, сбойные — фиксируются отдельно, не прерывая цикл и не роняя
  сервис.
- Явно применяется `FutureTask` (это указано в цели задания): один из сценариев оборачивает `Callable`
  в `FutureTask` и показывает отмену именно так; в отчёте это отмечается как покрытие цели сверх
  чек-листа.
- Демонстрация запускается изолированно: `mvn -pl app spring-boot:run -Dspring-boot.run.arguments=--app.hw=hw09`;
  без флага не выполняется. Все сценарии ограничены по времени и завершаются штатно.
- Пишется отчёт `Домашнее задание 9 (дедлайн 09.10.2026)/README.md` с описанием каждого этапа и
  промежуточными результатами.

Чек-лист самопроверки из текста ДЗ 9, под который проектируется изменение:

1. создан пул потоков (`ExecutorService`), в пул отправлена долгая задача на 5–10 секунд;
2. получен объект `Future` для этой задачи;
3. задача отменяется методом `cancel()` через 2–3 секунды;
4. создан список из 3–5 задач, имитирующих работу случайной длительности и возвращающих результат;
5. все задачи запускаются одновременно через `invokeAll()`;
6. создан `ScheduledExecutorService`;
7. настроена периодическая задача-имитация фоновой операции;
8. реализован сервис `PeriodicDataAggregator` (список идентификаторов, асинхронный запрос с возможным
   исключением, обработка успешных результатов);
9. этапы описаны в отчёте, ссылка на отчёт прикреплена в ЛМС — **пункт закрывается вручную студентом**.

## Capabilities

### New Capabilities
- `dz09-callable-future`: управление задачами, возвращающими результат: получение `Future`,
  прерываемая отмена, одновременный запуск набора задач через `invokeAll`, периодические задачи через
  `ScheduledExecutorService` и устойчивая к частичным сбоям периодическая агрегация данных.

### Modified Capabilities
_Пусто — изменение вводит новую capability и не меняет требования существующих спецификаций: общий
механизм запуска демо из `openspec/config.yaml` сохраняется, пакеты ДЗ 1–8 не изменяются._

## Impact

- **Новый код**: `app/src/main/java/ru/tsu/tpm/vacancyparser/hw09/callable/**` (отмена, `invokeAll`,
  периодическая задача, агрегатор, демо), `app/src/test/java/**` (тесты отмены, одновременности,
  периодики и агрегатора).
- **Новые зависимости**: нет — используются только средства JDK (`java.util.concurrent`).
- **Изменения существующего кода**: нет; `hw01`–`hw08` и `common` не меняются.
- **Отчёт**: `Домашнее задание 9 (дедлайн 09.10.2026)/README.md`.
