Мы используем MasterSCADA 4D DT 2.0 в учебном процессе (МКАИР) и тестируем бета-сборку 2.0.4 RC.
За несколько дней работы собрали 4 воспроизводимых дефекта — ниже шаги, факты и выдержки из журналов.
Готовы прислать дополнительные данные и воспроизвести на созвоне.

Версия среды разработки: 1.3.10.33235 (2.0.4_RC_20260622.1), установка
«/opt/MasterSCADA 4D RC/MasterSCADA4D_2.0_RC» (Linux, пакет .deb от вендора).
Проект: учебный «Быстрый старт»; хранилище — PostgreSQL (проект открывается, RequestAllItems ok,
тиражирование объектов и привязка к Modbus работают).

Проверяли на двух системах, чтобы отделить дефекты сборки от особенностей окружения:
  A) Astra Linux SE 1.8.6 в KVM/QEMU (virtio-vga, Spice, 6 vCPU / 8 ГБ) — официально поддерживаемая ОС;
  B) Arch Linux + niri (Wayland), среда запускается в режиме X11 (через XWayland).

------------------------------------------------------------------------
Дефект 1. Среда разработки самопроизвольно завершается через 1,5–4 минуты
          (Astra Linux SE 1.8.6, QEMU/KVM, virtio-vga, Spice)

Шаги: запустить среду в графической сессии Astra (из меню), открыть проект, далее работать в
редакторе или ничего не делать.
Факт: через 1,5–4 минуты приложение завершается само. В stdout:

  ERROR:zygote_communication_linux.cc(290)] Failed to send GetTerminationStatus message to zygote
  ERROR:network_service_instance_impl.cc(601)] Network service crashed, restarting service.
  ERROR:gpu_process_host.cc(987)] GPU process launch failed: error_code=1002
  FATAL:gpu_data_manager_impl_private.cc(448)] GPU process isn't usable. Goodbye.

Также в stdout: libva error: /usr/lib/x86_64-linux-gnu/dri/virtio_gpu_drv_video.so init failed
Права chrome-sandbox выставлены как 4755 root:root (иначе среда не стартует вовсе).

Что пробовали:
  - --disable-gpu — падение сохраняется (те же сообщения);
  - --no-sandbox --disable-gpu — время жизни увеличивается до ~4 минут, затем падение повторяется;
  - запуск из сессии и по SSH, до и после перезагрузки виртуальной машины — результат повторяется.

Ожидаемо: среда работает стабильно в официально поддерживаемой ОС.
Замечание: на второй системе (Arch + niri) среда не падает, но там воспроизводятся дефекты 2 и 3,
то есть причина, похоже, специфична для виртуализации virtio-vga.

Дефект 2. Размер окна не сохраняется в модели (теряется после сохранения/переоткрытия проекта)

Шаги (воспроизводится на обеих системах — A и B):
  1) открыть окно: Библиотеки -> Локальная -> Объекты -> Насос 1 -> Ресурсы -> Окна -> Окно 1
     (Id элемента 42089; для других окон аналогично);
  2) «Свойства -> Расположение -> Ширина = 300, Высота = 200», Enter;
  3) «Проект -> Сохранить» (Ctrl+S), затем закрыть и снова открыть проект.
Факт: значения не сохраняются. В хранилище (PostgreSQL) у окон вообще отсутствуют свойства
Designer.Layout.Width/Height — у окон есть только SiblingIndex и Designer.Layer.SnapToGrid.
Для сравнения: у элементов окна размеры в модели есть (например, Designer.Layout.Height = 60).
Перетаскивание рамки окна мышью визуально показывает изменение размера (пунктирная рамка и
размерные линии — 160/190), но в модель ничего не пишется ни после отпускания мыши, ни после
сохранения.
Ожидаемо: заданный размер окна сохраняется в проекте так же, как сохраняются размеры элементов.

------------------------------------------------------------------------
Дефект 3. Ctrl+X / Ctrl+V теряет размеры элементов

Шаги: выделить элемент окна -> Ctrl+X -> открыть другое окно -> Ctrl+V -> «Проект -> Сохранить».
Факт: у перенесённых элементов сохраняются координаты (Designer.Layout.X/Y), но исчезают размеры
(Designer.Layout.Width/Height). В нашем проекте после такого переноса у кнопок (item 49303, 49308)
есть X/Y, но нет Width/Height — на мнемосхеме они отображаются некорректно.
Ожидаемо: перенос элемента не изменяет его геометрию.
