# Заявка 2. Размер окна не сохраняется в проекте

> Черновик для HelpDesk. Продукт: **MasterSCADA 4D**, галочка **«БЕТА-ТЕСТ MS4D DT2.0»**, тип — Ошибка.

**Тема:**

```
DT – Linux – мнемосхемы – размер окна не сохраняется в проект – у окна нет Designer.Layout.Width/Height
```

**Версия ПО:** `1.3.10.33235 (2.0.4_RC_20260622.1)`.
**ОС (основной стенд):** `Astra Linux Special Edition 1.8.6` («Воронеж», KVM/QEMU) — воспроизводим
и снимаем материалы здесь же. Дополнительно дефект наблюдался на втором стенде
(`Arch Linux + niri`, среда как X11-клиент через XWayland), но это неподдерживаемая конфигурация —
в заявке упоминаем только для сведения.
**Хранилище:** PostgreSQL 16, проект «Быстрый старт» (создан и открывается штатно, `RequestAllItems ok`).

**Описание задачи.** Верстаем окно мнемосхемы: задаём окну размер через панель свойств. Ожидаем,
что после сохранения проекта размер сохранится, как это происходит у элементов окна.

**Шаги воспроизведения.**

1. Открыть проект «Быстрый старт».
2. Открыть окно: `Библиотеки → Локальная → Объекты → Насос 1 → Ресурсы → Окна → Окно 1`
   (Id элемента **42089**; для других окон проекта — аналогично).
3. `Свойства → Расположение → Ширина = 300, Высота = 200`, нажать Enter.
4. Для контраста: задать `Параметры → Ширина → Начальное значение = 150` (это значение сохраняется),
   затем `Проект → Сохранить` (Ctrl+S), закрыть проект, снова открыть проект.
5. Открыть то же окно и посмотреть `Свойства → Расположение` (пусто) и `Параметры` (150).

**Ожидаемый результат.** Ширина/высота окна сохраняются в проекте (в хранилище появляются
`Designer.Layout.Width` / `Designer.Layout.Height`), значения видны после переоткрытия проекта.

**Фактический результат.** Значения не сохраняются — ни введённые в панели свойств, ни полученные
перетаскиванием рамки окна мышью (визуально размер меняется: видна пунктирная рамка и размерные
линии 160/190, но в модель ничего не пишется ни после отпускания мыши, ни после сохранения).

**Свежий прогон в Astra 2026-10-16 (окно 42089 «Окно 1» типа «Насос 1»), снимки модели до/после:**

| Что делали | Операции в журнале среды | Записи в модель |
|---|---|---|
| тянули рамку **окна** мышью (9 попыток) | 9 операций «Трансформация элемента: `…Окна.Окно 1` (Id=42089 Type=ViewDeclarationInObject)», trans 510–518 | **0 записей** (у окна 42089 в модели только `SiblingIndex`) |
| тянули рамку **элемента** «Насос горизонт 1» (Id=42124) | 4 операции, trans 519–522 | размеры ушли: `Width` 200 → 240, `Height` 200 → 220 |
| меняли «**Параметры** окна» (Ширина/Высота → Начальное значение) | trans 510–518 | значения пишутся (в модели 250 и 230) |

Отдельно зафиксирован **третий симптом**: при перетаскивании рамки редактирование визуально
«застревает» — на холсте остаются размерные линии (в кадре 350×250), а в модель это значение не
уходит (в модели 240×220). То есть интерфейс показывает размер, которого в проекте нет.

Итого дефект воспроизводится **на данных**: у окна размер не сохраняется никогда (ни мышью, ни через
«Расположение»), а у элемента сохраняется, но операция изменения размера может «застрять».

**Что проверяли в хранилище PostgreSQL (учебный проект «Быстрый старт», БД `ms4d_project_2`).**
У окна **42089** в сохранённом состоянии есть ровно два свойства:

```
 props_num | SiblingIndex | 0.000000000
 props_str | DisplayName  | Окно 1
```

Свойств `Designer.Layout.Width`/`Designer.Layout.Height` у окна нет вообще, и — важнее — их **нет
ни в одной операции журнала** проекта (таблицы `trans_log` / `trans_props_num`; на момент снятия
выписки в журнале было 487 операций): среда даже не пытается записать размер окна — запрос ниже
возвращает 0 строк:

```sql
SELECT count(*) FROM trans_props_num
WHERE item_id = 42089 AND type_id IN (751 /*Designer.Layout.Width*/, 752 /*Designer.Layout.Height*/);
--  count = 0
```

Для сравнения — у элементов окна размеры в модели **есть** и ненулевые: `Designer.Layout.Width`
заполнен у 128 элементов проекта, `Designer.Layout.Height` — у 95 (например, item 13959: Width = 5).

**Вложения.**

операции над окном 42089 в журнале есть, а записей в модель нет, тогда как правки элемента 42124 и
«Начальных значений» параметров окна в модель пишутся. Инструмент и методика — в `../repro-protocol.md`.
📎 `ErrorReports.zip` — «Сервис → Отчет об ошибках», снятый **внутри гостя Astra** (внутри журнал
среды за день **и архив самого проекта** «Быстрый старт» — в нём видно отсутствие свойств у окна).
📎 `sql-project-state.sql` + `sql-project-state.out` — воспроизводимая выписка из хранилища
(разделы 2–3: все свойства окна 42089 и отсутствие `Designer.Layout.Width/Height` в истории;
раздел 12: история «Начальных значений» параметров окна для контраста;
раздел 13: для контроля — правка размера элемента, которая в модель пишется).
📎 `sql-snimok-2026-10-16-polnaya-vypiska.out` — снимок полного состояния на 2026-10-16 06:16 UTC
(до того, как часть элементов была удалена при дальнейших опытах).
📎 Видео `02-okno-razmer.mp4` (~1,5 мин) — задаём 300×200 → Ctrl+S → переоткрываем проект →
размер сброшен; для контраста правка «Параметров» сохраняется.
📎 Скриншоты «Свойства → Расположение» и «Параметры → Начальное значение» до и после переоткрытия проекта.

**Замечание к смежной области — в среде есть два разных «Ширина/Высота» у окна, и ведут они себя по-разному.**

| Где задаётся | Что происходит (по данным хранилища) |
|---|---|
| «Свойства → **Расположение** → Ширина/Высота» окна | **не пишется в модель вообще**: у окна 42089 нет ни одной операции с `Designer.Layout.Width/Height` за всю историю проекта (см. §3 выше) |
| «**Параметры**» окна → `Ширина`/`Высота` → **Начальное значение** (свойство `MasterSCADA.Var.InitialValue` элементов 42094/42095) | **сохраняется штатно**: в сессиях Astra значения правились 1920 → пусто → 120 → 150 (операции журнала 469–472, 491–492) и лежат в хранилище |

Пример истории по параметрам окна (всё из Astra, время UTC):

```
 trans_id | commit_time              | item  | chto      | old  | new
      469 | 2026-10-13 08:26:18.063  | 42094 | удалено   | 1920 |
      471 | 2026-10-13 08:26:33.354  | 42094 | добавлено |      | 120
      491 | 2026-10-16 07:01:58.792  | 42094 | изменено  | 120  | 150
```

То есть вопрос к вендору формулируется точно: **каким свойством должен сохраняться размер окна,
задаваемый в «Расположении», и почему запись в модель не выполняется** (при том, что правка
размеров *элементов* в модель пишется — например операция 478: `Designer.Layout.Width` 120 → 130).
