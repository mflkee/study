# Заявка 3. Ctrl+X / Ctrl+V обнуляет размеры элементов

> Черновик для HelpDesk. Продукт: **MasterSCADA 4D**, галочка **«БЕТА-ТЕСТ MS4D DT2.0»**, тип — Ошибка.

**Тема:**

```
DT – Linux – мнемосхемы – Ctrl+X/Ctrl+V обнуляет размеры элементов – Designer.Layout.Width/Height = 0, координаты сохраняются
```

**Версия ПО:** `1.3.10.33235 (2.0.4_RC_20260622.1)`.
**ОС (основной стенд):** `Astra Linux Special Edition 1.8.6` («Воронеж», KVM/QEMU) — воспроизводим и
снимаем материалы здесь же. Дополнительно дефект наблюдался на втором стенде
(`Arch Linux + niri`, XWayland) — неподдерживаемая конфигурация, упоминаем для сведения.
**Хранилище:** PostgreSQL 16, проект «Быстрый старт» (`ms4d_project_2`).

**Важно:** часть операций, приведённых ниже, выполнена **в сессии Astra**
(`sessions.host_name = 'astra-vm'`, 2026-10-13), то есть дефект воспроизводится на штатной ОС.

**Описание задачи.** Переносим элементы оформления между окнами привычным способом — `Ctrl+X`
в одном окне, `Ctrl+V` в другом. Ожидаем, что перенос не меняет геометрию элемента.

**Шаги воспроизведения.**

1. Открыть окно `Библиотеки → Локальная → Объекты → Насос 1 → Ресурсы → Окна → Окно управления`.
2. Выделить элемент на мнемосхеме (у нас — «Кнопка 1», Id **49303**, и «Кнопка 2», Id **49308**).
3. `Ctrl+X`, перейти в другое окно, `Ctrl+V`.
4. `Проект → Сохранить` (Ctrl+S), закрыть и открыть проект, посмотреть `Свойства → Расположение`.

**Ожидаемый результат.** После переноса у элемента сохраняются и координаты, и размеры
(`Designer.Layout.X/Y/Width/Height`); на мнемосхеме элемент выглядит так же, как до переноса.

**Фактический результат.** У перенесённых элементов теряются размеры: в сохранённом состоянии
у «Кнопки 1» (49303) и «Кнопки 2» (49308) координаты и размеры обнулены, на мнемосхеме элементы
отображаются некорректно:

```
 item_id |           name            |    value
---------+---------------------------+--------------
   49303 | Designer.Element.TabIndex | 8.000000000
   49303 | Designer.Layout.Height    | 0.000000000
   49303 | Designer.Layout.Width     | 0.000000000
   49303 | Designer.Layout.X         | 0.000000000
   49303 | Designer.Layout.Y         | 0.000000000
   49303 | Designer.Layout.Z         | 12.000000000
```

**Что показывает журнал операций среды (таблицы `trans_log` / `trans_props_num` в хранилище).**

1. **Вставка из буфера** (trans 298, `2026-10-12 15:19:37.781`) —
   *«Вставить 'Овал 1, Кнопка 1, Кнопка 2' из буфера в '…Насос 1.Ресурсы.Окна.Окно управления.Схема'»*:
   для обеих кнопок записаны только `Designer.Layout.X` и `Designer.Layout.Y`
   (**ни `Width`, ни `Height` в операции вставки нет**), плюс, по данным операции, `Z`, `TabIndex`,
   `SiblingIndex`, `DisplayName`.
2. Позже размеры у кнопок появились (trans 299: `Width = 80`, `Height = 20`).
3. **Операция «Откат»** (trans 308, `2026-10-12 23:56:16.425`) — **удалила** свойства размеров
   у обеих кнопок (`action_type = 2`, удалено): `Designer.Layout.Width` (было 80) и
   `Designer.Layout.Height` (было 20).
4. Далее размеры записались повторно как нулевые — **уже в сессии Astra** (trans 475/476,
   `2026-10-13 09:34 UTC`, `sessions.host_name = 'astra-vm'`: `Width = 0`, `Height = 20 → 0`).

Итог: у элементов координаты и размеры обнулены, то есть перенос геометрию не сохраняет.

**Наблюдение, которое просим проверить (возможно, это и есть корневая причина).**
В журнале операции, которые фактически меняют свойства элементов **49303/49308**, названы как
изменение параметров окна:

```
 299 | Вставить…             | …Окно управления.Параметры.Ширина. Начальное значение = 100, Предыдущее = 1920
 300 |                       | …Окно управления.Параметры.Высота. Начальное значение = 100, Предыдущее = 1080
 307 | Откат …Параметры.Высота …
 308 | Откат …Параметры.Ширина …
```

Похоже, что действие над элементом мнемосхемы записывается в модель **как изменение свойства
другого элемента/параметра окна**. Если так, то же объясняет и дефект по размеру окна
(отдельная заявка).
