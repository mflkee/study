# Точное воспроизведение: как фиксируем, что дефект «есть»

Воспроизводить «на глаз» бесполезно: у этих дефектов симптом визуальный (рамка, пустой квадрат
вместо элемента), а доказательство — **что среда записала в модель**. Поэтому каждый прогон делаем
парой снимков: до операции и после неё.

```bash
cd ~/projects/study/masterscada/docs/reference/helpdesk-2026-10/evidence

./checkpoint.sh before      # снимок №1 (состояние + граница журнала)
#  ... ровно ОДНА операция в среде внутри Astra, затем Ctrl+S  ...
./checkpoint.sh after       # снимок №2

diff -u checkpoints/before-*.txt checkpoints/after-*.txt | less
```

Дифф и есть доказательство: в нём видно, появилась ли в модели запись (`trans_props_num/str`),
какая именно и с какими значениями, и как выглядит сохранённое состояние после операции.
Снимки складываются в `evidence/checkpoints/` (в git не коммитятся), нужный дифф прикладываем к заявке.

> Важно: снимок «after» делать **после `Ctrl+S`**. До сохранения изменения лежат в `trans_props_*`
> (журнал) и в сохранённое состояние (`props_*`) ещё не попали.

## Сценарий S1 — изменение размера окна МЫШЬЮ (дефект 2)

| Шаг | Действие |
|---|---|
| 1 | `./checkpoint.sh before` |
| 2 | Открыть `Библиотеки → Локальная → Объекты → Насос 1 → Ресурсы → Окна → Окно 1` (Id 42089) |
| 3 | Потянуть рамку окна за маркер (видно пунктирную рамку и размерные линии), отпустить |
| 4 | `Ctrl+S` |
| 5 | `./checkpoint.sh after` |

**Дефект воспроизведён, если в диффе:** в разделе 4 (журнал) есть операция про окно 42089
(«Трансформация»/«Перетаскивание»/«Изменение размеров»), но в разделе 4b **нет ни одной записи**
`Designer.Layout.Width`(751)/`Designer.Layout.Height`(752) для 42089, и в разделе 1/3 геометрия окна
не появилась. То есть операция зафиксирована, а размеров в модели нет.
**Ожидаемо:** значения 751/752 у окна появляются/меняются.

## Сценарий S2 — размер окна через «Свойства → Расположение» (дефект 2, вторая грань)

| Шаг | Действие |
|---|---|
| 1 | `./checkpoint.sh before` |
| 2 | Окно 42089 → `Свойства → Расположение` → `Ширина = 300`, `Высота = 200`, Enter |
| 3 | `Ctrl+S` |
| 4 | `./checkpoint.sh after` |

**Дефект воспроизведён, если:** в разделе 4b **нет** записей 751/752 для 42089 (значение принято
интерфейсом, но в модель не ушло). Отдельно сравнить с контрастом: `Параметры → Ширина → Начальное
значение` — эта правка **пишется** (`MasterSCADA.Var.InitialValue`, раздел 4c), то есть механизм
записи в модель в этой сборке работает.

## Сценарий S3 — `Ctrl+X` / `Ctrl+V` между окнами (дефект 3)

| Шаг | Действие |
|---|---|
| 1 | `./checkpoint.sh before` |
| 2 | В окне с элементом (например, «Окно 1») выделить элемент **с видимым размером**, посмотреть его `Расположение` (X, Y, Ширина, Высота) — снять скриншот |
| 3 | `Ctrl+X` → перейти в другое окно → `Ctrl+V` |
| 4 | `Ctrl+S` |
| 5 | `./checkpoint.sh after` |

**Дефект воспроизведён, если:** в дифе у нового элемента в разделе 1 стоит `WxH = 0x0` (или `-x-`),
а в разделе 4b операция вставки содержит записи `Designer.Layout.X/Y/Z/TabIndex/SiblingIndex`,
но **не содержит** 751/752 — размеры при переносе не переносятся.
**Ожидаемо:** у скопированного элемента `Ширина`/`Высота` такие же, как у исходного.

## Сценарий S4 — перенос объекта/окна НА МНЕМОСХЕМУ (третий симптом)

| Шаг | Действие |
|---|---|
| 1 | `./checkpoint.sh before` |
| 2 | Открыть `Объекты → Насосная станция → Ресурсы → Окна → Мнемосхема` (Id 49150) |
| 3 | Перетащить объект/окно из дерева на холст мнемосхемы (вставляется элемент `ViewUsage`) |
| 4 | `Ctrl+S` |
| 5 | `./checkpoint.sh after` |

**Что смотрим:** в разделе 1 у вставленного элемента (тип 573/`ViewUsage`, в дереве он идёт ребёнком
мнемосхемы) — есть ли у него **собственные** 751/752. Ранее зафиксировано (`course/PROGRESS.md`,
2026-10-12): у вставленного `50089 «Окно 1»` координаты (0,0) и своих `Ширина`/`Высота` нет — размер
элемента задаётся размером окна, из-за чего объект «на весь экран» и уменьшить его в свойствах нечем.
Это уже другой дефект, чем S1/S3, и в заявке его надо описывать отдельно (как «размер вставленного
на мнемосхему элемента не хранится в модели»).
