# Протокол: всё воспроизводим и снимаем в Astra (официально поддерживаемая ОС)

Решение: **все четыре дефекта показываем только на Astra Linux SE 1.8.6** (в KVM). Arch + niri —
неподдерживаемая вендором конфигурация, на неё легко получить ответ «проверяйте на штатной ОС».
Arch упоминаем в текстах заявок одной строкой как второй стенд, без вложений оттуда.

Работаем **внутри гостя**, в окне `virt-viewer` на хосте. Хост — только для БД, записи видео и выписок.

### 0.3. Запись окна VM (на хосте, niri)

Свой скрипт `screenrec-toggle.sh` удалён 2026-10-16 — пишем оверлеем **`gsr-ui`** (`Alt+Z`, источник
**portal**, окно выбирать в разделе «Окна»/«Windows») либо виджетом **«Screen Recorder»** в баре Noctalia
(левый клик — старт/стоп). Оба поднимают свой `gpu-screen-recorder` — **одновременно не запускать**.
Повторная запись того же окна без диалога — через `restorePortalSession` (restore-token в
`~/.config/gpu-screen-recorder/`). Для биндов: `gsr-ui-cli toggle-record-window|toggle-show|status`.

**Грабли (разобраны 2026-10-16):** gsr просит у портала три типа источника, а niri умеет только
монитор и окно, поэтому пункт **«Virtual Monitor» выбирать нельзя** — Start упадёт с
`Unknown method 'RecordVirtual'`. Если захват окна не работает вообще — демон gsr-ui поднялся до
установки/смены портала: `systemctl --user restart "app-gpu\x2dscreen\x2drecorder\x2dui@autostart.service"`.

Проверка, что запись пошла: в логе gsr есть `pipewire negotiation finished`, размер кадра = размер окна
(у нас 1932×1058). Файлы: `~/Videos/record_<дата>_<время>.mp4` (у плагина Noctalia — своя папка).
Ролик в заявку — до 3–4 минут; длинный прогон обрезаем: `ffmpeg -ss 00:00:20 -t 90 -i in.mp4 -c copy out.mp4`.
Fallback, если портал капризничает: развернуть `virt-viewer` на весь экран и писать монитор
(`gsr-ui-cli toggle-record`). Подробности и раскадровка — в [`video-scenario.md`](video-scenario.md).

## 1. Дефект 1 — среда сама завершается (снимаем первым: он самый «дорогой»)

1. Запись: `Alt+Z` → источник portal → окно virt-viewer → Start (или `gsr-ui-cli toggle-record-window`).
2. В госте: меню «Разработка» → MasterSCADA 4D 2.0 RC → проверить в заголовке версию
   `1.3.10.33235 (2.0.4_RC_20260622.1)`.
3. Открыть проект «Быстрый старт» (подключение к БД `192.168.122.1:15444`) — видно, что проект открылся.
4. Открыть окно `Насос 1 → Ресурсы → Окна → Окно 1`, немного подёргать элементы (доказать активность).
5. **Ничего не нажимать** и ждать падения. Засечь время от старта среды до падения.
6. После падения — снова запустить среду и снять **в госте**: `Сервис → Отчет об ошибках`
   (это `ErrorReports.zip` для заявки 1).

**Снимаем:** видео (`01-astra-crash.mp4`), скриншот терминала/вывода с `GPU process isn't usable. Goodbye`,
скриншот настроек VM (virtio-vga + Spice), `ErrorReports.zip` **из гостя**, `sys_log` за этот день
из `~/.config/MPSSoft/MasterSCADA4D_DT_2.0_RC/sys_log/`.

**На хосте:** `virsh -c qemu:///system dumpxml ms4d-astra > .../libvirt-ms4d-astra.xml`.

## 2. Дефект 2 — размер окна не сохраняется

Проверяем сразу **два места**, где в среде задаётся «ширина/высота» окна, — это и есть суть дефекта:

| Где | Что происходит (по данным хранилища) |
|---|---|
| «Параметры» окна → `Ширина`/`Высота` → **Начальное значение** (item 42094/42095, свойство `MasterSCADA.Var.InitialValue`) | **сохраняется**: в Astra правили 1920→пусто→120 (13.10) и 120→150 (16.10) |
| «Свойства → **Расположение** → Ширина/Высота» окна (`Designer.Layout.Width/Height` = 751/752) | **не пишется вообще**: у окна 42089 нет ни одной записи в модели и ни одной операции за всю историю проекта |

1. Запись: `gsr-ui-cli toggle-record-window` (окно VM уже в restore-token).
2. Открыть окно `Библиотеки → Локальная → Объекты → Насос 1 → Ресурсы → Окна → Окно 1` (Id 42089).
3. «Свойства → Расположение»: ввести `Ширина = 300`, `Высота = 200`, Enter. Показать, что рамка окна
   не меняется; потянуть рамку мышью (появляются размерные линии, размер «отскакивает»).
4. Для сравнения тут же: «Параметры → Ширина → Начальное значение = 150» → Ctrl+S → значение сохраняется.
5. `Проект → Сохранить` (Ctrl+S), закрыть проект, открыть заново, снова открыть окно и «Расположение» — пусто.

**Снимаем:** видео (`02-okno-razmer.mp4`), скриншоты «Расположение» до/после переоткрытия,
скриншот «Параметры → Начальное значение» (для контраста), `Сервис → Отчет об ошибках` из гостя.

**На хосте (сразу после Ctrl+S):**

```bash
cd ~/projects/study/masterscada
export PGPASSWORD=course
psql -h 127.0.0.1 -p 15444 -U course -d ms4d_project_2 -f docs/reference/helpdesk-2026-10/evidence/sql-project-state.sql
```
Смотреть разделы 2, 3 (свойства окна 42089) и 12 (история начальных значений параметров).

## 3. Дефект 3 — Ctrl+X/Ctrl+V обнуляет размеры

Прежние элементы удалены в сессии 16, поэтому создаём **чистые** для прогона:

1. Запись: `gsr-ui-cli toggle-record-window` (окно VM уже в restore-token).
2. Открыть любое окно со элементами (например, «Окно 1»), выделить элемент с видимым размером,
   зафиксировать в кадре «Свойства → Расположение» (X, Y, Ширина, Высота).
3. `Ctrl+X` → перейти в другое окно → `Ctrl+V`. Показать, что элемент вставился без размеров.
4. Открыть его свойства: `Ширина = 0`, `Высота = 0`.
5. `Проект → Сохранить`, закрыть и открыть проект — размеры по-прежнему нулевые.

**Снимаем:** видео (`03-ctrl-x-v.mp4`), скриншоты свойств до/после, `Сервис → Отчет об ошибках` из гостя.

**На хосте:** тот же SQL-скрипт; смотреть разделы 5, 6 (сохранённые размеры и история операций).

## 4. Дефект 4 — при экспорте вызывается `systeminfo`

1. Видео не нужно.
2. В госте: `Проект → Экспорт проекта` (SaveCompressed).
3. Показать, что файл создался, и что в журнале среды есть ошибка:
   `~/.config/MPSSoft/MasterSCADA4D_DT_2.0_RC/sys_log/<дата>.log` → строки `System.ComponentModel.Win32Exception (2)` и `ExportProject SaveCompressed`.

**Снимаем:** скриншот лога, `Сервис → Отчет об ошибках` из гостя, сам `sys_log/<дата>.log`.
