Это **боевой проект MasterSCADA с действующего объекта СИКН**, взятый как учебный. Пользователь
находится на объекте, где он крутится.

## Рантайм-БД (PostgreSQL)

`База данных.sql` создаёт схему `public`, владелец `arm` — это **БД рантайма/отчётов** СИКН
(данные пишет среда исполнения, не среда разработки):

| Таблица | Назначение (по имени) |
|---|---|
| `reports` / `reports_common` | сформированные отчёты (периодические) |
| `reports_act` | акты |
| `reports_passport` | паспорт качества нефти |
| `reports_control` / `_recs` / `_flow` / `_flow_recs` | контроль/учёт по линиям и потокам |
| `reports_proof_flow` / `_recs` | поверка/проливка (proof) |

То есть предметная модель — **метрия СИКН**: масса брутто/нетто, по линиям, акты, паспорта, поверка.

## Как открыть/изучить это в нашем стенде

1. Установлена среда разработки **MasterSCADA 4D DT 2.0** (см. `../../docs/reference/ustanovka-arch-niri.md`).
2. Поднять PostgreSQL-стенд (`../../course/00-orientation/infra/docker-compose.yml`, порт `15444`).
3. В DT 2.0 воспользоваться **импортом/миграцией проекта из 1.3.x** (продукт это заявляет;
   конкретный диалог — `UNVERIFIED`, сверить со справкой: раздел «Порядок перехода на новую версию»).
4. После конвертации проект встанет на хранение в **PostgreSQL**, и его можно смотреть/собирать в 2.0.

> Если миграция в 2.0 не пойдёт — потребуется среда разработки **MasterSCADA 4D 1.3.x** и **Firebird 2.5**
> (для прямого открытия `.fdb`). Это отдельная ветка, фиксируем как `UNVERIFIED`.
