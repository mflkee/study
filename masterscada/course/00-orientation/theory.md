Правила самостоятельного обучения:

1. **Примеры запускать, а не читать.** Проект, который не открыли в редакторе, — не пройден.
2. **Упражнения делать самому.** В `solutions/` заглядывать после того, как получилось (или когда
   застрял — и тогда честно переделать).
3. **Сверяться со справкой вендора**, а не с памятью: интерфейс 2.0 отличается от 1.3.x.
4. **Лабы «сломай и почини» — обязательны.** Это способ узнать, как система падает, до прода.
5. **Отмечать прогресс** в [`../PROGRESS.md`](../PROGRESS.md) после каждого модуля.

## Что такое MasterSCADA 4D

Российская SCADA-платформа (ИЭК ДИДЖИТАЛ / МПС Софт) для АСУ ТП: сбор данных с оборудования, логика,
визуализация, архивы, тревоги, отчёты. Проект разрабатывается в **среде разработки** (DT), а
исполняется на **среде исполнения** (RT) — на ПК, сервере или контроллере. Историю и проекты
хранит СУБД; в 2.0 это **PostgreSQL**.

Ключевые сущности: **узел** (машина исполнения), **объект** (устройство/агрегат), **параметр/тег**
(значение с типом и шкалой), **программа** (логика FBD/ST), **окно** (мнемосхема), **канал** (обмен
по протоколу), **архив** (история), **сообщение** (тревога).

## Поддерживаемые ОС: почему список разный

| Продукт | Официально поддерживается |
|---|---|
| **DT 2.0** (редактор) | Windows 10/11 x64; **Astra Linux SE 1.7x / 1.8x** |
| **RT** (исполнение) | Windows 10+; **Linux**: Astra, Debian 11, ALT Linux 8.x, РЕД ОС (ядро ≥ 3.18, x86/x64/arm/arm64) |

Читается так: **разработка** — узкий список (редактор — тяжёлое GUI-приложение), **исполнение** —
широкий (ядру нужен только Linux). Отсюда практическое правило: если машина «не в списке» для DT,
это ограничение *редактора*, и оно решается либо поддерживаемой ОС, либо (для учёбы) тем, что
редактор запускают вне поддержки — как в конспекте
[`../../docs/reference/ustanovka-arch-niri.md`](../../docs/reference/ustanovka-arch-niri.md).

## Архитектура: из чего состоит запущенная система

| Слой | Технология | Где смотреть |
|---|---|---|
| UI/редактор | Electron 28 (Chromium 120) | процессы `MasterSCADA4D_2.0 … --type=renderer` |
| Ядро проекта | .NET 8, self-contained | процесс `resources/MasterSCADA4D_Server/MasterSCADA4D_Server --server-startup-port=…` |
| Драйверы/плагины | C++/Boost, нативные `.so` | `…/Config/MasterPLC/linux/*.so` |
| Хранилище проектов | PostgreSQL ≥ 10 | внешний сервер; параметры — в `IdeSettings.json` |
| Среда исполнения (RT) | .NET/C++ ядро | отдельный процесс/служба; в DT 2.0.4 RT **в комплекте** |

Важно, что DT, RT и БД — **не один монолит**: можно обновить одно, не трогая другое; можно держать
БД отдельным сервером; редактор и RT могут стоять на разных машинах.

> Нумерация версий сбивает с толку: редактор — 2.0.4, а ядро/RT — 1.3.x (линейка RT). В логе старта
> так и пишется: `Start application 1.3.10.33235(2.0.4_RC_20260622.1)`. Это норма.

## Где что хранится (шпаргалка)

| Данные | Где | Переживает удаление пакета? |
|---|---|---|
| Программы/настройки редактора (файлы приложения) | `/opt/MasterSCADA 4D 2.0/` | нет |
| Данные UI: кэш, cookies, single-instance lock | `~/.config/MasterSCADA 4D 2.0/` | да |
| Настройки IDE + логи | `~/.config/MPSSoft/MasterSCADA4D_DT_2.0/` (`IdeSettings.json`, `sys_log/`) | да |
| **Реестр проектов** | PostgreSQL, БД `ms4d_projects`, таблица `projects` | да |
| **Содержимое проектов** | PostgreSQL, по БД на проект: `ms4d_project_<N>` | да |
| Бэкапы/экспорты проектов | куда экспортировал | зависит от тебя |

### Как редактор хранит проект внутри БД (проверено 2026-10-11)

Редактор держит проект не «файлами», а **объектным графом** — универсальной схемой, поверх которой
и строится дерево объектов:

| Таблица | Смысл |
|---|---|
| `items` | «объекты» проекта (элементы модели); у каждого `item_id` и `type_id` |
| `types` | типы элементов (у нас ≈ 819: служебные, свойства дизайнера, типы библиотек) |
| `links` / `link_types` | связи между элементами и их типы |
| `props_str` / `props_num` / `props_bin` | свойства по типу значения (текст / число / двоичные) |
| `trans_*` | транзакционные «версии» изменений (черновик/фиксация) |
| `users`, `sessions`, `log`, `sys_props` | пользователи проекта, сеансы, журнал, системные настройки |

Отсюда практические выводы: «дерево объектов» и «дерево системы» в редакторе — это строки в
`items`+`links`+`props_*`; сравнение/сортировка имён зависит от локали БД (`ru_RU.UTF-8` в нашем
стенде); «сохранить проект» = зафиксировать изменения (в т.ч. перенести `trans_*` в основные таблицы).

## Стек учебного стенда

| Компонент | Версия | Обязателен? |
|---|---|---|
| MasterSCADA 4D DT | 2.0.4 | да (редактор) |
| PostgreSQL | ≥ 10, у нас 16 | да (хранилище проектов) |
| Docker + compose | 2x | нет — альтернатива: системный PostgreSQL |
| Графический сеанс | любой X11/Wayland | да |

Стенд БД — [`infra/docker-compose.yml`](infra/docker-compose.yml): `localhost:15444`,
`course/course/course`, локаль `ru_RU.UTF-8`, том `pgdata`, публикация только на loopback. Вариант
«как у вендора» — системный PostgreSQL/PostgresPro на 5432 (урок 03, §2).

## Глоссарий модуля

| Термин | Значение |
|---|---|
| **DT** | Design Time — среда разработки (редактор проектов) |
| **RT** | Runtime — среда исполнения (работает проект) |
| **АРМ** | устройство исполнения «на ПК»; в эмуляции — эта же машина |
| **Узел** | конкретная машина исполнения проекта |
| **Дерево системы** | физика: узлы, протоколы, модули, каналы |
| **Дерево объектов** | логика: объекты, параметры, программы, окна |
| **Параметр** | именованное значение с типом (BOOL, REAL, …) и шкалой |
| **Эмуляция** | запуск RT локально, без загрузки в контроллер |
| **Хранилище** | PostgreSQL, в котором лежат проекты |
