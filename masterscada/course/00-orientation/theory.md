# Теория модуля 00: как устроен курс, стенд и что такое MasterSCADA 4D

## Карта курса

Курс — 14 модулей, идут строго по порядку: каждый опирается на предыдущие.

```
00 окружение ─► 01 проект ─► 02 теги ─► 03 объекты ─► 04 программы FBD/ST
                                                       │
                                              05 визуализация (HMI)
                                                       │
                                              06 каналы/протоколы
                                                       │
                                              07 архивы + PostgreSQL ─► 08 тревоги
                                                       │                   │
                                              09 деплой RT ◄───────────────┘
                                                       │
                                              10 резервирование/ИБ
                                                       │
                                              11 интеграция
                                                       │
                                              12 капстоун (мини-СИКН) ─► 13 собеседование
```

Единая структура модуля: `README.md` (цели, план, чеклист) → `theory.md` (конспект) →
`lessons/` (пошаговые уроки) → `examples/` → `exercises/` (решения в `solutions/`) → `labs/`.

Правила самостоятельного обучения:

1. **Примеры запускать, а не читать.** Проект, который не открыли в редакторе, — не пройден.
2. **Упражнения делать самому.** В `solutions/` заглядывать после того, как получилось (или когда застрял — и тогда честно переделать).
3. **Сверяться со справкой**, а не с памятью: интерфейс версии 2.0 отличается от 1.3.x.
4. **Лабы «сломай и почини» — обязательны.** Это способ узнать, как система падает, до прода.
5. **Отмечать прогресс** в `course/PROGRESS.md` после каждого модуля.

## Что такое MasterSCADA 4D (в двух абзацах)

MasterSCADA 4D — российская SCADA-платформа (вендор ИЭК ДИДЖИТАЛ / МПС Софт) для АСУ ТП:
сбор данных с оборудования, логика, визуализация, архивы, тревоги, отчёты. Проект строится в
**среде разработки** (в 2.0 — кроссплатформенная, `DT 2.0`), а исполняется на **среде исполнения**
(`RT`), которая может крутиться на ПК, сервере или контроллере. Данные историзации складываются в
СУБД — в 2.0 проекты и архивы завязаны на **PostgreSQL**.

Ключевые сущности, с которыми будем работать: **узел** (машина исполнения), **объект** (устройство/
агрегат), **тег/параметр** (значение с типом и шкалой), **программа** (FBD/ST-логика), **окно**
(мнемосхема для оператора), **канал** (обмен по протоколу), **архив** (история), **сообщение** (тревога).

## Стек стенда (что под капотом)

Среда разработки — это связка:

| Слой | Технология | Почему важно знать |
|---|---|---|
| UI/редактор | Electron 28 (Chromium 120) | отсюда требования к GTK и поддержка Wayland |
| Ядро | .NET 8 (self-contained) | рантайм внутри, отдельно ставить не надо |
| Драйверы | C++/Boost | нативные `.so`, переносимы на linux-x64 |
| БД проектов | PostgreSQL ≥ 10 | без неё проект не сохранить |

Поэтому SCADA запускается не только на «официальной» Astra SE 1.7/1.8, но и на Arch (см. урок 02).

## Стенд

Единый `docker-compose.yml` в `infra/`: **PostgreSQL 16**, порт хоста **15444** (не 5432 — чтобы не
конфликтовать с локальными сервисами и другими контейнерами). Доступы: user `course`, password
`course`, база `course`. Проекты MasterSCADA 2.0 хранятся в PostgreSQL — на этом стенде для обучения.

```bash
cd infra
docker compose up -d
docker compose exec -T postgres psql -U course -d course -c "SELECT version();"
docker compose down        # данные сохраняются в volume
```
