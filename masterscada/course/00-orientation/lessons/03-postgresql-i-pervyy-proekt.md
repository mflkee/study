# Урок 03: PostgreSQL в Docker и первый проект

**Закрывает цель:** PostgreSQL поднят, среда разработки видит БД, создан первый проект.
**Время:** 60 мин

## Зачем это нужно

В MasterSCADA 4D **2.0 все проекты хранятся в PostgreSQL** (в 1.3.x — в файлах). Пока БД не поднята,
редактор не сможет сохранить проект. Поэтому первый практический шаг — база.

## Ключевые идеи (сжато)

- Требование продукта: **PostgreSQL ≥ 10**; для обучения берём свежую (16).
- Держим БД в Docker на **нестандартном порту 15432** — чтобы не конфликтовать с другими.
- Доступы стенда: user `course` / password `course` / db `course`.
- Проект SCADA = запись(и) в БД; проверяем наличие схем/таблиц продукта после создания проекта.

## Разбор на примере

### 1. Поднять стенд

```bash
cd infra
docker compose up -d
docker compose ps                       # postgres должен быть Up (healthy)
```

### 2. Проверить БД

```bash
docker compose exec -T postgres psql -U course -d course -c "SELECT version();"
# ожидаем: PostgreSQL 16.x …
```

### 3. Создать первый проект

1. Запусти среду разработки (`../../../scripts/run-masterscada.sh`).
2. В стартовом окне выбери **«Создать проект»** (или меню **Проект → Создать**).
3. Укажи имя (напр. `sikn-lesson00`) и, если спросит, подключение к PostgreSQL:
   `localhost:15432`, БД `course`, пользователь `course`.
4. Сохрани проект и **перезапусти редактор** — проект должен открыться из БД (значит, он там).

> Точные пункты меню и строки подключения сверяй со справкой 2.0:
> `https://support.mps-soft.ru/ms4d_web/` (разделы «Проект в MasterSCADA 4D», «Операции с проектами»).

### 4. Убедиться, что данные легли в БД

```bash
docker compose exec -T postgres psql -U course -d course -c '\dt'
```
Появятся служебные таблицы MasterSCADA (имена уточняются по справке/логу — фиксируем в заметках).

## Как это устроено под капотом

- **docker compose volume** `pgdata` хранит данные между перезапусками; `docker compose down` не удаляет их,
  `down -v` — удаляет.
- Порт **15432:5432** — «host:контейнер». Внутри контейнера всегда 5432.
- Среда разработки подключается к БД по TCP (localhost:15432). Проверка связи — `psql` или `pg_isready`:
  ```bash
  docker compose exec -T postgres pg_isready -U course -d course
  ```

## Типичные ошибки и грабли

1. **Порт занят** — если 15432 тоже занят (у тебя много контейнеров), поменяй маппинг в `docker-compose.yml`.
2. **`password authentication failed`** — проверь `user/password/db` (`course/course/course`).
3. **Проект «не сохраняется»** — почти всегда БД не поднята/не тот порт; смотри лог редактора.
4. **`down -v` снёс базу** — данные стенда потеряны по определению; для обучения нормально.
