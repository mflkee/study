# Урок 02: Первый запуск среды разработки и диагностика

**Цель урока:** запустить DT 2.0 штатным способом, убедиться по процессам/логам, что поднялись
**все три части** (UI, .NET-ядро, драйверы), и знать, что делать, когда «не открывается окно».

**Время:** ~50 мин · **Пререквизиты:** урок 01 (пакет установлен), рабочий графический сеанс.

---

## 1. Три способа запуска

| Способ | Как | Когда нужен |
|---|---|---|
| Ярлык в меню | раздел **Разработка** → «MasterSCADA 4D 2.0» | обычная работа |
| Из терминала | `cd "/opt/MasterSCADA 4D 2.0" && ./MasterSCADA4D_2.0` | нужны флаги/вывод в консоль |
| Скрипт | `scripts/run-masterscada.sh` (этот репозиторий) | режимы X11/Wayland (по умолчанию X11), см. §5 |

Ярлык и терминал делают одно и то же: `.desktop` — это та же команда плюс, при необходимости,
флаги. Держи в голове правило: **всегда проверяй запуск из терминала** — там виден stderr.

## 2. Как понять, что запустилось всё, а не «половина»

Среда разработки — это **три слоя**: UI (Electron/Chromium), ядро проекта (.NET) и нативные
драйверы (.so). Проверяем:

```bash
# 1) окно на месте (X11)
wmctrl -l | grep -i masterscada        # или: xdotool search --name MasterSCADA
# 1') окно на месте (Wayland/niri)
niri msg --json windows | grep -i masterscada

# 2) процессы: должен быть и Electron, и .NET-ядро
ps -eo pid,args | grep -i masterscada | grep -v grep
```

Ожидаемая картина (пример):

```
… /opt/MasterSCADA 4D 2.0/MasterSCADA4D_2.0
… /opt/MasterSCADA 4D 2.0/MasterSCADA4D_2.0 --type=zygote …
… /opt/MasterSCADA 4D 2.0/MasterSCADA4D_2.0 --type=renderer …
… resources/MasterSCADA4D_Server/MasterSCADA4D_Server --server-startup-port=44000 …
```

Если есть только Electron и нет `MasterSCADA4D_Server` — UI поднялся, а ядро упало: смотри лог.

## 3. Где живут настройки, логи и «залипшие» признаки запуска

Это знание экономит часы. Проверено на стенде (сборка rc):

| Что | Путь | Зачем |
|---|---|---|
| Данные UI | `~/.config/MasterSCADA 4D 2.0/` (у rc: `…/MasterSCADA 4D RC/`) | кэш Chromium, `SingletonLock` |
| Настройки IDE | `~/.config/MPSSoft/MasterSCADA4D_DT_2.0/IdeSettings.json` | параметры и подключение к БД (урок 03) |
| **Лог IDE** | `~/.config/MPSSoft/MasterSCADA4D_DT_2.0/sys_log/ГГГГ_ММ_ДД.log` | старт, ошибки, подключение к хранилищу |
| Настройки проекта (в самом проекте) | в PostgreSQL | см. урок 03 |
| Общие данные (пользовательские запросы) | `/usr/share/MPSSoft/` | создаётся `postinst` пакета (урок 01, §4.1); без него проект не открыть |

> У сборок с суффиксом (rc/beta/branch) каталог настроек тоже с суффиксом:
> `~/.config/MPSSoft/MasterSCADA4D_DT_2.0_RC/`. Ниже в командах — релизное имя.

Проверка, что запуск реально состоялся (а не «окно от прошлого раза»):

```bash
tail -n 5 ~/.config/MPSSoft/MasterSCADA4D_DT_2.0/sys_log/$(date +%Y_%m_%d).log
# ожидаем свежую строку: Start application <версия> (<сборка>)
```

> Версия в логе выглядит «странно»: `Start application 1.3.10.33235(2.0.4_RC_20260622.1)` —
> ядро/RT ведут собственную нумерацию (1.3.x), а редактор — 2.0.4. Это норма, не путать версии.

## 4. Диагностика: симптом → причина → действие

| Симптом | Причина | Действие |
|---|---|---|
| Команда сразу завершилась, окна нет | не хватает библиотек | `ldd … \| grep 'not found'` (урок 01, §4) |
| `The SUID sandbox helper binary was found, but is not configured correctly` | `chrome-sandbox` без setuid | см. §5 «про песочницу» |
| Окно не появляется, а процесс уже висит со старым временем старта | сработал **single-instance lock** | §5 «повторный запуск» |
| Окно есть, но чёрное / интерфейс тормозит | рендер через SwiftShader (нет GPU-ускорения) | проверить драйвер GPU, снять софтверный фолбэк |
| В консоли `fontconfig: … 48-guessfamily.conf` | предупреждения шрифтов | игнорировать, безвредно |
| Не переключается раскладка в полях ввода | приложение идёт через XWayland, а у X-сервера своя раскладка (в неофициальных Wayland-окружениях) | задать раскладку X-серверу при старте сеанса (в niri — `spawn-sh-at-startup` с `setxkbmap`), см. §5 и конспект |
| `Access to the path '/usr/share/MPSSoft' is denied` / `UnauthorizedAccessException` при открытии или создании проекта | не выполнен `postinst` пакета (установка распаковкой): IDE пишет общие данные в `/usr/share/MPSSoft`, которого нет | `sudo mkdir -p /usr/share/MPSSoft && sudo chmod a+rwx /usr/share/MPSSoft` (урок 01, §4.1) |
| «Выбранный проект уже открыт» | проект удерживается advisory-блокировкой PostgreSQL другим сеансом/окном IDE | закрыть второе окно/старую копию IDE (или `pkill`), проверить: `SELECT * FROM pg_locks WHERE locktype='advisory'` |
| `!!!Обращение к удаленному элементу : '<disposed>' (Id=… Type=MasterSCADA.Program…)` в логе | шум .NET-ядра: дизайнер (мнемосхема/схема) читает уже удалённый элемент модели; проект при этом работает | если идёт потоком — сохранить проект и переоткрыть; на данные не влияет |
| Диалог **«Fatal error» с кнопкой RELOAD**, после нажатия — белый экран (перезагрузка не помогает) | упал **серверный Blazor-канал** среды: RC-баг при работе с уже удалёнными элементами модели — `BranchesService.BranchedItem_ItemChanged` → `System.InvalidOperationException: Sequence contains no matching element`; в дизайнере FBD `ValueIndicatedFbdComponent` → `Обращение к удаленному элементу … <disposed>`. Замечено в т.ч. после ввода текста в фильтр дерева «Поиск…». Стек — только сборки MS4D, к ОС не привязан | **перезапустить среду** — данные не теряются (проект в PostgreSQL): `pkill -f '^/opt/MasterSCADA 4D RC'; sleep 3; scripts/run-masterscada.sh`. В журнале симптом ищется по `BranchesService.BranchedItem_ItemChanged`. Сохраняйся чаще («Проект → Сохранить») |
| **Часть горячих клавиш не срабатывает** (`Ctrl+C`, `Ctrl+V`), а меню и ПКМ работают | проверено 2026-10-12: клавиатуру приложение **видит** — в X11-режиме работают `Ctrl+D` (дублировать), `Ctrl+N`, `Del` и само ПКМ-меню. Отказы `Ctrl+C/Ctrl+V` встречались в сеансе, где окно шло через XWayland с незакрытой прежней копией (**UNVERIFIED**: привязаны ли эти команды к клавишам в вашей сборке — проверьте сами) | если не срабатывает — меню **«Правка»** и контекстное меню (ПКМ): «Дублировать», «Копировать», «Вставить», «Вставить как экземпляр». Эталон привязок релиза — `vkladka_sochetaniya_klavish.html` (`Ctrl+C/V`, `Ctrl+D`, `Ctrl+Shift+V`, `Ctrl+S`, `F2`, `Del`) |
| При запуске эмуляции **не появляется** окно выбора «клиент визуализации ИЭК / браузер по умолчанию» | выбор уже был сделан ранее и запомнен в настройках (`IdeSettings.json` → `OpenClientMode`) | посмотреть/сменить: **Настройки среды → вкладка «Клиент визуализации»**; мнемосхема при этом открывается в выбранном клиенте (часто — вкладкой в браузере, а не отдельным окном) |
| «Не удалось подключиться» при создании проекта | нет PostgreSQL / не тот порт/пароль | урок 03 |

**Общее правило диагностики:** сначала процессы (`ps`), потом лог (`sys_log`), и только потом
GUI. 90 % «не работает» видно в этих двух местах.

## 5. Особые случаи запуска

### Песочница Chromium (`chrome-sandbox`)

Electron требует, чтобы `chrome-sandbox` был setuid-root. Два честных варианта:

```bash
# Вариант А (предпочтительный, один раз, нужен root):
sudo chown root:root "/opt/MasterSCADA 4D 2.0/chrome-sandbox"
sudo chmod 4755 "/opt/MasterSCADA 4D 2.0/chrome-sandbox"

# Вариант Б (только для своей машины, без root): запуск без песочницы
./MasterSCADA4D_2.0 --no-sandbox
```

`--no-sandbox` снижает изоляцию процесса — для учебного стенда допустимо, для рабочего парка
лучше вариант А.

### Повторный запуск («окно не открывается»)

Приложение — single-instance: второй запуск просто «покажет» первый. Если предыдущий процесс
завис и не умирает по SIGTERM:

```bash
pkill -9 -x MasterSCADA4D_2          # в списке процессов имя обрезано до 15 символов
pkill -9 -x MasterSCADA4D_S
find "$HOME/.config/MasterSCADA 4D 2.0" -maxdepth 1 -name 'Singleton*' -delete
```

> Имя процесса в `ps` обрезано до 15 символов (`MasterSCADA4D_2`), поэтому `pkill -x
> MasterSCADA4D_2.0` не сработает — используй `-f` или обрезанное имя.

### Варианты запуска под Wayland

Под Wayland у Electron два пути — через **XWayland** (окно живёт как X11-клиент) или **нативно
в Wayland** (озеро, включается флагом `--ozone-platform-hint=auto`). Выбор не косметический:
от него зависит, работает ли **контекстное меню (ПКМ)**.

| | X11 (XWayland) — **рекомендуется** | Нативно Wayland |
|---|---|---|
| ПКМ-меню, диалоги, горячие клавиши | работают штатно (проверено 2026-10-12) | **ПКМ ломается**: меню рисуется отдельным X11-окном без родителя, композитор вставляет его в раскладку — окно дёргается, меню закрывается |
| Раскладка клавиатуры | у X-сервера своя раскладка → нужен `setxkbmap` при старте сеанса (см. конспект, грабл. 7) | раскладку даёт композитор |
| Вид окна | рамка и фокус-кольцо композитора | без рамки (клиентские декорации) |

Проверить, каким путём пошёл запуск:

```bash
ps -eo args | grep -o -- '--ozone-platform=wayland' | head -1   # есть вывод → нативно Wayland
niri msg --json windows | grep -i masterscada                   # pid = процесс xwayland-satellite → X11
```

Проверенный частный случай (Arch + niri, **неофициально**) — скрипт
[`scripts/run-masterscada.sh`](../../../scripts/run-masterscada.sh) (режим задаётся переменной
`MASTERSCADA_MODE`: `x11` — по умолчанию, `wayland` — нативно) и конспект
[`../../../docs/reference/ustanovka-arch-niri.md`](../../../docs/reference/ustanovka-arch-niri.md).

На поддерживаемой **Astra Linux** этот раздел читается «на будущее»: там сессия X.Org, и приложение
работает в том же режиме, что и «X11» у нас, — поэтому все шаги курса выполняются одинаково.

Ещё одна грабля того же места (проверено 2026-10-12): если запустить новую копию, **не сняв прежнюю**,
окно навсегда застревает на заставке — старый `.NET`-сервер держит порт ядра (44000). Лечится
полной зачисткой: `pkill -f '^/opt/MasterSCADA 4D RC'; sleep 3` (и не матчить этой же командой
свою оболочку — шаблон должен быть привязан к началу пути).

## 6. Проверка себя (чеклист урока)

- [ ] Среда разработки запускается тремя способами, из терминала — вижу stderr.
- [ ] В процессах есть и Electron, и `MasterSCADA4D_Server`.
- [ ] В `sys_log/<сегодня>.log` появилась свежая строка `Start application …`.
- [ ] Знаю путь `IdeSettings.json` и что в нём лежит.
- [ ] Знаю, чем «не хватает библиотек» отличается от «сработал single-instance».
- [ ] Могу объяснить, зачем `chrome-sandbox` и что делает `--no-sandbox`.

## 7. Задание

1. Запусти редактор из терминала, покажи две команды проверки (§2) и их вывод.
2. Найди в `sys_log` строку старта и сравни версию ядра (1.3.x) с версией редактора (2.0.x).
3. **Сломай и почини:** оставь приложение запущенным и запусти его второй раз — опиши, что
   произошло. Затем прибей процессы и запусти снова, предварительно удалив `Singleton*`.
4. Определи, идёт ли твой запуск нативно в Wayland или через XWayland (одна команда).
