# Урок 04: Hello world — полный цикл (разработка → исполнение/эмуляция RT)

**Закрывает цель:** пройти весь цикл MasterSCADA 4D вживую: проект → дерево системы → логика →
мнемосхема → компиляция → запуск **среды исполнения (RT) в режиме эмуляции**.
**Время:** ~1.5 ч

## Зачем это нужно

Это тот самый «hello world», после которого SCADA перестаёт быть абстракцией: ты увидишь, как
логика (`Управляющий выход`), кнопка на мнемосхеме и режим исполнения связаны воедино. Всё делается
**в режиме эмуляции** — RT запускается на этой же машине, в контроллер ничего не загружается.

> Сценарий повторяет официальный **Быстрый старт (БС. Урок 1)** из справки 2.0. Ниже — адаптация под
> наш стенд (Arch+niri, PostgreSQL на порту `15444`). Точные названия пунктов меню **сверяй со справкой**:
> <https://support.mps-soft.ru/ms4d_web/bs__urok_1.html>.

## Ключевые идеи (сжато)

- **Два дерева:** *дерево системы* (физика: узлы, протоколы, каналы) и *дерево объектов* (логика: объекты, параметры, программы).
- **Узел** — где исполняется проект. Для старта берём **АРМ** (эмуляция на этом же ПК).
- **Параметр** — значение с типом (у нас `BOOL`). **Программа** (FBD) обрабатывает параметры.
- **Окно** — мнемосхема оператора; элементы привязываются к параметрам.
- **Компиляция** → **Исполнение в режиме эмуляции** → появляется клиент визуализации.

## Разбор по шагам

### 0. Подключение к PostgreSQL (до создания проекта)

Справка: «Прежде чем начать работать нужно настроить среду разработки — указать параметры
подключения к базе данных PostgreSQL».

**Настройки среды → Вкладка Базы данных** (по справке `vkladka_bazy_dannyh.html`):

| Поле | Значение для стенда |
|---|---|
| Сервер | `localhost` |
| Порт | **`15444`** (наш стенд; по умолчанию у продукта `5432`) |
| Пользователь | `course` |
| Пароль | `course` |
| Путь к PostgreSQL | путь к папке `bin` PostgreSQL — на Linux поле выглядит «по-виндовому», поведение `UNVERIFIED` |

Стенд поднимается из `infra/`: `docker compose up -d` → `SELECT version()` = PostgreSQL 16.x.

### 1. Создать проект
Запусти среду разработки, выбери **«Создать проект»**. Имя по умолчанию — «Новый проект», можно оставить.

### 2. Дерево системы (физика)
1. ПКМ по дереву системы → выбрать устройство исполнения **АРМ**.
2. ПКМ по **Протоколы** → **Modbus TCP**.
3. ПКМ по Modbus TCP → **Добавить → ModbusTCP Device** (модуль дискретного вывода).
4. В свойствах устройства задать, сколько входов/выходов нам нужно (нам — один дискретный выход).

### 3. Дерево объектов (логика)
1. ПКМ по дереву объектов → **Добавить → Объект**.
2. ПКМ по объекту → **Добавить → Параметр**; имя — `Управляющий Выход`, тип — **BOOL**.
3. В контекстной панели объекта добавить программу на языке **FBD** (создаст входы `Пуск`/`Стоп` и выход).

### 4. Окно управления (мнемосхема)
1. ПКМ по объекту → **Добавить → Окно**.
2. Перетащить в окно (с зажатым `Alt`) параметр `Пуск` → из меню выбрать
   **«Создать связанный контрол.Кнопка.Двунаправленная связь»** (по нажатию параметр = TRUE).
3. То же для `Стоп`.
4. Индикация: из **Легенды → вкладка Палитра → Примитивы** перетащить **Овал**;
   привязать цвет/видимость к `Управляющий Выход` (по TRUE — зелёный).

### 5. Компиляция
Вкладка **Компиляция** на панели инструментов → **Скомпилировать проект**. Убедиться, что ошибок нет.

### 6. Запуск исполнения (эмуляция RT)
Вкладка **Исполнение** → запустить проект **в режиме эмуляции** (загрузки в контроллер нет —
исполнительная система работает на этой же машине). При первом запуске спросят, чем показывать
мнемосхему: **клиент визуализации** ИЭК или **браузер по умолчанию** — выбор любой.

### 7. Проверка
Рядом с именем узла появится признак запуска; откроется клиент визуализации с окном.
- Нажать **Пуск** → `Управляющий Выход` = **TRUE**, индикатор зелёный.
- Нажать **Стоп** → **FALSE**, индикатор другой.
В редакторе рядом с параметрами будут видны текущие значения — это и есть «живой» RT.

## Как это устроено под капотом

- **Компиляция** превращает части проекта в конфигурацию для узла; в среде разработки появляется
  папка скомпилированного проекта (по узлам).
- **Режим эмуляции** = локальный запуск **RT** (в DT 2.0 это `.NET`-ядро `MasterSCADA4D_Server`),
  которое мы уже видели в процессах. Обмен «среда разработки ↔ RT» идёт по локальным портам.
- **Исполнение без эмуляции** (реальный узел): компиляция → загрузка конфигурации на узел
  (или экспорт конфигурации и ручная загрузка в рабочую папку RT).

## Типичные ошибки и грабли

1. **Не задано подключение к БД** → проект не создаётся/не сохраняется. Проверь вкладку Базы данных (шаг 0).
2. **Порт БД**: у нас `15444`, а не 5432 — не перепутай.
3. **Первый запуск**: выбор клиента визуализации запоминается (файл вида `IdeSettings.json`); изменить — в Настройках среды.
4. **Лицензия**: среда разработки бесплатна; RT-исполнение может требовать ключ/демо (встроенное демо — ограничен по времени). Если RT не стартует — проверь статус лицензии.
5. **Compose стенда**: порт `15444`; если занят — поменяй маппинг и настройки среды согласованно.
6. Точные подписи меню могут отличаться от справки/версии — **сверяйся с `support.mps-soft.ru/ms4d_web`**.
