# Урок 04: Hello world — полный цикл (разработка → эмуляция RT)

**Цель урока:** пройти весь цикл вживую — проект → дерево системы → логика (FBD) → мнемосхема →
компиляция → запуск **среды исполнения в режиме эмуляции**. После этого урока SCADA перестаёт быть
абстракцией: видно, как связаны параметр, программа, окно и RT.

**Время:** ~1.5 ч · **Пререквизиты:** уроки 01–03 (редактор запущен, БД подключена, проект создаётся).

> Сценарий повторяет официальный **Быстрый старт (БС. Урок 1)** из справки 2.0. Точные подписи
> пунктов меню сверяй со справкой — интерфейс 2.0 живой:
> `bs__urok_1__sozdanie_proekta.html`, `…__konfigurirovanie_dereva_sistemw.html`,
> `…__sozdanie_logicheskoy_chasti_proekta.html`, `…__sozdanie_okna_upravleniya.html`, `…__zapusk.html`.

## Что получится в итоге

Объект «насос» с двумя кнопками (`Пуск`, `Стоп`), одним логическим выходом (`Управляющий выход`)
и индикатором на мнемосхеме. Нажатие `Пуск` устанавливает выход в `TRUE` (индикатор зелёный),
`Стоп` — сбрасывает. Логика — **SR-триггер**: пока держишь `Пуск`, на S-входе `TRUE`, триггер
«взводится» и остаётся в этом состоянии после отпускания, пока не нажмёшь `Стоп` (R-вход).

## Ключевые идеи

- **Два дерева:** *дерево системы* (физика: узлы, протоколы, каналы) и *дерево объектов* (логика:
  объекты, параметры, программы). Не путай их — это половина всех ошибок новичка.
- **Узел** — то, где исполняется проект. Для старта берём **АРМ** (эмуляция на этой же машине).
- **Параметр** — значение с типом (`BOOL`), **программа** — обработка (FBD), **окно** — мнемосхема.
- **Компиляция → Исполнение (эмуляция)**: контроллер не нужен, RT поднимается локально.

## Шаги

### 0. Проверь, что БД на месте

Создание/сохранение проекта невозможно без PostgreSQL (урок 03). Быстрая проверка стенда:

```bash
cd ../infra && docker compose exec -T postgres pg_isready -U course -d course   # вариант B
```

### 1. Создать проект

Стартовое окно → **«Создать проект»**. Имя — как решил в уроке 03 (например `Обучение`),
параметры хранилища — те же, что в настройках среды.

### 2. Дерево системы (физика)

1. ПКМ по **дереву системы** → выбрать устройство исполнения **АРМ**.
2. ПКМ по элементу **Протоколы** → **Modbus TCP**.
3. ПКМ по **Modbus TCP** → **Добавить → ModbusTCP Device** (модуль дискретных входов-выходов).
4. В свойствах модуля задать **1 канал** — нам нужен один дискретный выход.

> Смысл этого шага: сказать SCADA, *где физически* живёт сигнал. Дальше логика будет ссылаться
> на канал, а не на «абстрактный выход».

### 3. Дерево объектов (логика)

1. ПКМ по **дереву объектов** → **Добавить → Объект**.
2. ПКМ по объекту → **Добавить → Параметр**: имя `Управляющий выход`, тип **BOOL**.
3. В контекстной панели объекта добавить программу на языке **FBD**; собрать SR-триггер так, чтобы
   входы `Пуск`/`Стоп` управляли `Управляющий выход` (как в справке: S-вход — `Пуск`, R-вход — `Стоп`).

### 4. Окно управления (мнемосхема)

1. ПКМ по объекту → **Добавить → Окно** — откроется редактор графического интерфейса.
2. Из группы **Параметры** программы перетащить в окно (удерживая **Alt**) параметр `Пуск` →
   в контекстном меню выбрать **«Создать связанный контрол.Кнопка.Двунаправленная связь»**
   (это создаст кнопку и связь с параметром).
3. Повторить для `Стоп`.
4. Индикация: **Легенда → вкладка Палитра → Примитивы** → перетащить **Овал** в окно; настроить
   цвет/видимость по параметру `Управляющий выход` (`TRUE` — зелёный, `FALSE` — белый).

### 5. Компиляция

Вкладка **Компиляция** на панели инструментов → **Скомпилировать проект**. Дождаться сообщения об
успехе; при ошибках открыть панель ошибок и перейти по сообщению двойным щелчком.

### 6. Запуск в режиме эмуляции

Вкладка **Исполнение** → запустить проект **в режиме эмуляции**. Загрузки в контроллер нет —
исполнительная система эмулируется на этой же машине. При первом запуске спросят, чем показывать
мнемосхему: **клиент визуализации ИЭК** или **браузер по умолчанию** — выбор любой.

### 7. Проверка (обязательные доказательства)

- рядом с именем узла появился признак запуска;
- открылся клиент визуализации/браузер с созданной мнемосхемой;
- в редакторе рядом с параметрами появились **текущие значения**;
- `Пуск` → `Управляющий выход` = `TRUE`, индикатор **зелёный**;
- `Стоп` → `FALSE`, индикатор **белый**.

Бонусы из справки (по желанию):
- открыть мнемосхему **с другого устройства** по IP этой машины — управление работает так же;
- если есть реальный контроллер: отключить эмуляцию, выделить контроллер в дереве, проверить IP и
  нажать **«Подключить»** вместо «Эмуляция» — проект загрузится и запустится на контроллере.

## Как это устроено под капотом

- **Компиляция** превращает проект в конфигурацию по узлам; появляется папка скомпилированного
  проекта. Ошибки компиляции — это ошибки логики/типов, а не «глюк SCADA».
- **Эмуляция** = локальный запуск RT (в комплекте DT 2.0.4 — ядро RT 1.3.10, отдельно качать не
  надо). Обмен «редактор ↔ RT» идёт по локальным портам; в процессах видно `MasterSCADA4D_Server`.
- **Реальный узел** отличается только способом доставки конфигурации (`Подключить`), а не логикой
  проекта.

## Грабли

| Симптом | Причина | Что делать |
|---|---|---|
| Проект не создаётся/не сохраняется | нет БД или не тот порт (урок 03) | поднять стенд, сверить настройки |
| Команды запуска серые | выбран **«Проект визуализации»** (нет узла) или ничего не выделено | пересоздать как **«Общий проект»**; выделить узел. Тип уже созданного проекта видно в реестре БД: `psql -d ms4d_projects -c "SELECT project_name, type_name FROM projects;"` |
| RT не стартует / «Узел не активирован» | нет лицензии/ключа — работает ограниченный демо-режим | проверить статус ключа/лицензии; для обучения хватает демо-сеанса |
| Значения параметров не «живут» | смотришь проект, но не запустил исполнение; или узел не тот | запустить эмуляцию (шаг 6), проверить узел |
| Диалог выбора клиента визуализации не появляется | выбор уже был сделан раньше | изменить в настройках среды |

## Критерии «урок пройден»

- [ ] Проект создан и **сохранён** (виден в БД — урок 03).
- [ ] Компиляция без ошибок.
- [ ] Эмуляция запущена: рядом с узлом есть признак, открылся клиент визуализации.
- [ ] `Пуск`/`Стоп` меняют `Управляющий выход` и цвет индикатора; значения видны и в редакторе.
- [ ] Могу объяснить, зачем в дереве системы нужен был ModbusTCP Device, если логика — в дереве объектов.
