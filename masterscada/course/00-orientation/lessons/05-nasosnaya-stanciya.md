# Урок 05: Насосная станция — тиражирование объекта и привязка к Modbus

**Цель урока:** превратить один объект-насос в **тиражируемый библиотечный тип** и собрать из него
объект «Насосная станция» из трёх насосов, каждый со своим дискретным выходом модуля. После урока
ты понимаешь цепочку **тип → наследник → экземпляр**, умеешь связывать параметры перетаскиванием и
знаешь, где эти связи лежат (в панели свойств и в БД).

**Время:** ~1.5 ч · **Пререквизиты:** [урок 04](04-hello-world-polnyy-cikl.md) — проект с объектом,
логикой FBD, мнемосхемой и работающей эмуляцией RT.

> Сценарий повторяет официальный **Быстрый старт (БС. Урок 3)** из справки 2.0:
> `bs__urok_3__ob_ektnwy_podhod_pri_sozdanii_proekta.html` (объектный подход),
> `bs__urok_3__operacii_s_bibliotekami.html` (операции с библиотеками),
> `bs__urok_3__zapusk.html` (запуск). База справки: `https://support.mps-soft.ru/ms4d_web/`.

## Что получится в итоге

```
Дерево объектов                          Дерево системы
└── Насосная станция                     АРМ 1 → Modbus TCP → ModbusTCP Device 1
    ├── Насос 1  (экземпляр)  ──┐                ├── DO 1  (адрес 1)
    ├── Насос 2  (экземпляр)  ──┼── связи ──►    ├── DO 2  (адрес 2)
    └── Насос 3  (экземпляр)  ──┘                └── DO 3  (адрес 3)

Библиотеки → Локальная → Насос 1   ← библиотечный тип, на который «ссылаются» все три насоса
```

Три насоса — это **три экземпляра одного типа**: окна и программа у них общие (правятся один раз в
типе и применяются ко всем), а связь с «внешним миром» у каждого своя — параметр «Управляющий выход»
каждого экземпляра связан со своим каналом.

## Ключевые идеи

- **Три роли элемента** (справка: `tipy_nasledniki_i_ekzemplyary_masterscada_4d.html`):
  - **тип** — библиотечный элемент, в нём хранятся окна, программы, параметры;
  - **наследник** («Унаследован от») — копия типа, которую можно править локально (и «Разорвать
    наследование», чтобы получить независимый объект);
  - **экземпляр** («Ссылается») — «содержит в себе только элементы, необходимые для связи с другими
    элементами проекта… Разработчик не может изменить внутреннюю структуру отдельного экземпляра».
- **Экземпляр — это про связи, а не про редактирование.** Хочешь три насоса с одинаковой логикой и
  окнами и разными выходами — тебе нужны именно экземпляры.
- **Связь параметров создаётся перетаскиванием** (справка: `svyazwvanie_peremennwh.html`):
  «необходимо выполнить перетаскивание одного параметра… на другой параметр. Направление перетаскивания
  определяет направление передачи значения… если допускается установка только одной связи данного типа,
  то при попытке установить вторую связь открывается диалог подтверждения замены связи».
- **Канал принимает одну входящую связь.** Значит, DO-канал нельзя «скормить» двум насосам — при
  попытке SCADA предложит заменить связь.
- **Связи — это данные, а не «настройка окна»:** они живут в БД проекта (таблица `links`, тип связи
  `MasterSCADA.ReadValue`) и **исчезают вместе с экземпляром**, которому принадлежат (проверено: удалили
  экземпляр — у каналов не осталось связей).

## Карта дерева после тиражирования (важно для навигации)

В дереве несколько корневых веток — **Система**, **Объекты**, **Библиотеки** (и «Безопасность»).
После связки «объект → тип → экземпляры» один и тот же насос видно в **двух** местах, и это главный
источник путаницы:

```
Объекты
└── Насосная станция               ← рабочий объект, содержит экземпляры
    ├── Ресурсы → Окна → …         ← окна самой станции (например, «Мнемосхема»)
    └── Насос 1 ─┐
        Насос 2 ─┼─ экземпляры: окна и программы править НЕЛЬЗЯ (структура — от типа)
        Насос 3 ─┘
Библиотеки
└── Локальная
    └── Объекты → Насос 1          ← библиотечный ТИП: здесь и живут «Окно 1» и «Программа_FBD_1»
        └── Ресурсы → Окна → Окно 1
                   → Программы → Программа_FBD_1
                   → Управляющий выход   ← у элементов со связями есть значок связи
```

Правила навигации:

- **Правки окон и программ насоса — только в типе** (`Библиотеки → Локальная → Объекты → Насос 1`):
  в экземпляре те же элементы открываются, но редактирование запрещено (справка: экземпляр «содержит
  только элементы, необходимые для связи»).
- «Поиск…» над деревом в этой RC-сборке **не находит** элементы (а после ввода может уронить сессию
  в `Fatal error`) — ищи по веткам.
- Понять, где ты: над полотном редактора есть «хлебные крошки» —
  `Библиотеки » Локальная » Насос 1 » Программа_FBD_1` или `Объекты » Насосная станция » Окно 1`.
- Если элементы «пропали»: в панели инструментов дерева есть кнопка **вида** (упрощённый/полный).
  В упрощённом виде показываются только явно созданные элементы, а из библиотек — только
  пользовательские; верни полный вид — и всё на месте.

## Шаги

### 0. Подготовка

1. Проект из урока 04 **сохранён** («Проект → Сохранить»), СУБД отвечает, эмуляция можно остановить —
   дальше работаем в редакторе.
2. Дерево системы уже содержит `АРМ 1 → Протоколы → Modbus TCP → ModbusTCP Device 1`.

### 1. Объект → станция

1. Переименуй свой объект в **`Насос 1`** (выделить → `F2`).
2. ПКМ по **дереву объектов** → **Добавить → Объект**, имя — **`Насосная станция`**.
3. **Перетащи** `Насос 1` внутрь `Насосной станции` (зажми ЛКМ на элементе и отпусти на новом
   родителе). Получился корневой объект со вложенным.

### 2. Тип и экземпляры

4. ПКМ по `Насос 1` → **«Поместить в библиотеку»** → **`Локальная`**. Теперь насос — **библиотечный
   тип** (виден в ветке «Библиотеки → Локальная»).
5. ПКМ по **библиотечному** элементу `Насос 1` → **«Заменить наследников на экземпляры»**. Насос в
   дереве объектов станет **экземпляром** — об этом говорит значок у имени и всплывающая подсказка.
6. **Перетащи библиотечный `Насос 1`** в `Насосную станцию` дважды — получится три насоса.
   У каждого должен быть **один параметр для связи с внешним миром** — `Управляющий выход`.

> Проверка понимания: открой у любого экземпляра «Окна» или «Программы» — они открываются только на
> просмотр. Правки делаются в **библиотечном типе** (см. упражнение в конце урока).

### 3. Каналы Modbus

7. В дереве системы раскрой `ModbusTCP Device 1`: должно быть три дискретных канала — `DO 1`,
   `DO 2`, `DO 3`.
   - у каждого канала в **панели свойств** проверь **«Адрес»** — он должен быть **своим** (1, 2, 3);
   - «Регион» и «Тип данных в устройстве» можно не трогать: если они не переопределены, действуют
     значения из **шаблона модуля** (`HOLDING_REGISTERS` / `INT` для этого устройства), и в БД у
     канала их просто не будет — это нормально, а не ошибка.
   - нужно больше каналов — `Ctrl+D` (дублировать) или ПКМ → «Дублировать»; **адрес после
     дублирования проверяй руками** (SCADA проставляет следующий по порядку, но задумку не знает).

### 4. Привязка насосов к каналам

8. ПКМ по объекту **`Насосная станция`** → **«Открыть в панели веток»** — это представление, где
   видно содержимое объекта и удобно тянуть связи.
9. Открой рядом дерево системы с каналами (`АРМ 1 → … → ModbusTCP Device 1 → DO 1…3`). В справке
   прямо сказано: «Связывание удобнее производить, **открыв деревья связываемых элементов в
   параллельных окнах**».
10. **Перетащи** `Управляющий выход` насоса на соответствующий канал: `Насос 1 → DO 1`,
    `Насос 2 → DO 2`, `Насос 3 → DO 3`. Пока тянешь, следи за курсором: когда связь разрешена, он
    меняет вид; если канал уже с чем-то связан — SCADA покажет диалог **замены связи**, соглашайся.

> Меню по самому параметру (`Восстановить по умолчанию`, `Копировать путь к элементу`,
> `Сменить тип`, `Открыть в панели веток`) — это меню **элемента**, команды «создать связь» там нет
> и не должно быть: связи делаются перетаскиванием.

### 5. Второе окно: «Окно управления» и всплывающее окно (по БС. Урок 2)

Вендор делит окна объекта так: `Окно 1` — изображение насоса, `Окно управления` — кнопки и
индикатор, которое открывается всплывающим по клику на изображении насоса.

11. **Создай окно в библиотечном ТИПЕ** (не в экземпляре!): `Библиотеки → Локальная → Объекты →`
    ПКМ по `Насос 1` → **Добавить → Окно**, имя — **`Окно управления`**.
12. В окне типа `Окно 1` выдели кнопки и индикатор → **Вырезать** (`Ctrl+X` / кнопка «Вырезать» /
    ПКМ) → перейди на вкладку `Окно управления` → **Вставить** (`Ctrl+V`) → в диалоге
    **«Восстановление связей»** нажми **«Установить»**.

    > **После вставки обязательно проверь размеры.** Проверено 2026-10-12: при переносе между окнами
    > в этой RC-сборке у элементов **теряются `Ширина`/`Высота`** — в модели остаются координаты
    > (`Designer.Layout.X/Y`), а `Designer.Layout.Width/Height` пропадают (в БД у перенесённых кнопок
    > нет свойств 751/752, у библиотечных «эталонных» кнопок они есть: 120×37). Без размера контрол
    > рисуется «пустым квадратиком». Лечится: выделить элемент → «Свойства» → категория
    > **«Расположение»** → задать `Ширина`/`Высота` (или потянуть за маркеры в редакторе).
    > Связи и тип вида при переносе не теряются — их переносит корректно.
13. **Уменьши окно.** Размер задаётся в свойствах **самого окна**, а не элемента: выдели **узел окна**
    в дереве → категория **«Расположение» → «Ширина» и «Высота»** (справка: `svoistva_okna.html`).
    Границы в редакторе тоже тянутся, но при масштабе 100 % они могут оказаться за краем видимой
    области — уменьши масштаб внизу редактора.
14. Снова `Окно 1` типа → выдели изображение насоса → панель свойств → вкладка **«СОБЫТИЯ»** →
    ПКМ по событию **«Клик мыши»** → **Добавить** → действие **«Открыть всплывающее окно»** →
    выбери `Окно управления`.
15. Проверь: всё сделано в типе — значит применилось ко всем трём насосам.

> **Как понять, что правишь не то:** если в правом верхнем углу редактора горит **`READ-ONLY`**,
> окно открыто **из экземпляра** — правки запрещены, и размер тоже не изменить. Открой то же окно
> из библиотечного типа: крошки над полотном будут вида `Библиотеки » Локальная » …`, и бейджа нет.

### 5.1 Мнемосхема станции: как размещать насосы

Окно станции (`Объекты → Насосная станция → Ресурсы → Окна`) — это её мнемосхема: перетащи в него
насосы, чтобы на старте было что показать.

- Перетаскивание объекта (у которого есть окна) **левой кнопкой** вставляет **его первое окно**
  (справка `razmeschenie_tega_kanala_objecta_v_okne.html`). Размер вставленного элемента равен размеру
  того окна — поэтому «насос на весь экран» это нормальное поведение, а не ошибка.
- **Тяни объекты-экземпляры, а не окно.** Перетаскивай из дерева `Насос 1`, `Насос 2`, `Насос 3`
  (они лежат в «Насосной станции») — тогда каждый вставленный элемент привязан к **своему** экземпляру
  и показывает его состояние. Если тащить само окно типа, все три будут показывать одно и то же.
- **Размер вставленного элемента держи равным размеру окна.** Иначе содержимое рисуется не так, как ты
  ожидаешь. Проверить и задать: выделить элемент → «Свойства → **Расположение** → `Ширина`/`Высота`»
  (например `110×100`), либо потянуть за узлы рамки.
- **В редакторе вложенное окно экземпляра выглядит пустой рамкой** — это не ошибка: содержимое окна
  экземпляра наследуется от окна **типа**, а редактор его внутри вложенного элемента не прорисовывает.
  Реальный вид — в **клиенте визуализации** при запуске (проверено 2026-10-12: элементы мнемосхемы
  ссылаются на окна экземпляров `43069/43083/43097`).
- Окно станции по умолчанию — **размер экрана узла** (у нас `1920×1080`), поэтому насосы `110×100`
  на его фоне выглядят мелкими. Для удобства уменьшай **масштаб редактора** (список внизу, например
  `50%`), а не размер окна.
- **Уменьшить/растянуть**: выдели элемент на холсте (вокруг появится рамка и подпись с именем и типом) и
  **потяни за узлы рамки**; с зажатым `Ctrl` — пропорционально (справка `hmi_razmeschenie_elementov.html`).
  Точные числа — в «Свойства → **Расположение** → `Ширина`/`Высота`».
- **Двигать**: мышью или **стрелками клавиатуры** (точная подгонка).
- **Удалить**: выделить элемент **на холсте** (не объект в дереве!) → ПКМ → «Удалить» или `Del`.
- **Перетаскивание с `Alt`** даёт меню выбора: «Вставить вложенное окно», «Вставить кнопку перехода
  на окно», «Вставить кнопку открытия окна» — последнее сразу создаёт кнопку с событием «Клик мыши» →
  «Открыть всплывающее окно».
- Чтобы все насосы были аккуратными, размер удобно задать один раз **в типе**: `Библиотеки → Локальная →
  Объекты → Насос 1 → Ресурсы → Окна → Окно 1` → «Расположение → Ширина/Высота» (например `200×150`) —
  тогда и размещения на мнемосхеме станут такими же.

### 6. Стартовое окно, проверка и запуск

16. **Назначь стартовое окно** — без него проект **не скомпилируется** (ошибка «шаблон экрана … не имеет
    стартового окна»). ПКМ по окну станции (то, что лежит в «Насосной станции»; удобно сначала
    переименовать его в `Мнемосхема` и перетащить в него три насоса) → **«Назначить стартовым окном»**
    → **«Для узла»**. Справка (`startovoe_okno.html`): стартовое окно — это окно, которое открывается
    в браузере при запуске узла; варианты — «Для узла», «Для пользователя», «Для роли»; снять —
    «Убрать из стартовых окон».
17. Компиляция и запуск в эмуляции — как в уроке 04.
18. Понажимай кнопки `Пуск`/`Стоп` у каждого насоса: меняться должен **свой** канал (`DO 1`, `DO 2`,
    `DO 3`). Чтобы увидеть это «по-настоящему», подключи эмулятор Modbus-устройства (модуль 06) — тогда
    значения будут видны в регистрах внешнего источника.

## Проверка (обязательные доказательства)

**В интерфейсе.** Выдели канал → панель **«Свойства»**: слева от свойства, задействованного в связи,
есть кнопка-переключатель (стрелка вправо/влево — входящая/исходящая связь; справка:
`okno_svoystva_otobrajenie_svoystv_zadeystvovannwh_v_svyazyah.html`). Нажми кнопку справа — раскроется
**строка описания связи** с инструментами: «разорвать связь», «перейти к связанному элементу»,
«конвертер значений». Это и есть способ **удалить/поправить** связь руками.

**В БД** (проект лежит в PostgreSQL; имя базы проекта — `ms4d_project_<id>` из реестра):

```sql
-- связи типа «передача значения» (MasterSCADA.ReadValue) с каналами DO*
SELECT s.value AS kanal, l.target_id AS kuda, t.name AS tip_celi
FROM links l
JOIN types t ON t.type_id = (SELECT type_id FROM items WHERE item_id = l.target_id)
LEFT JOIN props_str s ON s.item_id = l.source_id AND s.type_id = 767
WHERE l.type_id = 699 AND s.value LIKE 'DO%';
```

В колонке `tip_celi` будет `MasterSCADA.Attribute` — это **слот связи экземпляра**: у экземпляра в
модели нет внутренностей, есть только такие элементы для подключения к внешнему миру.

## Грабли

| Симптом | Причина | Что делать |
|---|---|---|
| Нет пункта «Заменить наследников на экземпляры» | меню вызвано по объекту в дереве объектов, а не по **библиотечному** элементу | ПКМ по элементу в ветке **Библиотеки → Локальная** |
| На мнемосхеме вставленные окна выглядят пустыми рамками («мелкий насос в квадрате») | элементы ссылаются на окна **экземпляров** (`ViewDeclarationInObjectInstance`) — их содержимое наследуется от окна **типа**, и в редакторе оно не прорисовывается (видна только рамка самого элемента). Проверено в БД 2026-10-12: на мнемосхеме `50110 → 43069`, `50113 → 43083`, `50116 → 43097` | это не ошибка: проверяй в **клиенте визуализации** (компиляция + запуск) — там содержимое рисуется. Размер каждого элемента держи равным размеру окна; чтобы насос был крупнее, увеличивай окно **в типе** (например `200×200`) и картинку внутри него |
| Перетащил насос в окно — он «на весь экран», второй не вставить | перетаскивание объекта вставляет **его первое окно**, и размер элемента равен размеру этого окна (справка: «в него вставляется первое окно тега/канала/объекта») | выдели элемент на холсте и **потяни за узлы рамки** (с `Ctrl` — пропорционально) либо задай `Ширина`/`Высота` в «Расположение»; удобнее один раз уменьшить окно в **типе** (`Насос 1 → Окна → Окно 1`) — тогда все размещения станут аккуратными |
| Не могу удалить элемент с мнемосхемы | выделен не тот объект: элемент на холсте и объект в дереве — разные вещи | выдели **элемент на холсте** (появится рамка и подпись с именем/типом) → ПКМ → «Удалить» или `Del` |
| В панели «Ошибки»: **«Шаблон экрана «Шаблон экрана 1» не имеет стартового окна и будет проигнорирован»** (источник: `Система » АРМ 1 » Шаблон экрана 1`) | у шаблона экрана узла не назначено стартовое окно. Справка: «если ни одно окно не назначено стартовым, то веб-сервер среды исполнения использоваться не будет… клиент визуализации не запустится в автоматическом режиме» | ПКМ по нужному окну → **«Назначить стартовым окном» → «Для узла»** (варианты: «Для пользователя», «Для роли»); снять назначение — «Убрать из стартовых окон». Справка: `startovoe_okno.html` |
| После переноса (`Ctrl+X`/`Ctrl+V`) элементы выглядят «пустыми квадратиками» без стиля | при переносе между окнами **теряются размеры** элементов: остаются координаты (`Designer.Layout.X/Y`), а `Designer.Layout.Width/Height` пропадают. Проверено в БД 2026-10-12: у перенесённых кнопок и овала свойств `751`/`752` нет, у библиотечных «эталонных» кнопок они есть (120×37). Тип вида и связи при переносе сохраняются | выдели элемент → «Свойства» → категория **«Расположение»** → задай **`Ширина`/`Высота`** (для кнопки ориентир 120×37, для индикатора-овала ~40×40) либо потяни за маркеры в редакторе — тогда свойства запишутся сами |
| Не могу изменить окно (в том числе уменьшить): поля серые или ничего не меняется | окно открыто **из экземпляра** — в правом верхнем углу редактора горит **`READ-ONLY`** | открой то же окно **из библиотечного типа** (`Библиотеки → Локальная → Объекты → Насос 1 → Ресурсы → Окна → …`): бейджа не будет, а правка применится ко всем экземплярам |
| Меняю ширину/высоту, а «уменьшается» не то | в панели свойств выделен **элемент** окна (кнопка, овал…), а не само окно | выдели в дереве **узел окна** — тогда в свойствах появится категория **«Расположение»** с `Ширина`/`Высота` |
| Ничего не находит «Поиск…» над деревом | это **фильтр дерева**, а не поиск с переходом: справка («Панель дерева MasterSCADA») — «оставляет видимыми только те элементы, которые в своих настройках имеют символы, находящиеся в текстовом поле». В иерархическом дереве совпавшие листья скрываются вместе с несовпавшими родителями, поэтому результат часто выглядит как «ничего не найдено». Замечено также падение сессии после ввода текста — стек падения лежит в серверной части MS4D (`BranchesService`), к ОС отношения не имеет (**UNVERIFIED** как причина) | искать по веткам вручную; быстрая ориентация — «хлебные крошки» над полотном редактора. Если элементы «исчезли», проверь кнопку **вида дерева** (упрощённый/полный) в панели инструментов дерева |
| Не могу поправить окно/программу у насоса в станции | это **экземпляр** — его структура управляется типом | правь **библиотечный тип**; изменение применится ко всем экземплярам (упражнение ниже) |
| Ищу «Окно»/программу в дереве объектов и не нахожу (или открывается только просмотр) | после тиражирования окна и программы живут **в библиотечном типе**, а экземпляр показывает их только для чтения | открой **Библиотеки → Локальная → Насос 1 → Окна / Программы**. Поиск по дереву объектов их «теряет» именно поэтому |
| В меню по параметру нет «создать связь» | связи создаются **перетаскиванием**, а не командой меню | тяни параметр на приёмник (ЛКМ) |
| Тяну — «не даёт» (курсор «запрещено») | тянешь не от источника к приёмнику, либо элементы из несовместимых мест | тяни `Управляющий выход` (источник) **на канал** (приёмник); открывай деревья в параллельных окнах, в т.ч. через «Открыть в панели веток» |
| У канала «двойная» связь | канал допускает только одну входящую связь | согласиться на **замену** либо «разорвать связь» в панели свойств |
| Адрес канала совпал с другим каналом | дублирование проставило «следующий» адрес, который не совпал с задумкой | задай адреса **явно** (1/2/3) |
| После удаления насоса у канала пропала связь | связи принадлежат экземпляру | это нормально: удалил элементы — свяжи заново (в БД строки `links` тоже исчезли) |
| ПКМ-меню: окно дёргается, меню не открывается | запуск **нативно в Wayland** (Chromium/GTK отдаёт меню в X11 отдельным окном) | запусти среду в **X11-режиме** — разбор в [конспекте Arch+niri, грабля 10b](../../../docs/reference/ustanovka-arch-niri.md) |

## Упражнение: «Изменил тип — поехали экземпляры»

1. Открой **библиотечный** `Насос 1` → `Окна` → переименуй `Окно 1` в `Изображение насоса`.
2. Проверь: имя поменялось у **всех трёх** насосов станции. Это и есть смысл типа.
3. Теперь сделай «особый» насос: ПКМ по экземпляру → **«Заменить на наследника»** (или у библиотечного
   типа — «Разорвать наследование» у наследника) и поменяй только его. Вопрос к себе: почему это
   ломает идею тиражирования и когда так делать правда нужно?
4. Докажи в БД: сколько теперь связей `MasterSCADA.ReadValue` на каналы `DO*`? Должно быть три.

## Критерии «урок пройден»

- [ ] В ветке библиотеки есть тип `Насос 1`, а в дереве объектов — `Насосная станция` с тремя насосами.
- [ ] Все три насоса — **экземпляры** (значок «Ссылается» в свойствах), а не независимые объекты.
- [ ] Каждый канал `DO 1/2/3` имеет **свою** связь с `Управляющий выход` нужного насоса.
- [ ] Вижу и умею **разорвать/переназначить** связь через панель свойств.
- [ ] Изменение в библиотечном типе отражается **во всех** экземплярах.
- [ ] Проект компилируется и запускается в эмуляции; кнопки каждого насоса меняют свой канал.

- [ ] Второе окно `Окно управления` создано **в типе**, кнопки и индикатор перенесены, размер задан через «Расположение → Ширина/Высота», по клику на насос открывается всплывающее окно.
