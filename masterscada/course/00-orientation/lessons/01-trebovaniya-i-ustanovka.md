# Урок 01: Требования, дистрибутив и установка среды разработки

**Цель урока:** понять, что именно требует MasterSCADA 4D 2.0 от машины, разобрать `.deb`
«по кирпичикам» и поставить среду разработки так, как это делает вендор (Astra/Debian), с
оговорённым неофициальным вариантом для остальных дистрибутивов.

**Время:** ~60 мин · **Пререквизиты:** доступ в терминал с `sudo`, ~2 ГБ на диске под установку.

---

## 1. Требования: что нужно машине

Из справки 2.0 (`sistemnwe_trebovaniya_dt.html`):

| Параметр | Минимум | Рекомендуется |
|---|---|---|
| ОС | Windows 10 SP1 x64, **Astra Linux** | Windows 10+ x64, **Astra Linux SE ≥ 1.7 (Воронеж)** |
| CPU | Intel Core i3, 2.3 ГГц | Core i5, 3.4 ГГц+ |
| ОЗУ | 8 ГБ | **16 ГБ+** |
| Дисплей | 1280×1024 | 1920×1080 |
| Диск | 10 ГБ свободно | SSD, 100 ГБ свободно |

Поддерживаются **только 64-битные ОС**. Вендор прямо предупреждает: на минимальной конфигурации
редактор формально поставится, но будет «тормозить при переключении вкладок и работе с деревьями».

> **Разделяй DT и RT.** Среда разработки (**DT**) официально живёт на Windows и Astra Linux SE.
> Среда исполнения (**RT**) — куда шире: Astra, Debian 11, ALT Linux 8.x, РЕД ОС (ядро ≥ 3.18,
> x86/x64/arm/arm64). Поэтому «не поддерживается ОС» почти всегда относится именно к редактору.

## 2. Что лежит внутри `.deb`

Дистрибутив — обычный Debian-пакет (~680 МБ). Разбираем его **до** установки, это же пригодится
для установки на «неродном» дистрибутиве.

```bash
DEB=~/Downloads/MasterSCADA4D_2.0.4_Install.deb      # ← подставь свой путь
ls -lh "$DEB"                                        # ожидаем ~679 МБ, не 0 и без .part
file "$DEB"                                          # Debian binary package (format 2.0)

ar t "$DEB"                                          # debian-binary, control.tar.*, data.tar.*
dpkg-deb -f "$DEB" Package Version Architecture       # имя пакета, версия, архитектура
dpkg-deb -f "$DEB" Depends                            # ← зависимости, самое важное
```

Ожидаемый `Depends` (имена Debian-пакетов):

```
libgtk-3-0, libnotify4, libnss3, libxss1, libxtst6, xdg-utils,
libatspi2.0-0, libuuid1, libsecret-1-0
```

Посмотреть, **куда** пакет всё положит, ничего не устанавливая:

```bash
dpkg-deb -c "$DEB" | awk '{print $6}' | sed 's|^\./||' | cut -d/ -f1-3 | sort -u | head
```

Ожидаем дерево `/opt/MasterSCADA 4D 2.0/` плюс ярлык в `/usr/share/applications/`.

> Полезно знать: имя пакета у релизных сборок — `masterscada4d`, у сборок beta/branch/**rc** —
> с суффиксом (`masterscada4d-rc`). От этого зависит команда удаления (см. §5).

## 3. Установка: основной путь (Astra Linux / Debian-подобные)

Как в справке (`ustanovka_dt_linux.html`):

```bash
sudo apt install /путь/к/MasterSCADA4D_2.0.4_Install.deb
# справка предлагает эквивалент: sudo apt-get install <path_to_deb>
# apt покажет размер, спросит подтверждение — нажать «Д» (да)
```

После установки проверяем **три** вещи:

```bash
ls -d "/opt/MasterSCADA 4D 2.0"                       # каталог установки есть
dpkg -l | grep masterscada                            # пакет в базе dpkg (ii = установлен)
ls /usr/share/applications/ | grep -i masterscada     # ярлык для меню «Разработка»
```

Запуск из терминала (проверяем ещё на этом шаге, что бинарник стартует):

```bash
cd "/opt/MasterSCADA 4D 2.0" && ./MasterSCADA4D_2.0
```

> Если из терминала не запускается — не идём дальше, разбираемся здесь (урок 02, раздел
> «Диагностика»). Ярлык в меню — та же команда плюс флаги из `.desktop`.

## 4. Вариант: не-Debian дистрибутив (Arch, Fedora, …)

Вендор такой путь не поддерживает, но пакет остаётся архивом, и его можно распаковать вручную.
Смысл варианта — «посмотреть/поучиться, не трогая систему»:

```bash
# Вариант «без установки»: распаковать в /tmp и запускать оттуда
mkdir -p /tmp/ms4d && cd /tmp/ms4d
ar p ~/Downloads/MasterSCADA4D_2.0.4_Install.deb data.tar.xz | tar -xJ
ls "opt/MasterSCADA 4D 2.0/" | head

# Вариант «поставить в систему» (нужен root, кладёт ровно то же дерево, что dpkg -x)
sudo sh -c 'ar p /путь/к/MasterSCADA4D_2.0.4_Install.deb data.tar.xz | tar -xJ -C /'
```

Чего при этом **не** появляется: записи в базе dpkg, автоматической установки зависимостей,
ярлыка в меню. Зависимости из §2 придётся сопоставить с пакетами своего дистрибутива и поставить
самому, а нехватку библиотек проверять так:

```bash
ldd "/opt/MasterSCADA 4D 2.0/MasterSCADA4D_2.0" | grep 'not found'      # пусто = всё на месте
ldd "/opt/MasterSCADA 4D 2.0/resources/MasterSCADA4D_Server/MasterSCADA4D_Server" | grep 'not found'
```

`grep 'not found'` не показывает ничего — значит, отображать и запускать будет чем. Если строки
есть — ставь соответствующие библиотеки своего дистрибутива (для Arch соответствия:
`libgtk-3-0→gtk3`, `libnss3→nss`, `libxss1→libxss`, `libxtst6→libxtst`, `libatspi2.0-0→at-spi2-core`,
`libsecret-1-0→libsecret`, `libnotify4→libnotify`, `libuuid1→util-linux`, `xdg-utils→xdg-utils`).

> Проверенный пример такого запуска (Arch + Wayland/niri) — в конспекте
> [`../../../docs/reference/ustanovka-arch-niri.md`](../../../docs/reference/ustanovka-arch-niri.md).
> Это **не** вендорская конфигурация: возможны сюрпризы, поддержки не будет.

## 5. Обновление и удаление

Справка (`udalenie_dt_linux.html`): обновление = **удалить и поставить заново**.

```bash
dpkg -l | grep masterscada                    # узнать точное имя пакета (у нас — masterscada4d-rc)
sudo apt remove masterscada4d                 # релизная сборка
sudo apt remove masterscada4d-rc              # сборка rc/beta/branch
```

Удаление пакета **не** трогает пользовательские данные: настройки и логи остаются в
`~/.config/` (см. урок 02, §4). Проекты же лежат в PostgreSQL — их удаление пакета вообще
не касается (урок 03).

## 6. Проверка себя (чеклист урока)

- [ ] Знаю минимальные и рекомендуемые требования и почему 16 ГБ — это «рекомендуется», а не «на всякий случай».
- [ ] Понимаю разницу «DT vs RT» по поддерживаемым ОС.
- [ ] `dpkg-deb -f $DEB Depends` показывает список зависимостей, а `dpkg-deb -c $DEB` — дерево `/opt`.
- [ ] На поддерживаемой ОС: `dpkg -l | grep masterscada` → `ii`, каталог `/opt/MasterSCADA 4D 2.0` на месте.
- [ ] Знаю, какой командой удалить именно **свою** сборку (с суффиксом или без).
- [ ] Знаю, где искать «чего не хватает»: `ldd … | grep 'not found'`.

## 7. Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `ar p … \| tar -xJ` молчит / «неожиданный конец файла» | `.deb` скачан не полностью (`*.part`) | Проверить размер (`ls -lh`), докачать |
| `xz: Cannot exec` | нет утилиты `xz` | Поставить `xz` своим пакетным менеджером |
| `apt` не видит пакет по пути | передан относительный путь или файл недоступен пользователю | Использовать абсолютный путь; `sudo apt install ./file.deb` |
| Установка «прошла», ярлыка нет | сборка с суффиксом, ярлык называется иначе | `ls /usr/share/applications/ \| grep -i masterscada` |
| Приложение падает на старте с «error while loading shared libraries» | не хватает библиотек (§4) | `ldd … \| grep 'not found'` и доставить |

## 8. Задание

1. Выведи `Depends` и `Architecture` своего `.deb` одной командой и сохрани вывод.
2. Докажи, **не устанавливая** пакет, что внутри дерево `/opt/MasterSCADA 4D 2.0`.
3. Установи среду разработки и приведи три доказательства установки из §3.
4. Назови команду удаления для **твоей** сборки и обоснуй суффикс.
