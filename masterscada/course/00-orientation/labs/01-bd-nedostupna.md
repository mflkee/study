# Лаба 01: «БД недоступна» — сломай и почини

**Цель:** своими глазами увидеть, как отсутствие СУБД проявляется на трёх уровнях (GUI редактора →
лог IDE → сервер БД) и научиться строить причинно-следственную связь, а не «перезапускать, пока не
заработает».

**Время:** ~40 мин · **Пререквизиты:** уроки 01–03; желательно проект из урока 04.

> Лаба учебная: мы ломаем стенд из [`../infra/`](../infra/README.md). **Никогда** не проделывай
> такое на рабочей БД — там остановка сервера = остановка объекта.

---

## Часть 1. Базовая линия (всё работает)

1. Убедись, что стенд поднят и отвечает:

   ```bash
   cd course/00-orientation/infra
   docker compose ps                                   # Up (healthy)
   docker compose exec -T postgres psql -U course -d course -c "SELECT version();"
   ```

2. В редакторе открой/создай проект и **сохрани** его. Запиши, что видишь на экране (сообщение об
   успехе). Это твоя «норма» для сравнения.

   Вариант A (системный PostgreSQL): вместо `docker compose …` используй
   `systemctl status postgresql` и `psql -h localhost -U postgres`.

## Часть 2. Ломаем

Останавливаем **только** СУБД, IDE не трогаем:

```bash
docker compose stop                    # вариант B
# sudo systemctl stop postgresql       # вариант A
docker compose ps                      # статус: Exited / Stopped
```

## Часть 3. Наблюдаем и объясняем

1. Всё ещё запущенный редактор: попробуй **сохранить** проект, затем **создать новый**.
   Зафиксируй **дословно**, что показывает GUI.
2. Найди ту же проблему в логе IDE (минуты — свежие строки в конце):

   ```bash
   tail -n 40 ~/.config/MPSSoft/MasterSCADA4D_DT_2.0/sys_log/$(date +%Y_%m_%d).log
   ```

   Ожидаемое (пример с нашего стенда):

   ```
   System.InvalidOperationException: Ошибка подключения:
   Connection refused (Проверьте правильность введённых данных для подключения)
      at InSAT.Framework.DbStore.Services.Store.PostgreSql.PostgreSqlStoreService…
   ```

3. Ответь на вопросы (письменно, одной строкой каждый):
   - Почему сообщение «Connection refused», а не «нет прав»?
   - Что было бы в логе, если бы сервер работал, но у роли не было прав на создание БД?
   - Почему IDE не «положила проект в очередь и пошла дальше», а сразу ошиблась?

## Часть 4. Чиним

```bash
docker compose start
docker compose exec -T postgres pg_isready -U course -d course     # accepting connections
```

Снова сохрани/создай проект в редакторе — операция должна пройти без перезапуска самого редактора.
Если редактор всё же кэширует состояние — переоткрой проект и зафиксируй это как факт (это тоже
знание: «что требует перезапуска, а что нет»).

## Часть 5. Усложнение (на выбор, но лучше сделать)

**5a. Не тот порт.** Поменяй в `.env` `PG_PORT=15445`, выполни `docker compose up -d`, а в
настройках IDE порт оставь прежним. Симптом тот же — `Connection refused`. Найди несоответствие и
приведи к одному значению. Мораль: «refused» чаще всего означает **не тот порт**, а не «сервер умер».

**5b. Не те права.** Верни стенд на 15444 и выдай себе «плохую» роль:

```bash
docker compose exec -T postgres psql -U course -d course \
  -c "ALTER ROLE course NOCREATEDB;" \
  -c "SELECT rolcreatedb FROM pg_roles WHERE rolname='course';"     # → f
```

Попробуй создать проект. Ожидаемое: соединение проходит, но ошибка иная —
`permission denied to create database`. Верни как было (`ALTER ROLE course CREATEDB;`) и проверь.
Мораль: **связь ≠ доступ ≠ права** — три разных слоя.
