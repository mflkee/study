# AGENTS.md — как работать с этим каталогом (инструкция для ИИ-ассистента)

Этот каталог — учебный стенд по **MasterSCADA 4D 2.0** (среда разработки DT 2.0) на
Arch Linux + Wayland/niri. Здесь живут: установочные артефакты, конспекты, офлайн/онлайн
документация и курс обучения (`course/`).

> Читай этот файл первым. Он объясняет, **где брать документацию** и **как проверять факты**,
> чтобы не выдумывать API и не путать версии линейки 1.3.x и 2.0.

## 2. Технологический стек (проверено вскрытием `.deb`)

Среда разработки — это **не монолит**, а связка из трёх частей. Это важно: определяет,
что она переносима на любой Linux x64, а не только на Astra.

| Слой | Технология | Расположение |
|---|---|---|
| UI/редактор | **Electron 28.3.3** (Chromium 120.0.6099.291) | `MasterSCADA4D_2.0` + `resources/app.asar` |
| Ядро RT/сервер | **.NET 8.0 (CoreCLR, self-contained)** | `resources/MasterSCADA4D_Server/` |
| Драйверы/плагины | C++ (**Boost 1.86**), SQLite, soci | `.../MasterSCADA4D_Server/Config/MasterPLC/linux/*.so` (138 `.so`) |
| БД проектов | **PostgreSQL ≥ 10** | внешний сервер |

Зависимости `.deb` (все штатные, есть в Arch через `pacman`):
`libgtk-3-0 libnotify4 libnss3 libxss1 libxtst6 xdg-utils libatspi2.0-0 libuuid1 libsecret-1-0`
(+ recommends `libappindicator3-1`).
Требования к glibc мизерные: Electron — `GLIBC_2.17`, CoreCLR — `GLIBC_2.16`;
единственное «свежее» — `GLIBCXX_3.4.32` (GCC 13+, в Arch есть).

## 4. Ключевые факты (чтобы не ошибаться)

- **Официально поддерживаемые ОС среды разработки DT 2.0:** Windows 10+, **Astra Linux SE 1.7x / 1.8x**.
- **Фактически:** Electron-пакет запускается и на **Arch + niri/Wayland** (проверено, см. `course/00-orientation/lessons/02-*`). Это **не** поддерживаемая вендором конфигурация — потенциальные проблемы возможны и официальной поддержки не будет.
- **Среда исполнения (RT)** официально поддерживает Linux шире: AstraLinux, Debian, AltLinux, РЕД ОС (ядро ≥ 3.18, x86/x64/arm/arm64).
- **Работа в виртуальной машине** разрешена, но вендор **не гарантирует** производительность.
- **Разработка** — только через среду разработки (DT). На Linux исторически RT-only; DT 2.0 — первый кроссплатформенный редактор (это бета).
- **Лицензии:** среда разработки бесплатна; лицензируется число внешних каналов/клиентов. RT — демо 1 час (`RT Demo`) или по ключу.

## 5. PostgreSQL — обязателен
В DT 2.0 **все проекты сохраняются в PostgreSQL** (в 1.3.x было в файлах). Версия ≥ 10,
вендор рекомендует свежую; в инструкции — **PostgresPro 1C-14**. См. тему
`ust_postgresql_linux.html`. Для курса поднимаем PostgreSQL в Docker (изолированно от хоста).

## 6. Конвенции курса (`course/`)

- Модули идут строго по номерам: `NN-название/`. Каждый модуль: `README.md` (цели+чеклист),
  `theory.md` (конспект), `lessons/` (пошаговые уроки), `examples/`, `exercises/`
  (решения в `solutions/`), `labs/`.
- Соотношение **30% чтения / 70% практики**. Каждый урок заканчивается заданием.
- Факты о версиях/горячих клавишах/меню — **только из справки**, не выдумывать. Если
  утверждение не проверено на стенде — пометить **`UNVERIFIED`**.
- Прогресс — в [`course/PROGRESS.md`](course/PROGRESS.md).

## 7. Правила для ИИ-ассистента
1. Перед ответом про интерфейс/функции SCADA — **сверься со справкой** (см. §3.1), не полагайся на память.
2. Не смешивай версии: 2.0 (DT, PostgreSQL-проекты) ≠ 1.3.x (старая веб-справка).
3. Правки — в файлы этого каталога; приложение и систему без спроса не трогать.
4. Всё, что запускалось/проверялось — фиксировать (команда + результат), отмечать `UNVERIFIED` иначе.
5. Коммиты в репозиторий `study` — по явной просьбе.
