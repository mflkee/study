# Глава 15. Что это значит для прошивки на Rust

> [Вернуться к карте глав](README.md)

Аппаратная архитектура почти напрямую диктует структуру прошивки. Ниже —
сопоставление «что на плате → что в коде» (актуальное для текущего каркаса
`ai32/`), и практические следствия из глав 6–7.

## Плата → код

| Модуль в прошивке | За что отвечает | Что ему даёт этот документ |
|---|---|---|
| `fw/src/ads1256.rs` | Инициализация общей SPI2/HSPI (Mode 1, CPOL=0, CPHA=1), драйвер 3× ADS1256: WREG MUX (выбор входа), задержка установления, RDATA (24 бита); выбор кристалла CS0..CS2 (GPIO10/9/8) | таблица выводов, режим SPI, протокол чтения ([глава 10](10-ads8681-spi.md)), разложение канала на чип/вход ([глава 9](09-multiplexer.md)) |
| `fw/src/main.rs` (цикл сканирования) | Планировщик опроса: 24 канала, выбор CS + вход, выдержка установления перед оцифровкой, усреднение выборок | временны́е рамки ([глава 6](06-opa320.md)), скорость потока ([глава 10](10-ads8681-spi.md)) |
| `core/src/calib.rs` | Хранение (a, b) на каждый канал, применение `I = a·N_raw + b`, пересчёт кода в физические единицы | формула калибровки ([глава 13](13-pcb-calibration.md)), LSB ([глава 7](07-adc-scaling.md)) |
| `fw/src/config_store.rs` | (a, b) каждого канала в NVS (flash ESP32) | хранение в энергонезависимой памяти ([глава 13](13-pcb-calibration.md)) |
| temp_comp (опционально) | Чтение бортового датчика температуры, поправка через таблицу | температурная компенсация ([глава 13](13-pcb-calibration.md)) |
| `fw/src/rtu_slave.rs` | Modbus RTU slave по RS-485 (UART + трансивер MAX3485): ток каналов как INPUT-регистры (float32), калибровка как HOLDING (read-only), включение как COIL | интерфейс RS-485, типы регистров (глоссарий) |

> RTU по RS-485. В `core/` нет `mbap.rs`, в `fw/` нет `modbus_tcp.rs`.

## Практические следствия из глав 6–7, важные для кода

- после переключения канала (выбор CS + вход) перед чтением АЦП нужно подождать
  **время установления**. Для дельта-сигма АЦП это не микросекунды (как у SAR),
  а как минимум пара периодов цифрового фильтра — в каркасе `SETTLE_US = 1000`
  после `select_channel` — `ads1256.rs`;
- формат выдачи в ИВК: ток в мА (значение `f32` в 32-битном INPUT-регистре
  укладывается легко: LSB ≈ 0,00185 мкА ≪ 0,01 мА) либо код калиброванной
  физической величины. Каркас отдаёт `f32` тока по 2 регистра на канал —
  `core/src/register_map.rs`;
- `channel = (chip << 3) | input` — тот же номер канала во всех слоях: выбор
  кристалла CS, вход внутри АЦП, регистр Modbus, калибровочные коэффициенты
  (`fw/src/ads1256.rs`, `core/src/channels.rs`, `core/src/register_map.rs`);
- код АЦП теперь `u32` (24 бита), а не `u16`: интерфейс `AdcBackend::read_code`
  возвращает `u32` во всём коде (`fw/src/adc_backend.rs`,`fw/src/sim.rs`).

## Связано с кодом

- расположение модулей — `fw/src/*.rs` и `core/src/*.rs`;
- точка входа и потоки — `fw/src/main.rs`;
- состав и смысл фичи `sim` — `fw/Cargo.toml`,
  `.cargo/config.toml` (target + build-std), `build.rs` (embuild).
