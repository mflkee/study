# AI-32 — модуль аналогового ввода 4–20 мА (24 канала)

Учебный проект: **ESP32-S3** (плата HW-678) читает **24 канала** тока
**4–20 мА** и отдаёт их в ИВК по **Modbus RTU via RS-485**. Каналы — на трёх
24-битных АЦП **ADS1256** (по 8 каналов на чип) на **общей SPI-шине** без
мультиплексоров; выбор кристалла — тремя GPIO (CS0..CS2). Есть **sim-режим**:
вся логика работает на столе без железа.

```
Датчики 4..20 мА
     │   (24 канала: 3 × 8)
     ▼
 [ADS1256 ×3] ── общая SPI ─► [ESP32-S3] ── Modbus RTU ── RS-485 ─► [ИВК]
     │                        ▲
     └─ CS0/CS1/CS2 (GPIO10/9/8) ─┘
```

## Структура проекта

| Каталог      | Что это                                                                 |
|--------------|-------------------------------------------------------------------------|
| `core/`      | **чистое ядро без железа**: калибровка, карта регистров, CRC. `cargo test` — 16 тестов. [Документация](core/src/lib.rs) |
| `fw/`        | **прошивка ESP32**: backend АЦП (3×ADS1256), sim-датчики, RTU-slave по RS-485, NVS-калибровка |
| `docs/`      | **инженерный разбор** — [иерархия глав](docs/README.md) (16 глав), [распиновка](docs/PINMAP.md) |
| `scripts/`   | ИВК-клиент ([`ive_client.py`](scripts/ive_client.py))                  |

Два крейта — это намеренное разделение «логика ↔ железо»:

| Крейт   | Содержимое                                      | Как проверяется         |
|---------|-------------------------------------------------|-------------------------|
| `ai32-core` | калибровка, каналы, Modbus PDU, CRC | обычный `cargo test` на ПК |
| `ai32-fw`   | SPI, GPIO, 3×ADS1256, RTU по RS-485, NVS на ESP32 | `cargo +esp check` (два режима) |

Прошивка **вызывает чистое ядро** (`register_map::dispatch`, `crc`) —
та самая логика, что покрыта тестами.

## Быстрый старт

### 1) Ядро — тесты на любом ПК

```sh
cd ai32/core && cargo test
# 16 passed; 0 failed
```

Зависимости — только стандартная библиотека, поэтому собирается на любой
машине без embedded-тулчейна.

### 2) Прошивка — sim и реальное железо

Требуется тулчейн `esp` (nightly с build-std) + IDF v5.3 — как в
`test-bench/esp32-fw`. Файл `fw/rust-toolchain.toml` подхватывает его
**автоматически**, поэтому `cargo +esp` можно даже не набирать:

```sh
cd ai32/fw
cargo check                        # sim (по умолчанию) — АЦП имитируется
cargo check --no-default-features  # реальный SPI/GPIO (3×ADS1256)
cargo +esp build --release         # собрать прошивку
```

Что меняет фича `sim` (`fw/Cargo.toml`):

- **с `sim`** (умолчание): `main.rs` берёт `SimAdc` — каналы имитируют синусы
  4.8..19.2 мА, RTU-slave отдаёт их по RS-485, ИВК показывает «живые» данные
  **без железа**;
- **без `sim`**: `main.rs` инициализирует общую шину SPI2 (SCLK=12, MOSI=11,
  MISO=13) и три CS-ноги GPIO10/9/8 (по чипу на каждые 8 каналов) — реальная
  плата.

### 3) ИВК-клиент

```sh
python3 ai32/scripts/ive_client.py /dev/ttyUSB0 --baud 9600          # разовый опрос + демо
python3 ai32/scripts/ive_client.py /dev/ttyUSB0 --baud 9600 poll     # цикл каждые 2 с
```

Клиент умеет функции FC01/03/04/05/06 по RTU (CRC16, slave id 1) — это готовый
«тестер» для карты регистров через обычный USB-RS485 адаптер.

## Как читать проект

**Маршрут «программист прошивки»:**

1. **Ядро снизу вверх** — от физики к протоколу, файлы идут в этом порядке:
   - [`core/src/calib.rs`](core/src/calib.rs) — код АЦП → мА (калибровка),
     физика глав 3/7 документации;
   - [`core/src/channels.rs`](core/src/channels.rs) — 24 канала: ток + флаг;
   - [`core/src/register_map.rs`](core/src/register_map.rs) — карта Modbus
     FC01..FC06, диспетчер;
   - [`core/src/crc.rs`](core/src/crc.rs) — CRC16 для RTU.
2. **Документация по железу** — [`docs/README.md`](docs/README.md) (карта глав),
   маршрут: главы **1 → 2 → 7 → 9 → 10 → 15**.
3. **Прошивка**:
   - [`fw/src/main.rs`](fw/src/main.rs) — потоки, банк `Arc<RwLock>`, цикл скана;
   - [`fw/src/ads1256.rs`](fw/src/ads1256.rs) — 3 чипа 24-бит на общей SPI-шине;
   - [`fw/src/rtu_slave.rs`](fw/src/rtu_slave.rs) — Modbus RTU slave (RS-485);
   - [`fw/src/config_store.rs`](fw/src/config_store.rs) — NVS-калибровка (FFI).

Маршрут «инженер» — все 16 глав подряд, начиная с [01-overview.md](docs/01-overview.md).
Для обучения: курс **[`course/09-ai32-module/`](../course/09-ai32-module/README.md)** —
пособие поверх этого кода (теория + лабораторные + упражнения).

## Карта регистров Modbus

| Функция | Тип     | Регистры | Значение                                    |
|---------|---------|----------|---------------------------------------------|
| FC04    | INPUT   | 0..47    | ток по каналу, `f32` (2 регистра на канал, мА) |
| FC03    | HOLDING | 0..95    | калибровка `gain`(2)+`offset`(2), read-only |
| FC01    | COIL    | 0..23    | включён ли канал (1 = да)                   |
| FC02    | DISCR   | 0..23    | копия COILS (совместимость)                 |
| FC05    | запись  | coil     | включить/выключить канал                    |
| FC06    | запись  | holding  | всегда exception 0x04 (калибровка через NVS) |

Детали (порядок байт, исключения, пакование f32) — в
[`core/src/register_map.rs`](core/src/register_map.rs) и его тестах.

## Частые проблемы и их решения

| Проблема | Причина | Решение |
|----------|---------|---------|
| `can't find crate for core` при `cargo check` | стабильный rust без `-Zbuild-std` | рядом есть `rust-toolchain.toml` — он сам зовёт тулчейн `esp`; убедитесь, что он установлен (`rustup toolchain install esp`) |
| Собралось с `sim`, а надо железо | не отключили фичу | добавляйте `--no-default-features` |
| Modbus не отвечает из стенда | ИВК-клиент и модуль на разных линиях/скоростях | проверьте baud (9600), slave id (1) и пару A/B витой пары |
| Коды кажутся «случайными» в sim | так и задумано | это синусы: каждый канал — свой период/фаза (`fw/src/sim.rs`) |
