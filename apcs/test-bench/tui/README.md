# TUI — универсальный терминальный интерфейс стенда

Один пульт для всех задач тестового стенда ESP32 Modbus RTU — без X-сервера
и браузера, работает в обычном терминале (Linux/macOS/Windows).

> **📚 Учебная документация**:
> - `DOCUMENTATION.md` — протокол Modbus и интерфейс TUI: архитектура,
>   туториал, упражнения, отладка и частые ошибки.
> - `docs/` — разбор **исходного кода на Rust** по файлам (структура,
>   CRC/кадры, мастер, эмулятор, потоки, TCP, app/ui, прошивка) + практика
>   по написанию кода. Начните с [`docs/00-index.md`](docs/00-index.md).

```
test-bench/tui/
├── Cargo.toml
└── src/
    ├── main.rs        # точка входа, цикл событий, хоткеи (hotkeys — горячие клавиши)
    ├── app.rs         # состояние приложения, действия
    ├── ui.rs          # отрисовка всех вкладок (tabs)
    ├── worker.rs      # фоновые потоки (threads): сканирование портов + опрос
    ├── discover.rs    # hotplug-детекция ESP32 (VID/PID + Modbus-пробинг)
    ├── master.rs      # Modbus RTU мастер (опрос по USB/RS-485)
    ├── tcp_master.rs  # Modbus TCP мастер (MBAP-клиент, опрос по Ethernet)
    ├── tcp_server.rs  # Modbus TCP сервер (отдаёт карту эмулятора)
    ├── emulator.rs    # встроенный эмулятор устройств и датчиков
    ├── frames.rs      # сборка/разбор Modbus-кадров (frames)
    ├── crc.rs         # CRC-16 Modbus (Cyclic Redundancy Check)
    └── firmware.rs    # espflash/esptool: flash / backup / restore
```

## Возможности

- **Вкладки** (tabs): Dashboard, Ports, Registers, Sensors, Firmware, Bus, Log, Help.
- **Bus (лог шины, bus trace)**: каждая Modbus-транзакция (transaction) по
  реальной шине (или эмулятору) показана как сырые байты RTU (Remote Terminal
  Unit) (`→` запрос/request, `←` ответ/response) с CRC и временем в мс;
  в эмуляторе кадры строятся из реальных данных устройств — те же байты, что
  пойдут и по железу. Прочитав их, вы в точности понимаете, что будет видеть
  в шине будущий мастер (PLC/Zynq).
- **Hotplug** (горячее подключение): авто-обнаружение ESP32 при
  подключении/отключении USB.
- **Автоподключение** (autoconnect): при появлении ESP32 интерфейс сам
  начинает опрос (polling).
- **Эмулятор** (emulator): встроенный «тестовый сервер» — 4 устройства
  (насосная станция, тест-девайс, электрокотёл, метеостанция) с
  виртуальными датчиками (sensors; температура, давление, расход, уровень,
  влажность и др.) с плавающими значениями; не нужен ни порт, ни ESP32: `[e]`.
- **Редактор регистров**: чтение/запись input-регистров, holding-регистров
  и катушек по любому источнику (эмулятор или реальное устройство);
  результат операции виден прямо в панели (включая ошибки «нет цели»).
- **Фабрика датчиков и устройств**: добавление виртуальных датчиков (форма) и
  создание/удаление целых слейв-устройств (режим управления `[m]`).
- **Modbus TCP сервер** (`[t]` на Ports): TUI сам становится slave и отдаёт
  ту же карту эмулятора по Ethernet (future Zynq/PLC читают без RS-485).
- **Modbus TCP мастер** (правая панель Ports): TUI подключается к внешнему
  устройству (ваш AI-32 или собственный TCP-сервер) и опрашивает его как
  обычный мастер — поток входа 0..63 (32×float32), катушки, holding.
  Обе роли Modbus (master — мастер и slave — ведомый) живут в одном
  интерфейсе — удобно для отладки и обучения.
- **Переключение катушек** (coils — дискретные выходы) с дашборда
  (dashboard — приборная панель) пробелом; список устройств прокручивается
  сам, PgUp/PgDn — по странице.
- **Мышь**: переключение вкладок кликом, выбор строк/полей кликом, колесо
  листает Dashboard и историю Bus/Log/Help.
- **Firmware Manager**: board-info (сведения о плате), прошивка тестовой
  прошивки, резервная копия (backup) текущей прошивки ESP32 и восстановление
  (restore) из бэкапа.
- Кроссплатформенность: `crossterm` + `ratatui`, на Windows подойдёт
  Windows Terminal / PowerShell ISE.

## Сборка и запуск

```bash
cd test-bench/tui
cargo run --release        # или: cargo build --release
```

Проверки:

```bash
cargo test    # 35 тестов (и 2 ignored live-теста): CRC, кадры, эмулятор,
              # формы, навигация, удаление, мышь, TCP master ⇄ TCP server
cargo clippy  # 0 предупреждений
```

| `d` | отключиться |
| `p` | Modbus-пробинг порта (какой slave отвечает) |
| `t` | вкл/выкл Modbus TCP сервер (эмулятор по Ethernet) |
| **Ports: Modbus TCP master** | |
| `←`/`→` | выбор поля формы (Host / Port) |
| `Enter` | редактировать поле (`Esc` — отмена) |
| `y` | подключиться к Host:Port (unit = Slave ID формы регистров) |
| `o` | отключиться |
| **Registers** | |
| `1` / `2` / `3` | тип: input / holding / coils |
| `r` | прочитать |
| `w` | записать |
| `t` | циклически сменить тип |
| `↑/↓` | выбор поля формы |
| `Enter` | редактировать поле, сохранить (`Esc` — отмена) |

| `↑/↓` | выбор поля формы |

| `m` | режим управления: список активен (заголовки ◆ и датчики ●) |

| `d` (в manage) | удалить датчик ● или целое устройство ◆ под курсором |

| *(последнее устройство защищено от удаления)* | |
| **Dashboard** | |
| `↑/↓` или `k/j` | выбор устройства (маркер `▸`); список прокручивается сам |

| `Space` | переключить первую катушку выбранного устройства |
| колесо (Dashboard) | прокрутка всего списка построчно (многодатчиковый slave влезает целиком) |
| **Log / Help** | |

| **Мышь** | |
| клик по вкладке | переключение вкладки |
| клик по строке/полю | выбор устройства, порта, датчика, поля формы, бэкапа |

## Потоки данных (что откуда берётся)

1. **Enable emulator `[e]`** → Worker начинает опрашивать встроенный
   эмулятор (`emulator.rs`) → снапшот (snapshot — срез данных) на Dashboard.
   Порт не нужен.
2. **Подключение порта `[c]`** → подключается SerialMaster → Worker
   опрашивает реальное устройство Modbus RTU → снапшот на Dashboard.
3. **Hotplug** → Scanner (в фоне) находит ESP32 по VID и добавляет её
   в список портов; при автоподключении опрос стартует сам.
4. **Register editor** → посылает запрос (эмулятору, RTU master'у по порту
   или TCP master'у — что подключено) и показывает ответы/исключения
   (exceptions) в логе.
5. **TCP мастер `[y]`** → подключается к внешнему Modbus TCP устройству
   (AI-32, стенд) → Worker опрашивает его с MBAP-заголовками → снапшот
   на Dashboard; кадры в Bus помечены `TCP`.

## Требования к инструментам для Firmware-вкладки

`espflash` (или `esptool` из pip) для прошивки/бэкапа:

```bash
cargo install espflash
# или
pip install esptool
```
