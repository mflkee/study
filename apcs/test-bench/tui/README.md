# TUI — универсальный терминальный интерфейс стенда

Один пульт для всех задач тестового стенда ESP32 Modbus RTU — без X-сервера
и браузера, работает в обычном терминале (Linux/macOS/Windows).

> **📚 Учебная документация**: `DOCUMENTATION.md` — архитектура, разбор каждого
> файла, туториал по Modbus, упражнения для самостоятельной работы,
> отладка и частые ошибки с примерами кода.

```
test-bench/tui/
├── Cargo.toml
└── src/
    ├── main.rs        # точка входа, цикл событий, хоткеи
    ├── app.rs         # состояние приложения, действия
    ├── ui.rs          # отрисовка всех вкладок
    ├── worker.rs      # фоновые потоки: сканирование портов + опрос
    ├── discover.rs    # hotplug-детекция ESP32 (VID/PID + Modbus-пробинг)
    ├── master.rs      # Modbus RTU мастер (опрос по USB/RS-485)
    ├── emulator.rs    # встроенный эмулятор устройств и датчиков
    ├── frames.rs      # сборка/разбор Modbus-кадров
    ├── crc.rs         # CRC-16 Modbus
    └── firmware.rs    # espflash/esptool: flash / backup / restore
```

## Возможности

- **Вкладки**: Dashboard, Ports, Registers, Sensors, Firmware, Help.
- **Hotplug**: авто-обнаружение ESP32 при подключении/отключении USB.
- **Автоподключение**: при появлении ESP32 интерфейс сам начинает опрос.
- **Эмулятор**: встроенный «тестовый сервер» — 4 устройства (насосная
  станция, тест-девайс, электрокотёл, метеостанция) с виртуальными датчиками
  (температура, давление, расход, уровень, влажность и др.) с плавающими
  значениями; не нужен ни порт, ни ESP32: `[e]`.
- **Редактор регистров**: чтение/запись input-регистров, holding-регистров
  и катушек по любому источнику (эмулятор или реальное устройство);
  результат операции виден прямо в панели (включая ошибки «нет цели»).
- **Фабрика датчиков и устройств**: добавление виртуальных датчиков (форма) и
  создание/удаление целых слейв-устройств (режим управления `[m]`).
- **Переключение насосов** (катушки) с дашборда пробелом.
- **Firmware Manager**: board-info, прошивка тестовой прошивки, резервная
  копия текущей прошивки ESP32 и восстановление из бэкапа.
- Кроссплатформенность: `crossterm` + `ratatui`, на Windows подойдёт
  Windows Terminal / PowerShell ISE.

## Сборка и запуск

```bash
cd test-bench/tui
cargo run --release        # или: cargo build --release
```

Проверки:

```bash
cargo test    # 22 теста: CRC, кадры, эмулятор, формы, навигация, удаление
cargo clippy  # без ошибок
```

## Хоткеи

| Клавиша | Действие |
|---------|----------|
| `Tab` / `Shift+Tab` | переключение вкладок |
| `F1` | справка (Help) |
| `e` | вкл/выкл встроенный эмулятор (тест-сервер) |
| `R` | повторное сканирование портов |
| **Ports** | |
| `↑/↓` или `k/j` | выбор порта |
| `c` | подключиться к выбранному порту |
| `d` | отключиться |
| `p` | Modbus-пробинг порта (какой slave отвечает) |
| **Registers** | |
| `1` / `2` / `3` | тип: input / holding / coils |
| `r` | прочитать |
| `w` | записать |
| `t` | циклически сменить тип |
| `↑/↓` | выбор поля формы |
| `Enter` | редактировать поле, сохранить (`Esc` — отмена) |
| **Sensors** | |
| `1`..`6` | тип датчика: T°C / Pressure / Flow / Test / Level / Humidity |
| `↑/↓` | выбор поля формы |
| `Enter` | редактировать поле, сохранить (`Esc` — отмена) |
| `a` | добавить датчик в эмулятор |
| `n` | создать новое (пустое) слейв-устройство "Device N" |
| `m` | режим управления: список активен (заголовки ◆ и датчики ●) |
| `↑/↓` (в manage) | перемещение по всем строкам списка, с заворотом |
| `d` (в manage) | удалить датчик ● или целое устройство ◆ под курсором |
| `Esc` (в manage) | выйти из режима управления |
| *(последнее устройство защищено от удаления)* | |
| **Dashboard** | |
| `↑/↓` или `k/j` | выбор устройства (маркер `▸`) |
| `Space` | переключить насос выбранного устройства |
| **Firmware** | |
| `i` | board-info |
| `f` | прошить тестовую прошивку |
| `b` | backup текущей прошивки |
| `o` | restore выбранного бэкапа |
| `↑/↓` | выбрать бэкап |
| **Все вкладки** | |
| `q` / `Esc` / `Ctrl+C` | выход |

## Потоки данных (что откуда берётся)

1. **Enable emulator `[e]`** → Worker начинает опрашивать встроенный
   эмулятор (`emulator.rs`) → снапшот на Dashboard. Порт не нужен.
2. **Подключение порта `[c]`** → подключается SerialMaster → Worker
   опрашивает реальное устройство Modbus RTU → снапшот на Dashboard.
3. **Hotplug** → Scanner (в фоне) находит ESP32 по VID и добавляет её
   в список портов; при автоподключении опрос стартует сам.
4. **Register editor** → посылает запрос (эмулятору или master'у) и
   показывает ответы/исключения в логе.

## Требования к инструментам для Firmware-вкладки

`espflash` (или `esptool` из pip) для прошивки/бэкапа:

```bash
cargo install espflash
# или
pip install esptool
```
