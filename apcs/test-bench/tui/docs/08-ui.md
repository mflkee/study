# 08. Рисование и главный цикл: `ui.rs` + `main.rs`

## `main.rs` — точка входа и цикл (322 строки)

### `main` (`main.rs:25-32`)

```rust
let mut terminal = ratatui::init();
crossterm::execute!(std::io::stdout(), EnableMouseCapture)?;
let res = run(&mut terminal);
crossterm::execute!(std::io::stdout(), DisableMouseCapture)?;
ratatui::restore();
res
```

`ratatui::init()` включает alternate screen (вторичный/альтернативный буфер
терминала, как в `less`/`vim`), `EnableMouseCapture` — подписку на события
мыши (mouse capture; понадобится для кликов и колеса). В конце всё
возвращается обратно, даже если есть `Err` — res вернёт ошибку наружу.

### `run` — главный цикл (`main.rs:34-64`)

База ритма — **poll каждые 50 мс** (опрос — проверка наличия события):

```
terminal.draw(|frame| ui::draw(frame, &mut app))   // нарисовать
if event::poll(50ms) {                             // клавиша/мышь?
    read → handle_key / handle_mouse
}
while let Ok(ev) = app.runtime.events_rx.try_recv() // фоновые события
    { app.handle_event(ev) }
if app.should_quit { break }
```

Три замечательные детали:

- `event::poll(50ms)` не просто «подождать 50 мс»: если нажатие пришло раньше —
  обработаем мгновенно; если нет — цикл всё равно пройдёт (перерисует и
  дренирует события). Это даёт и живой UI, и низкую задержку.
- `try_recv` (неблокирующий — non-blocking) — фоновые события применяются
  разом и не могут заморозить UI (никакому потоку `send` тут не блокируется —
  канал неограниченный `mpsc`, multi-producer single-consumer).
- выход — только через `should_quit` (ставится клавишами `q`/`Esc`/`Ctrl+C`
  или `handle_event`).

### `handle_key` — все хоткеи (hotkeys — горячие клавиши) (`main.rs:66-236`)

Три приоритетных уровня:

1. **Редактирование текста** (`main.rs:70-78`): если `app.is_editing()` — всё
   уходит в `edit_char`/`edit_backspace`/`cancel_edit`, остальное игнор.
2. **Во время фоновой задачи** (`main.rs:82-89`): разрешены только безопасные
   клавиши (`q/Esc/Tab/F1/навигация`), остальные — игнор. Так connect/flash
   не прерываются.
3. **Обычный match** по `key.code`, часто с guard'ом (guard — условие-фильтр
   в `match`) `app.tab == …` (например `Char('c') if app.tab == AppTab::Ports`).

Guard'ы — самая частая тема вопросов: одна и та же клавиша делает разное на
разных вкладках («c» на Ports = connect, на Registers ничего; «o» на Ports =
disconnect TCP, на Firmware = restore, и т.д.).

Обратите внимание на `Char(' ') if app.tab == Dashboard`: пробел переключает
катушку выбранного устройства через `toggle_coil(di, 0)`
(`main.rs:194-200`). Напомним, клик по дашборду **не** трогает катушку —
только `Space` (см. `left_click`, ниже).

### `handle_mouse` — мышь (`main.rs:239-256`)

- строка `0` (ряд вкладок) — клик `Down(Left)` переключает вкладку через
  `ui::tab_at_col(column)`.
- иначе: `ScrollUp/ScrollDown` → `mouse_scroll`, `Down(Left)` → `left_click`.

### `left_click` — клик по телу (`main.rs:259-322`)

- Если редактируем — игнор. Затем `y` отсчитывается от `ui::HEADER_ROWS`, и
  координаты мапятся (map) по вкладкам:

- Портс: `list_index_at(y, ports.len())` → `set_selected_port`.
- Дашборд (dashboard): левая 3/5 ширины и `y>0` → `dashboard_rows_for_devices(app)` →
  `set_selected_device(di)`.
- Сенсоры: левая половина — список (`sensor_selected = i`), правая — форма
  (фиксированные строки формы 3..8 → `sensor_focus`).
- Регистры: левая 3/5, строки форм 4..8 → `reg_focus` (сдвиг `cr-4`).
- Фирмваре: правые 2/5 → список бэкапов (backup — резервные копии).

## `ui.rs` — отрисовка (1303 строки)

### Константы и помощники (`ui.rs:12-68`)

- `pub const HEADER_ROWS: u16 = 3` — шапка (вкладки + статус) занимает 3
  строки; `FOOTER_ROWS: u16 = 4` — подвал (хоткеи).
- `tab_at_col(col)` — по колонке вернуть номер вкладки (через ширины имён).
- `dashboard_rows_for_devices(app)` — строит маппинг «строка экрана → индекс
  устройства» для дашборда (для кликов и автопрокрутки).
- `list_index_at(y, len)` — y в индекс списка с проверкой границ.

### `draw` — диспетчер (dispatcher) (`ui.rs:70-92`)

`ratatui::Frame` (кадр — то, что выводится за одну отрисовку) + `Layout`
(раскладка, вертикально: header/body/footer) + выбор функции по `app.tab`.
Ничего не возвращается — только рисует.

### `draw_header` / `draw_footer` (`ui.rs:94-202`)

Шапка (header): название + спиннер (spinner — индикатор занятости) `spin` при
`app.busy`, табы (tabs — вкладки; выбранный — другим цветом), строка статуса.
Подвал (footer): список хоткеев с клавишами.

### Вкладки по отдельности

| Функция | Что рисует |
|---------|-----------|
| `draw_dashboard` (`ui.rs:203`) | список устройств с датчиками/катушками/holding; интерфейс распадается на колонки; device header ◆ + sensor rows ● |
| `draw_pipeline` (`ui.rs:343`) | схема потока (EMU/Serial/TCP → ... → Bus) с активностью |
| `draw_ports` (`ui.rs:444`) | список портов + кнопки/хоткеи подключения |
| `draw_tcp_master` (`ui.rs:497`) | форма Host/Port + статус подключения (правая панель Ports) |
| `field_line(...)` (`ui.rs:585`) | строка формы с подсветкой фокуса/редактирования |
| `draw_registers` (`ui.rs:606`) | форма: slave/start/count/addr/value/reg_type + кнопки r/w/t |
| `draw_sensors` (`ui.rs:726`) | левая панель: список датчиков; правая: форма добавления |
| `draw_firmware` (`ui.rs:865`) | кнопки i/f/b/o, список бэкапов, статус esptool |
| `clip_hex` (`ui.rs:945`) | обрезает длинный hex-логи для Bus |
| `draw_bus` (`ui.rs:955`) | кольцо `app.trace` (ring buffer — кольцевой буфер): `→ req`, `← resp`, `[ok|err]`, время |
| `draw_log` (`ui.rs:1067`) | `app.logs` с цветом по `level` |
| `draw_help` (`ui.rs:1096`) | `help_lines()` — статичные строки помощи |
| `help_lines()` (`ui.rs:1109`) | весь текст Help (та же структура, что в README) |

Данные для рисования **никогда не вычисляются внутри `ui.rs`** — только
читаются из `App` и вспомогательных функций (`dashboard_rows_for_devices`).
Это «лицо» приложения; вся логика — в `app.rs`.

### Тесты (`ui.rs:1245-1303`)
