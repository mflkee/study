# Разбор Rust-кода: как устроен TUI и как всё понять

Эта папка (`docs/`) — расширенное учебное пособие по **исходному коду** проекта.
Если `DOCUMENTATION.md` объясняет *протокол Modbus и интерфейс TUI*, то здесь
разбирается *сам код на Rust* — файл за файлом, строка за строкой, с точными
ссылками на `src/*.rs`, чтобы после прочтения у вас не оставалось «тёмных мест».

## Как читать

1. Начните с [01 — Структура](01-structure.md) — общая картина, затем идите
   по порядку: каждая глава опирается только на предыдущие.
2. Откройте рядом файл исходника. В каждой главе ссылки вида
   `emulator.rs:58-60` — это точные строки. Читайте исходник *вместе*
   с объяснением.
3. Запускайте команды из [01-structure](01-structure.md#команды), где они
   даны: `cargo test`, `cargo clippy`.
4. После чтения главы выполните задачи из [10 — Практика](10-practice.md) —
   там упражнения именно на *написание* кода по образцу проекта.

## Что потребуется знать заранее

Считается, что вы уже прошли `DOCUMENTATION.md` и понимаете, что такое:

- регистры Input (Input Register, IR, область 3x) и Holding (Holding Register,
  HR, область 4x), катушки (coils, область 0x), дискретные входы
  (Discrete Input, DI, область 1x);
- код функции (Function Code, FC), PDU (Protocol Data Unit — «полезная
  нагрузка»), кадр RTU (Remote Terminal Unit) `[addr][fc][pdu][crc]`, кадр TCP
  `[tid][proto][len][unit][pdu]`;
- CRC-16 Modbus (Cyclic Redundancy Check — циклический избыточный код),
  big-endian (BE, «старший байт первым»), IEEE-754 float32 (числа с плавающей
  точкой и одинарной точностью);
- роли master (мастер — инициатор запросов) и slave (слейв/ведомый —
  отвечает).

Минимальный Rust: структурки, `enum`, `match`, ссылки, `Result/Option`,
`Vec`/`VecDeque` (вектор / двухсторонняя очередь), `BTreeMap` (словарь на
B-дереве, ключи отсортированы), `Arc<Mutex<T>>` (Arc — atomic reference
counting, счётчик ссылок; Mutex — mutual exclusion, мьютекс; вместе — общий
ресурс между потоками), потоки `thread::spawn` (thread — поток исполнения),
`std::sync::mpsc` (multi-producer single-consumer — канал «много пишут, один
читает»). По ходу дела каждая конструкция объясняется кратко.

## Где проверять себя

- **Единицы**: `cargo test` — 35 тестов, 2 ignored (живые: порт + сканер).
- **Статика**: `cargo clippy --all-targets -- -D warnings` — должно быть 0.
- **Практика**: [10-practice.md](10-practice.md) — задания с ответами,
  привязанными к реальным строкам проекта.
