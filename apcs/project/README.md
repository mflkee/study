# ESP32 Modbus TCP/RTU Gateway

## Дипломная работа

**Тема:** Разработка масштабируемого Modbus TCP/RTU шлюза на ESP32-S3 для интеграции полевых устройств с Zynq SoC

**Платформа:** ESP32-S3 DevKitC

**Стек:** Rust (no_std/embedded), Embassy, Modbus TCP/RTU

---

## 1. Постановка задачи

### 1.1 Проблема

На промышленном объекте необходимо обеспечить сбор данных от 32 полевых устройств (датчики температуры, давления, пробоотборники) и передачу их в управляющую систему на базе Zynq SoC. Устройства используют промышленный протокол Modbus RTU по шине RS-485, а Zynq работает в Ethernet-сети.

### 1.2 Решение

Разработка промышленного шлюза на ESP32-S3, который обеспечивает:
- Сбор данных с полевых устройств по Modbus RTU (RS-485)
- Предоставление данных по Modbus TCP (Ethernet) для Zynq
- Динамическую конфигурацию без перепрошивки
- Масштабируемость (добавление новых устройств без изменения кода)

### 2.2 Потоки данных

**Сбор данных (чтение):**
```
Полевые устройства (RTU Slaves)
    ↓ RS-485 (Modbus RTU)
ESP32 (RTU Master) — опрос каждые 500 мс
    ↓ обновление
Register Map (共享 память)
    ↓ чтение
ESP32 (TCP Slave, порт 502)
    ↓ Ethernet
Zynq (TCP Client) — получает данные
```

**Управление (запись):**
```
Zynq (TCP Client)
    ↓ Modbus TCP (Write Single Register)
ESP32 (TCP Slave)
    ↓转发 в RTU
ESP32 (RTU Master)
    ↓ RS-485 (Modbus RTU)
Пробоотборник (RTU Slave) — выполняет команду
    ↓ ответ
ESP32 (RTU Master) — получает подтверждение
    ↓ обновление Register Map
Zynq (TCP Client) — получает статус
```

| Уровень | Технология |

### 4.2 Структура проекта

```
src/
├── main.rs                    # Точка входа, инициализация
├── modbus/
│   ├── mod.rs                 # Modbus модуль
│   ├── rtu_master.rs          # RTU Master для RS-485
│   ├── tcp_slave.rs           # TCP Slave (сервер)
│   ├── register_map.rs        # Карта регистров (共享)
│   ├── pdu.rs                 # Парсинг/формирование PDU
│   └── exceptions.rs          # Обработка исключений
├── drivers/
│   ├── mod.rs
│   ├── uart.rs                # UART драйвер
│   ├── spi.rs                 # SPI драйвер
│   ├── rs485.rs               # RS-485 (GPIO4 control)
│   └── ethernet.rs            # W5500 Ethernet
├── sensors/
│   ├── mod.rs
│   ├── temperature.rs         # Датчики температуры
│   └── pressure.rs            # Датчики давления
└── config/
    ├── mod.rs
    └── settings.rs            # Конфигурация устройства
```

### 4.3 Карта регистров

| Диапазон | Тип | Назначение | Описание |
|----------|-----|-----------|---------|
| 0x00-0x0F | Input | Температуры | 16x f32, показания ДТ |
| 0x10-0x1F | Input | Давления | 16x f32, показания ДД |
| 0x20-0x23 | Coil | Статусы | Пробоотборники (on/off) |
| 0x30-0x33 | Holding | Команды | Управление пробоотборниками |
| 0xF000 | Holding | poll_interval | Интервал опроса RTU (мс) |
| 0xF001 | Holding | rs485_baud | Скорость RS-485 |
| 0xF002-0xF01F | Holding | slave_ids | Slave ID для опроса |
| 0xFFFE | Holding | apply | Запись = применить конфигурацию |
| 0xFFFF | Input | version | Версия прошивки |


## 5. Протокол взаимодействия

### 5.1 Modbus RTU Master (опрос устройств)

**Запрос (от ESP32 к датчику):**
```
[0x01] [0x03] [0x00 0x00] [0x00 0x02] [CRC_LSB] [CRC_MSB]
 │      │      │             │            │
 │      │      │             │            └── CRC-16 Modbus
 │      │      │             └── Количество регистров (2)
 │      │      └── Начальный адрес (0)
 │      └── Функция: Read Holding Registers
 └── Slave ID: 1
```

**Ответ (от датчика к ESP32):**
```
[0x01] [0x03] [0x04] [0x41 0xC8] [0x00 0x00] [CRC_LSB] [CRC_MSB]
 │      │      │      │             │             │
 │      │      │      │             │             └── CRC-16
 │      │      │      │             └── Значение 2 (0x0000 = 0.0)
 │      │      │      └── Значение 1 (0x41C8 = 25.0 в float)
 │      │      └── Количество байт данных (4)
 │      └── Функция: Read Holding Registers
 └── Slave ID: 1
```

### 5.2 Modbus TCP Slave (ответ Zynq)

**Запрос (от Zynq к ESP32):**
```
MBAP: [0x12 0x34] [0x00 0x00] [0x00 0x06] [0x01]
       │             │             │            │
       │             │             │            └── Unit ID: 1
       │             │             └── Length: 6 (Unit ID + PDU)
       │             └── Protocol ID: 0
       └── Transaction ID: 0x1234

PDU:  [0x03] [0x00 0x00] [0x00 0x0A]
       │      │             │
       │      │             └── Количество: 10 регистров
       │      └── Адрес: 0
       └── Функция: Read Holding Registers
```

**Ответ (от ESP32 к Zynq):**
```
MBAP: [0x12 0x34] [0x00 0x00] [0x00 0x17] [0x01]
       │             │             │            │
       │             │             │            └── Unit ID: 1
       │             │             └── Length: 23
       │             └── Protocol ID: 0
       └── Transaction ID: 0x1234 (копируется!)

PDU:  [0x03] [0x14] [данные 20 байт]
       │      │      │
       │      │      └── 10 регистров × 2 байта
       │      └── Byte Count: 20
       └── Функция: Read Holding Registers
```

## 6. Требования к реализации

### 6.1 Функциональные

- [ ] RTU Master: опрос 32 устройств по RS-485
- [ ] TCP Slave: поддержка функций 0x01-0x06, 0x0F, 0x10
- [ ] Динамическая карта регистров
- [ ] Исключения при ошибках (0x01-0x04)
- [ ] Конфигурация через TOML
- [ ] Применение конфигурации без перезагрузки
- [ ] Лирование всех запросов

### 6.2 Нефункциональные

- [ ] Время ответа TCP: < 1 мс
- [ ] Время опроса 32 устройств RTU: < 500 мс
- [ ] Стабильная работа 24+ часов
- [ ] Восстановление после разрыва RS-485
- [ ] Корректная обработка одновременных TCP-запросов

### 6.3 Тестирование

- [ ] Unit-тесты: парсинг PDU, CRC, register map
- [ ] Интеграционные: TCP клиент ↔ сервер
- [ ] Стресс-тест: 50+ одновременных клиентов
- [ ] Проверка исключений: все коды ошибок
- [ ] Long-running: 24+ часов без падений
- [ ] Тест с pymodbus (Python клиент)
