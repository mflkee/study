# Лабораторная 5. Управление из ИВК: FC05/FC04

> [Все лабораторные](README.md)

## Цель

Научиться управлять модулем «как SCADA»: из клиента ИВК **выключить канал**
и убедиться, что его ток пропадает из FC04 (0.0), а потом **включить обратно**.
Это полный цикл «запрос → изменение состояния → чтение».

## Вводные

- логика видимости канала — [`channels.rs`](../../ai32/core/src/channels.rs):
  `current_of` возвращает `None` для выключенного канала;
- и это уже учтено в [`register_map.rs`](../../ai32/core/src/register_map.rs):
  `read_input` подставляет `0.0`;
- FC05 пишет coil (включить/выключить), FC04 читает ток —
  [`ive_client.py`](../../ai32/scripts/ive_client.py) умеет и то и другое.

## Шаги

1. **Прочитайте `current_of` в `channels.rs`.** *Почему выключенный канал
   «прячется» через `Option`, а не хранит `0.0`?* (подсказка: так сервер не
   перепутает «реально 0 мА» и «канал выключен»).

2. **Запустите sim-модуль** (см. Лабораторную 2) и ИВК в режиме `poll`:
   ```sh
   python3 ai32/scripts/ive_client.py /dev/ttyUSB0 poll
   ```

3. **Выключите канал 5 через клиент.** Найдите при этом в `ive_client.py`
   колонку «coil» (или команду записи). Включите/выключите несколько каналов.
   *Как изменилось «табло»?*

4. **Проверьте поведение FC04 по документации кода:** посмотрите в
   `register_map.rs` (`read_input` → `unwrap_or(0.0)`). Есть ли сценарий, где
   `0.0` может «слиться» с реальным нулевым током? Как это различать?

5. **Закрепите тестом** (в `register_map.rs` или в `channels.rs`): канал 3 с
   током 12.5 мА → `write_coil(3, false)` → `read_input(bank, 6, 2)` ==
   `[0, 0]` → включить → снова 12.5 мА. Прогоните `cargo test`.

```text
Из ИВК «выключили» канал, FC04 отдал 0.0, «включили» обратно — ток вернулся.

```

## Вопросы на подумать

- Зачем нужна двухбайтовая запись FC05 (адрес + value 0xFF00/0x0000), если
  можно было бы одним байтом? (посмотрите `out_echo` — формат ответа такой же.)
- Что произойдёт с FC05 на несуществующий канал (адрес 24)? Найдите ответ
  в `write_coil`.
