# 03: Lifetimes — время жизни ссылок

> **Цель урока:** понять, что ссылка не может жить дольше своих данных,
> и научиться объявлять время жизни, когда Rust не может вывести его сам.
>
> В нашем проекте (TUI) явные аннотации почти не встречаются, но понимание
> lifetimes нужно, чтобы читать ошибки компилятора и структуры вида
> `struct View<'a> { ... }`.

## Проблема: ссылка дольше данных

```rust
fn main() {
    let r;                    // r пока не существует значения
    {
        let x = 5;
        r = &x;               // ❌ x умрёт на выходе из блока
    }                         // x удалена
    println!("{r}");          // нельзя: r указывает в несуществующий x
}
```

Rust вычисляет *время жизни* (lifetime) по коду — оно про то, **как долго
данные гарантированно существуют**.

## Когда lifetime нужен явно

Если функция возвращает ссылку, связанную с одним из входных параметров,
компилятор должен знать, КАК связана — иначе ошибка:

```rust
fn longer<'a>(s1: &'a str, s2: &'a str) -> &'a str {
    if s1.len() > s2.len() { s1 } else { s2 }
}
```

`'a` — имя lifetime. Здесь оно говорит: «возвращаемая ссылка имеет то же
время жизни, что и обе входные». Вызывающий может гарантировать, что
результат жив, пока живы оба аргумента.

## Elision: когда аннотации можно опустить

Три правила вывода (elision):

1. Каждый входной параметр получает своё время жизни.
2. Если входной параметр ровно один — выходная ссылка берёт его время.
3. В методах `&self`/`&mut self` — выходные ссылки берут время `self`.

```rust
fn first_word(s: &str) -> &str {   // elision правило 2: → &'a str по s
    // ...
}
```

На практике **95% функций не нуждаются в явных аннотациях**. Их пишут,
когда есть несколько входных ссылок или ссылка возвращается из архива.

## 'static: самая длинная время жизни

`'static` — время жизни, равное времени работы программы.

```rust
let s: &'static str = "hello";  // строковой литерал — константа в программе
static PORT: u16 = 1502;        // глобальная константа — тоже 'static
```

**Не путать:** `&'static str` — ссылка на строку, которая живёт вечно.
Если данных не существует вечно — ссылка не может быть `'static`.

## Использование в TUI

В `emulator.rs:35-51` структура `VirtualSensor` хранит `name: String` —
это *владение*, а не ссылка, поэтому lifetime не требуется. Если бы поле
было `&'a str` (например, для ссылки на имя извне), пришлось бы писать
`struct VirtualSensor<'a> { name: &'a str }`.

Со временем в проекте встречаются lifetimes в обратных вызовах и
итераторах. Понимание базы достаточно: **долговечность ссылки не может
превышать долговечность данных**.

## Шпаргалка

| Случай                                | Нужна ли аннотация |
|---------------------------------------|--------------------|
| один входной параметр                 | нет (elision)      |
| метод `&self` → вернул `&...`         | нет (elision)      |
| несколько входных ссылок, выходная привязана к одной | да, `<'a>` |
| строка-литерал                        | это `'static`      |
