# 01: Ownership — система владения

> **Цель урока:** понять главное правило Rust — один владелец, а move,
> Copy и заимствование — следствия из него. Это то, что отличает Rust
> от C (в С память разбирает программист, в Rust — компилятор).

## Три правила владения

1. **Каждое значение имеет ровно одного владельца** (owner).
2. **Когда владелец покидает область видимости, значение удаляется** (drop).
3. **Владение можно переместить** (move) **или временно одолжить** (borrow).

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;        // move: s2 — новый владелец
    // println!("{s1}"); // ❌ E0382: use of moved value
    println!("{s2}");   // ✅
} // s2 выходит из области видимости → строка удалена
```

Из правила 2 следует **RAII** (Resource Acquisition Is Initialization,
как в C++): деструктор вызывается автоматически на выходе из блока.
В `SerialMaster` (master.rs) эта же идея закрывает порт при уничтожении.

## Copy: особая категория типов

Примитивы и маленькие типы **копируются** — владельца не переносится:

```rust
let x: u16 = 0x1234;
let y = x;             // копия (Copy)
assert_eq!(y, x);      // оба живы
```

- `Copy`: `u8..u128`, `i8..i128`, `f32`, `f64`, `bool`, `char`, кортежи из них.
- **НЕ Copy**: `String`, `Vec`, `Box`, `HashMap`, любой тип с `Drop`.

### Как это связано с проектом

`ModbusError` (frames.rs:18-33) производят `#[derive(Clone, Copy, ...)]` —
поэтому его можно и копировать, и сравнивать. Строки и `Vec<u8>` — всегда

## Move в функцию и обратно

```rust
// Функция ПРИНИМАЕТ владение (String уходит внутрь).
fn chew(s: String) -> usize { s.len() }

// Функция ВОЗВРАЩАЕТ владение (String возвращается наружу).
fn fix(s: String) -> (String, usize) {
    let len = s.len();
    (s, len)   // вернули и данные, и длину
}
```

Именно так работает `read_holding_registers` в master.rs:178-186:
«возьми PDU по ссылке, верни `Result<Vec<u16>, _>`» — данные переезжают
вовне, а владелец (`SerialMaster`) ничего не теряет.

## Clone: когда копия всё-таки нужна

```rust
let a = String::from("payload");
let b = a.clone();   // ЯВНАЯ дорогая копия (глубокая)
drop(a);             // a можно удалить — b живёт отдельно
assert_eq!(b, "payload");
```

Правило-эвристика: **если приходится много `clone()` — спроектируйте
владельца иначе**. В TUI `Arc<Mutex<Emulator>>` (worker.rs) делит одно
состояние между потоками — клонирование `Arc` бесплатно, это не данные.

## Срез против владения на практике

Из `crc.rs`:

```rust
// crc::crc16 — читает и не забирает владение:
pub fn crc16(data: &[u8]) -> u16 { /* ... */ }

// crc::append — мутабельно дописывает:
pub fn append(frame: &mut Vec<u8>) { /* ... */ }
```

Передача `&[u8]` позволяет вызывать `crc16` десяток раз, не копируя кадр.

## Шпаргалка

| Код                                   | Результат                  |
|---------------------------------------|----------------------------|
| `let s2 = s1;` (String)               | move — `s1` «убит»         |
| `let y = x;`  (u16)                   | copy — оба живы            |
| `fn f(&s)`                            | borrow — владелец не меняется |
| `fn f(&mut s)`                        | мутабельный borrow, один за раз |
| `let b = a.clone()`                   | глубокая копия, `a` живёт  |
